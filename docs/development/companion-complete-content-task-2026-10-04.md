# 陪伴媒体内容接入实施任务

状态：C5 已确认需要实施，待 C1 完成后分配 Memory 产品唯一写者。不是可跳过的占位。实现模型 GPT-6.1-sol / xhigh，主协调只分发、合同与验收。

## 已确认复用与缺口

现有 KnowledgeApplication 已有 project-scoped import、受控 file/url 获取；knowledge_sources 保存实际 bytes 和 sha256；knowledge_catalog.document_list/document_read 沿原对象/版本与完整语义块分页，每页重验权限。HTTP 已允许 document_read。当前仅支持 UTF8 文本、Markdown、代码和 HTML；没有上传稳定原件、图片 bytes、视频字幕/时间覆盖及 PDF/Office 读取。AssetLibrary 既有平台接入只证明目录与搜索，不能当作已经可取正文。

本轮以现有 Knowledge 内容 owner 演进，Companion 只保存阅读会话、引用和进度，Platform 负责已登录用户入口与请求转发。不要为每个陪伴用户创建虚假的工程项目来绕过 scope，应明确与当前项目资料空间并列的角色/受众内容范围，复用存储和读取能力。

## 交付范围

1. 链接与上传实际获取，原 bytes/内容 hash/来源地址或文件身份、版本、媒体类型和拥有范围持久化；更新同源产生修订，不能只有表单登记。
2. 按已授权来源读取正文、图片或媒体的实际片段，返回稳定 content_ref、来源时间、sha、实际覆盖、当前版本和可用期限；不能把摘要标为读完全文。
3. 网页/文本为首个真实适配；图片应有原 bytes 可读并供模型视觉输入；视频支持实际可取得的字幕/片段或抽帧覆盖，未取得音轨或全文不得宣称理解了全部视频。不用固定字幕/假图绕过真实内容。
4. 文档格式按现有可用解析库和真实产品需要接入；不新增万能解析框架。对不支持的格式准确返回，不能让完整媒体目标退化成只能手填文字。
5. 取得内容与向用户发送分离；同一对象供独立阅读、共读、收藏和后续追问引用。原作者/URL/版本保留，临时下载目录不成为永久原件目录。
6. 正式 authenticated acquisition/read 接口、部署配置、限制与错误投影，生产者消费者联合样例。主协调发布合同，不能只做内部函数。

需要新增的外部引擎或供给条件先列实据；已有相关引擎优先复用，不自行给 NAS 安装任意服务。现有项目资料/API和角色内容受众均须保持。

## 验收

从真实隔离 HTTP 来源取得文章，经正式入口纳管、分页读取、继续原进度；真实上传图片重新打开同一bytes；一个媒体样本的实际字幕或画面覆盖；来源修订/撤回、跨person读取拒绝、大小限制和中断恢复；重启后原件仍存在。与C3共读会话、C4页面的联合调用必须可运行，未配置外部条件单列，不能只测fixture返回对象。
