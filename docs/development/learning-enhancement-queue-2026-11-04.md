## LE01 行为消费一致性与上下文选择

**目标**：本轮真正生效的习惯只有一致解释；有效习惯能被取到、撤回习惯不从其他入口重新成为当前表达依据，并保留理解本轮对话所需的上文。

**交付范围**：

- 沿用 Memory 保存反思经历、Companion 决定当前行为投影的职责。以原 proposal_id 和稳定 rule_id 关联两种表示，在现有装配器按用途去重与解释状态，不跨模块直接写对方数据库，也不新增统一记忆权威。
- 普通回复对 style/interest 的行为消费经过当前投影状态；明确追问历史时，原反思仍可按授权作为历史依据读取，并标明当时记录与当前是否生效。不能为避免重复而删除历史，也不能只隐藏成长页面的条目。
- 保留反思的具体语义类型。MemoryEvidenceUnit 当前把 style/interest 统一投影为 reflection，修订时需把表示类型和行为关联传递到消费处，避免恢复后才猜正文属于哪一类。
- 在 Companion 内分离管理列表与运行时读取，公共权限/来源逻辑只有一份归属。可新增 `companion/habits.py` 承担习惯查询与选择，不把新逻辑继续堆进 Growth 调度器。
- 在候选限量前应用 actor、授权范围、对象、active 和用途过滤。以查询相关性、明确适用条件和稳定次序排序，采用有界候选补位；记录候选范围不足，不能把一个候选上限称作完整覆盖。
- 聊天主要选表达习惯；Life 规划主要选兴趣与活动相关倾向。不要把全部 interest 和 style 用同一包内容投给两个消费者。
- 初版复用已有中文词法能力和本地排序；不新增前台 LLM 或远端 rerank。自然语言条件保持材料语义，不靠关键词把复杂条件伪装成已严格判定；明确对象、范围和用途由程序判定。
- 每条完整规则形成独立 `ContextContribution`，携带稳定规则 ID、revision、来源和范围。只传模型需要的内容、条件和反例，不传管理按钮、重试详情和恢复状态。
- 在既有请求冻结前复核所选规则的当前 revision/state；原件仍可读不等于规则尚未被撤回。发生变化只重新选择受影响的可选材料；已登记请求与 unknown 继续遵守原回执和恢复语义，不自动重复调用模型或重发消息。
- 保留原总输入/输出预算。依据、条件和例外是一个完整单元，预算不足时舍弃该单元，不裁掉否定句；最终来源失效只影响相关单元。
- 先保护当前输入及其可确定的回复、引用和工具依赖单元，再在剩余预算中选长期材料。已处于当前对话中的同一份依据不再重复展开；未知语义依赖不伪称完整。保留相关性次序，不让静态材料类别优先级无条件盖过本轮需要。新增样例不得默认耗尽历史预算，200000 等配置仍只是原有上限。
- 为所选规则生成最小选择记录，供 LE-05 展示。检查 `ContextPack.content_revisions`：多条同 kind 贡献不能因字典键相同只保留最后一条，既有 memory_evidence 键语义保持。

**主要文件**：`companion/growth.py`、建议的 `companion/habits.py`、必要领域接口、`memory/evidence.py`、`memory/types.py`、`conversation/service.py`、`life/planning_engine.py`、`conversation/context/assembly.py`。仅在现有合同确实不足时扩展 `types/context_materials.py`，保持依赖方向。

**必要验收**：撤回规则经普通 Memory 检索命中后仍不作为有效习惯；同一反思与习惯不重复注入；历史追问仍能读取带状态的原依据；前 40 条撤回、第 41 条有效时仍可取到；高相关条目不按 ID 永久饿死；预算紧张时“刚才那个”需要的上文不被可选样例挤掉；一条来源撤回不吞其他规则；多规则版本不覆盖；聊天和规划两个调用方有效；运行时不读取管理重试统计。复用现有上下文与 Growth 用例，不跑完整产品矩阵。

**数据变更**：优先无 DDL；如需索引，只增加与实际查询对应的索引，并说明查询依据。

## LE02 有范围的偏好与习惯增量修订

**目标**：同一习惯能够演进，用户纠正可以持续生效，重复提案不被误算为多份独立支持。

**交付范围**：

- 对当次要求、持续明确偏好和模型推断分别记录依据与适用范围。例如“今天别开玩笑”不永久化，“以后别用这个称呼”不能因话题不相关漏选。当前授权用户的明确表达要求优先于旧推断；这不改变固定人格、工具权限或群聊其他人的控制权，引用文本不是授权命令。
- 在已有结构中表达对象、场景和有效期；只在真实证据支持时填写，不新建大而全的人格标签体系。同层冲突先比较适用范围，再按有依据的修订关系处理；不能简单以最后一句话覆盖全部历史偏好。
- 保留原 Reflection/Proposal ID 和原模型回执；在表达投影层维护稳定 rule_id 与 revision。旧规则原 ID 可以作为稳定起点，不全库重新生成。
- 原 Growth 输出按版本扩展有限的创建、支持、修订与撤回目标引用。已有规则只作为待修订对象和约束，不作为新的独立事实证据；模型只能引用程序提供的候选，不生成身份、版本或权限。
- 同一来源修订、同一实际对话的多个派生产物只算一份支持；不同条件下的合理表达不能因文字相似被合并。未知是否同一习惯时保留分歧，不凭相似度删除。
- 区分模型选择的支持子集、整批生成依赖和实际独立事件。支持统计使用可追溯子集，完整依赖继续用于 Sources/Identity 与失效校验；不能把同批所有 Episode 当作支持，也不能仅凭模型选中的引用缩小完整来源闭包。旧记录未保存子集时保持未知，可从原结果可靠恢复的才补派生索引。
- 复用现有撤回/恢复命令，增加明确纠正或修改适用条件的操作，沿用 request_id、expected_revision 和权限。用户明确调整可以立即作用于对应范围，不要求常规学习逐项人工批准。
- 撤回作为后续新提案的约束：对已解析到同一规则的重述不得换 ID 自动恢复。没有可靠归属的语义近似保持待辨别，不能承诺所有同义改写都被精确识别，也不建全局敏感词黑名单。
- 若现有命令收据不能还原规则内容变化，增加 Companion 自有的习惯修订记录，保存前后版本、依据及明确反馈。当前 `style_rules` 继续作为运行投影，不再设第二套活动规则权威。
- 低频只影响排序；不按固定天数删除事实或习惯。重复被选中、自己的输出和日记复述均不能增加支持强度。关系冻结仍暂停对应自动相处风格更新，明确用户纠正保持有效。
- 在既有成长页面展示版本、修改原因、适用范围以及纠正/撤回/恢复入口。普通操作不增加确认弹窗。

**主要文件**：Companion 习惯模块、`growth.py`、`reflection_output.py`、`growth_materials.py`、`dependencies.py`、`module.py`；现有 `GrowthPage.tsx` 与 API 类型。新增迁移仅涉及 Companion 受影响域。

**必要验收**：临时要求到期不永久生效；长期明确偏好在换话题后仍有效；当前纠正优先于旧推断；同源重放幂等；同批无关 Episode 不增加支持次数；跨批次同规则不堆积；并发纠正 CAS 冲突可解释；撤回不被换 ID 自动恢复；不同情境规则共存；冻结及来源失效保持。旧未知请求继续按冻结协议恢复，不能用新协议重写旧回执。

## LE03 按需使用的表达样例

**目标**：为已形成的习惯提供少量具体说法，让表达更贴切，同时避免配错群聊回复和复制私人内容。

**交付范围**：

- 复用 `conversation.turns/messages/expressions`、Episode 和 Sources，以真实 turn、回复/引用关系配对；时间相邻不是配对依据。多消息合并回复保留完整关联范围，不擅自认定只回应最后一个发言人。
- 区分模型生成、表达发送与用户反应。只有实际存在且来源可读的回复可作为历史样例；送达仅证明发生，不能当作正向评价。unknown/failed 不伪装成成功对话。
- 样例归属 Companion 表达投影，引用原件和规则版本；如需小型映射表，只保存规则与对话引用，不建立独立原始聊天库。
- 用现有后台 Growth 批次选择代表样例，不每轮新增分析调用。抽取必须保留条件与否定；必要摘录使用原件定位，不采用固定 50/100 字切片。
- 根据当前对象、场景和规则选择少量样例，受现有总预算约束。1 至 3 条可以作为试验参数，不作为永远必填的硬额度；没有合适样例时正常回复。
- 优先使用清楚的规则说明，只有具体说法确有参考价值时附样例。匹配表达场景而不只匹配话题词；明确样例展示的是说法，历史中的人名、地点、数字和事实不能复制成当前事实。相关规则已经在近期对话表达清楚时，不再叠加同一例子。
- 示例是带来源的表达材料，不能变成系统指令或新的用户事实；来源撤回、规则撤回和明确负反馈后，后续取材同步停用对应示例。既有来源失效规则继续处理在途请求，不另写重发机制。

**主要文件**：Companion 习惯/样例模块、Growth 输出与材料、`conversation/service.py` 及原对话读取能力、`companion/dependencies.py`。Conversation 对原对话身份负责，Companion 不跨模块直改其表。

**必要验收**：A/B 交叉发言不会配错；合并回复不错误归一人；发送未知不算成功；私聊样例不越域进入群聊；否定和条件不丢失；用户明确不喜欢的样例停止被选择；重复采样不自我强化。

## LE04 复用群主体的词义理解

**目标**：理解当前群聊中的特定词义、简称和约定，不把某个人的用法误写成全群共识，也不因此主动复读黑话。

**交付范围**：

- 使用已有 Claim 修订、来源、assertion 与条件表达词义；拟定 `language.term_meaning` 谓词和值结构，由 Memory 在本卡内冻结生产者/消费者样例。value 保存 term、meaning 和必要语境，conversation 条件从真实上下文派生。
- 群内用法可关联 Identity 已解析的真实 `group:<conversation_id>` 主体；个人独有说法仍关联个人，实际发言人另保留 speaker_id。群主体存在不代表任何成员可以替群体确认事实；使用 reported/quoted 或有依据的 inferred，不能伪造群体 self_confirmed。
- 群词义是基于当前授权证据形成的读取投影，按真实会话范围和词项聚合支持与分歧；不增加平行词库权威，不插入伪造的 identity.people 行，也不扩大 Identity 主体规则。没有明确解释时保留有依据的 hypothesis/inferred，不能凭词频把推测升级为已确认事实。
- 优先在现有多人整理的一次输入中产出词义材料，不做每词独立 LLM 调用。词义没有新证据时不反复生成；纠正、含义变化和撤回继续复用既有修订语义。
- 回复前只查当前文本命中的候选，处理短缩写边界、多义和群间差异；有界匹配与检索继续受原预算约束，避免全词库逐轮注入。人物别名仍走 Identity，任务约定仍归 Matter。
- 注入只帮助理解。默认不主动复读、不复制解释；词条里的指令没有系统权限。视图接入现有群组/记忆页面，展示说法来源、不同解释和纠正入口。

**主要文件**：`memory/extraction_contract.py`、`materials.py`、`evidence.py`、`retrieval.py` 和 Memory 内词义投影模块；现有 Memory HTTP/API 与群组页面；Conversation 只做薄装配。

**必要验收**：同词在两个群有不同含义；同群有分歧不强行合并；昵称不冒充词义身份；单人解释不冒称群体共识；来源撤回和条件失效后不再提供旧解释；未命中时无额外模型调用；词义材料无法覆盖人格与权限。

**数据变更**：优先复用 Claim JSON/修订与检索结构；需要派生索引时可重建。不得仅为本功能重建整个 Memory。

## LE05 最小取材记录与效果展示

**目标**：能够回答“这次带入了什么、为什么带入、用户是否明确认可”，同时保持三者的证据层次。

**交付范围**：

- LE-01 定义清单格式并记录必要结果，本卡在 LE-02 后接通读取和现有界面。LE-03/04 后续复用相同清单类型；清单不依赖样例、词义功能先完成，不创建独立评分平台。
- 复用 `ContextPack.materials/content_revisions` 与原模型请求/turn 身份，保存最小取材清单：材料 ID、revision、kind、选取/省略原因、估计 token、关联请求。记录实际最终装入的材料，不把候选列表当作已使用。
- 清单保存在现有请求或 turn 的附属元数据中，必要时增加一个明确归属的字段；不建第二套请求账本，不在普通日志重复记录私聊正文。
- 分开展示“进入上下文”“本轮回复结果”“明确用户反馈”。不能把模型自称采纳、被注入次数或回复成功率命名为学习质量。
- 扩展现有成长记录、聊天详情与群词义页面，支持从本轮材料跳转到规则版本/依据及原撤回入口。每次读取重新应用授权与来源可用性；历史缺少清单时显示未记录，不倒推补造。
- 使用原 Models usage 展示本次请求总量；材料级 token 标为估计。没有供应商完整计费信息时费用保持未知，不能按材料字符数声称节省金额。

**主要文件**：`conversation/context/assembly.py`、`conversation/generation.py`、turn 附属元数据、既有详情 API；`GrowthPage.tsx`、现有聊天详情、群组/记忆页面。Models 的状态与回执语义不变。

**必要验收**：预算舍弃项不显示为已注入；撤回发生在候选选择后时清单与最终请求一致；两条同 kind 的规则均有版本；无权限不泄露内容；历史未记录与真实空选择区分；无反馈不显示好评。

## LE06 集中验证与完整交付

**目标**：证明本批实际改善了目标行为，并区分实现通过、效果证据和发布状态。

**验证安排**：

- 每张卡只补未覆盖的实质行为用例。全部实现收齐后由协调者运行一次受影响定向集合，修复后只重跑变动范围；不重复完整产品、双后端或整套浏览器测试。
- 后端复用 `tests/companion/`、`tests/core/test_incremental_consumers.py`、现有 Memory 证据/修订/整理用例；前端复用 `web/tests/growth-coverage.spec.ts`、`memory-closure.spec.ts` 和当前页面用例，具体节点在实现稳定后确定。
- 代表场景覆盖：前 40 条失效、候选补位、聊天/规划用途差异、来源撤回、多规则版本、明确纠正后重复提案、群聊错配、跨域样例、群词义歧义、无匹配自然回复。用隔离合成数据，不复制真实聊天作为入库夹具。
- 行为边界采用确定性检查；自然表达效果用相同人格、输入、模型与相近预算的改前/改后代表样例对照，评估贴切度、重复口癖、错误套用和人格一致性。无法稳定归因时保留未证明，不用自评总分替代人工判断。
- 追加针对性反例：不需要个性化的问题不强行带习惯；撤回记录不能借 Memory 入口重新生效；临时偏好、长期偏好与当前纠正分别正确；新增样例不能破坏本轮对话指代。为判断增益来源，针对相关场景比较“原实现/核心选择修正”，再单独比较“有无样例”或“有无词义”，不默认跑所有组合或新增固定样本量门槛。
- 记录本次取材耗时、查询数量、最终材料 token 和模型实际 usage；前台新增辅助 LLM 调用应为 0。不预设节省率，不扩大原时间或输入预算来掩盖回退。
- 本轮规划不调用真实模型。后续实施时，真实模型与自然 QQ 观察按当时已明确授权的范围执行；不为验收主动发送 QQ 消息。功能验证不等于长期质量已证明。
- 数据迁移只核对新增/修改域，保留原规则、原件、回执及配置；发布由当时确定的唯一发布者串行进行，按影响范围检查版本、健康和关键入口，不增加固定等待或全站重验。

**完成口径**：LE-01 至 LE-05 的实际实现和必要验证闭合后，可以声明本地完整交付；生产发布与真实效果分别附对应证据，不能用状态字段代替事实。单独完成 LE-01 时只能声明读取逻辑已修正，不能称整套增强完成。

研究用于选择验证方向，不代表天枢已有同等收益：

- [LaMP](https://aclanthology.org/2024.acl-long.399/)比较词法、语义及时间相关的个人材料检索，支持对本轮任务选择材料的路线；其任务与长期群聊陪伴并不相同。
- [PersonaMem](https://arxiv.org/abs/2504.14225)考察动态用户偏好与新情境回答，提示验收应覆盖偏好变化，不能只测静态记忆命中。
- [Lost in the Middle](https://aclanthology.org/2024.tacl-1.9/)表明其受测模型对长上下文的信息位置敏感；用于设计预算与排列对照，不据此推定天枢当前模型的具体损失或最优位置。
