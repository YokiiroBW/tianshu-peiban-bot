## 交付目标

逐项审计已有平台、陪伴、记忆、网关、资产接入、家庭服务、任务及资料/项目能力，提供一份完整覆盖矩阵：实际应用端口、HTTP 是否存在、网页是否存在、部署是否配置、真实验证和剩余限制。已有能力不能仅以占位页面交付；没有实现的能力明确标记尚未提供，不能引导用户反复去配置。内置后端由部署自动配置；外部服务提供明确的配置/检测流程，保留对端授权边界。

## 并行责任

- CONNECT-B（Sol/xhigh）：平台后端集成唯一写者，拥有 services、tests/backend、后端说明及新增浏览器 API 契约文档；盘点后打通 Memory 人物/记忆/研究资料/项目目录、Companion 人格/生活/已发布日记，以及既有资产、家庭、任务端口。先公布实际端点和前端数据契约，复用领域服务，不读写对端 DB，不在网关重做模型功能。缺少对端端口时给出最小缺口，不自行并改其他产品。拥有平台公共路由/装配入口；不写 apps/web。
- CONNECT-U（Sol/xhigh）：平台 apps/web、前端测试及前端说明唯一写者。保留现有 React/样式体系及已认可视觉，不改小屋 Three.js/模型/资产。落实已实现模块的真实页面、统一连接状态和明确下一步，用户无需理解内部 token/origin。先读后端契约再接接口，不能自创并冻结不一致协议。未实现功能如实标注；无业务数据为空态，不冒充断连；故障/未授权/未配置/未实现区分。
- CONNECT-A（Luna/max）：只读全产品覆盖审计、遗漏检查、独立审查与隔离验证；只写自己的文档和测试取证。优先提交实际端口覆盖矩阵和缺口，通知 B/U；随后按固定提交审查权限、解耦和完整使用路径。无 NAS 操作。
- 总控：根合同协调、需要时另派非平台产品最小补缺；唯一集成者、NAS 写者与配置者。已有内置授权通过正式接口发放，不写数据库硬灌权限。运行备份、受控更新、健康/真实业务验证，不能把容器 healthy 视为功能完成。
