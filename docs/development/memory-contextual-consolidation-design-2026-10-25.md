## 1. 目标与当前边界

使用一套现有 Memory，保存值得保留的经历、表达和约定，并形成可修正的人物概况。短期、中期、长期是保留策略；经历记忆与画像按用途区分，不建设两套事实库或模型链。

群聊以一个有界会话片段为整理单位：一次模型调用理解其中的话题，返回各目标人物自己的记忆。模型判断表达含义、是否值得保留、重要性和保留建议；程序绑定真实身份、来源、覆盖进度和实际提交结果。不追求逐句满分，明确跨人或 BOT 内容误归仍是验收失败。

当前已验证候选仍为 Memory `25b8de1`、Companion `4872345`、Platform `0d3c959`、Gateway `62084e1`。它采用本人原话窗口，不能冒称已支持本设计的多人整理。此前本地、TLS、固定110和真实145结果仅在其原适用范围有效。

现有实现的必要调整：

- Core collector 的短暂静默用于及时回复；终态 turn 当前产生单人候选任务。后台没有独立的会话片段整理时机，仅延后旧任务既不会覆盖后续 turn，也不会减少任务数。
- `SummaryWindows` 当前只取一个新 turn 及本人历史；新设计要明确包含同一会话中有权使用的其他人和 BOT 原始发言。
- 普通人之间的旁听消息当前仅归档，不进入默认 schema5 整理。Observation 入口校验了回复引用和 @，但持久记录尚未完整保留这两个数组。
- 现有 BOT 关系账本是 `(actor_id, person_id)`，不承载人际社交图。AL02–04 自主生活接入、Chat 完整历史查询仍未集成。

## 2. 一条整理闭环

1. 原消息立即进入现有可靠归档。BOT 对话和群旁听保留同一来源身份；按原消息键及修订去重，不因同时经过两条入口而产生两份新表达。
2. 复用现有后台任务设施，在尚未封盘阶段收集待整理范围。聊天回复照常运行，普通等待不占模型槽，也不进入会阻挡前台的 `capture_wait/commit_wait`。
3. 达到收口条件时，直接创建一个段级整理任务，冻结消息范围、目标名单、各人完整 scope、绑定版本及新消息清单。新任务不再先逐 turn 创建模型任务，再追加 leader/follower 协调层。
4. 获取当前有效的有界上下文和完整来源证明，一次输入共享消息及各目标材料，一次输出话题、逐人记忆和可选画像。
5. 保存原输出及 digest。Memory 在原事务内完成全部必要校验，按各人 scope 写入经历与覆盖结果，形成一份段级 ledger 回执。
6. 回执逐人说明实际覆盖、新记忆引用、空结果和画像状态。只有真实回执能推进已整理进度；metadata 游标只是可以重建的查询投影。
7. unknown 保留同一任务、冻结窗口及输出，先查原回执，不换人、换窗或换输出绕过未知结果。旧已冻结 singleton 任务继续按原协议恢复，不原地改写。

新合同应固定 actor 和当前会话，并显式列出逐人 targets。不能用某一个人的 scope 代表整个群，也不能循环调用旧单人 `_submit`，让前一个人的写入影响后一个人的校验。复用原写入能力和事务边界，扩展现有任务及回执合同。

## 3. 分段与覆盖范围

### 收口时机

- 初始讨论参数：同一会话静默约 2 分钟收口；从首条未整理消息起，最长约 10 分钟，或达到现有输入、来源、输出预算时提前封段。数值是可调整起点，不是验证结论。
- 首版按会话的时间和容量封段，不在程序中猜每条新消息属于哪个话题。持续群聊由最长时限保证收口；引用、回复和 @ 用于补充上下文，交错话题由同次整理模型理解，不增加逐消息话题分类调用。
- 有未整理新表达的人才进入本段 targets；历史参与者仅作为上下文。等待期间不持有长期来源证明，封盘及提交仍使用现有有效期和全新检查，不能借等待延长旧 proof 的截止。
- 单段可以包含多个话题；同一个话题也可以跨段。话题是本段归纳信息，不作为身份、权限或完成进度的权威。

### 两种材料用途

- 覆盖材料：各目标人物此次尚未整理的新消息。程序给出明确清单，模型不能自行扩大或更换对象。
- 解释上下文：回复或引用的原消息、邻近交流、少量相关有效旧记忆及未完成约定。保留发言者、角色、时间、原始 scope 和来源；BOT 发言保持 BOT 身份。

同一条 B 的新消息，对 B 是待整理材料，对 A 可以是解释上下文。因此共享消息只传一份，另用逐人清单表示各自的新材料；不用把整段文本复制到每个人的输入中。

先保留完整的新消息，再按回复关系和邻近交流补充上下文。预算不足时缩减可选上下文，或在完整消息边界提前封段；不得截掉新消息的一部分却宣称已覆盖。必要的原始引用不可得时，保留缺项事实，不能补写其内容。

窗口之间可以重复使用少量前文作为上下文，同一修订的新消息只能属于一个有效整理任务。消息修订、作者绑定变化、撤回继续沿原失效路径处理。任务开始后新来的消息进入后续片段，不能悄悄改变已冻结窗口。

跨群、私聊或其他 BOT actor 的材料不因人物相同而自动拼入。整段公开聊天也不能把 A 转述 B 的话，升级为 B 本人的确认。

## 4. 输出、状态与遗忘

### 结构化输出

程序在输入中提供真实人物标识和目标槽位。模型返回本段话题及逐人结果，每人可以有零条或多条记忆；参与聊天不要求产生画像或稳定特质。

建议输出概念如下，字段名称尚非已发布 schema：

```text
本段话题：话题编号、概括、参与人物、原消息引用
逐人结果：人物标识、覆盖的新消息引用、记忆列表、可选画像更新
每条记忆：简短含义、原话/上下文引用、可选类型与状态、相关旧记忆引用、重要度、保留档位
```

输出必须恰好对应冻结 targets，不能漏人、重复人物或引用未提供的消息。明确空结果表示已理解但无内容值得保存；漏输出不表示已完成。校验身份及引用不能证明正文语义正确，真实正文归属仍需验证。

同一段经历及覆盖结果采用一次有界原子提交：任一必要来源、原作者授权或全局 CAS 不符，整段不写。不能静默裁人后仍宣称原集合完成。经历合法保存后的可选画像无更新或独立写入冲突，不能抹掉已保存经历；画像也不得绕过自己的来源和版本校验。

### 少量状态，不恢复逐句裁决系统

- 经历保存发生了什么、谁如何描述，保留时间及更正依据。
- 想法保存考虑、偏好或尚未确定的安排，不自动升级成约定。
- 约定保留对象、参与方、条件或时间；考虑、确定、完成、取消等状态应有本人的表达或实际行动依据。A 同意不能自动代表 B 同意。
- 模型只能关联输入中提供、归属合法的旧记忆引用。后续更正、完成或取消沿既有版本/lineage 更新，原始来源和变化过程可追查。
- 多人同题不代表每个人经历相同。共同行动可以共享事件来源，各人的角色仍须分别表达；普通聊天不强制拆成大量原子事实。
- 用户明确的记忆操作沿原工具链及时执行。BOT 执行结果依据实际回执；后台归纳不自动创建提醒、执行任务或授予权限。

### 重要度与保留时间

同一次模型调用给出重要度和短/中/长期保留建议，程序映射配置并执行。两者分开表达：重要且短时有效的取件安排，与普通但稳定的偏好不应被迫使用相同寿命。

保留档位先复用现有配置来源和三档默认周期，不新增模型复审链；现有重要度与期限直接映射的实现需要随新合同明确调整。新记忆按各自保留建议计算期限，共享原话仍保持实际作者和来源修订，不能由某一目标的写入顺序决定所有人的寿命。未完成约定的明确截止时间与自然保留期分别记录，不能在明确截止前因较短默认期限直接失去当前安排；时间过去只代表到期或待确认，不自动表示完成、取消。

自然遗忘优先使旧内容退出日常 current 召回，历史与原始来源按原策略留存。明确删除继续走 suppression、来源与派生失效链。BOT 复述、画像重写或后台重总结不为旧信息自动续期；真实新发言和进展才形成新的更新依据。精确原文回查待 Chat 完整接口接通后使用，不能冒称现在已有。

## 5. 值得做的深层优化及取舍

| 优化 | 本版处理 | 收益与边界 |
|---|---|---|
| 改变任务创建单位 | 封盘片段直接对应一个整理任务及一个覆盖回执；同 actor/会话按封盘顺序处理 | 减少重复模型调用和跨 job 协调，复用原 worker、公平恢复、jobs 和 ledger；不建立第二份完成账本 |
| 共享材料只读取、发送一次 | 批量取得同窗原文和来源，按人物提供引用清单；保留原逐作者授权、完整屏障及每页严格 AND | 降低重复 SQL、序列化和 token；不使用跨 checkpoint 缓存代替新校验，不放大槽位或超时 |
| 防止解释反复增信 | 画像由有效经历及对应本人原话重建；旧画像不作为新的原始事实，旧摘要可帮助定位原话 | 降低 BOT 想象和旧误解被重复吸收的风险；画像依据不足可不更新，不能以少量近话覆盖全部有效长期认识 |
| 画像按变化低频更新 | 沿现有可选输出，同次调用只为需要且已有合法依据的人更新；允许为空 | 避免每个群片段读取所有人的画像历史；更精细的按需重建后置，不另起高频调度链 |
| 来源证明与上下文成本一起控制 | 保留完整实际输入来源及删除闭包；静默等待发生在冻结/claim之前 | 收紧材料规模而不缩减证明；共享输入可能带来较宽失效范围，首版保守处理，不能仅凭模型自报没引用就解除依赖 |

重要取舍：一次多人调用能减少相同上下文的重复输入，但输出成本随人数及记忆数量增长；窗口过大也增加角色混淆。预算不足时提前分段，不能承诺全群任意长度只用一次调用。核心成本是每段实际输入/输出 token 和调用频率，静默等待本身不消耗模型。

群互动统计与点云后置：先复用保存完整的回复、@、人物和话题线索，再由程序计算互动边及布局。互动密集不直接等于私交好，群社交解释不写入 BOT 好感账本，也不产生权限。不先建设通用知识图谱或另一套事实库。
