# 首次使用流程修复

用户要求：保留现有视觉风格，以必要的小改动修复使用逻辑。部署后首次打开应能创建管理员，随后知道从哪里开始；不能把登录藏在陪伴页面，也不能让各模块互相指路。

## 已核实的问题

当前平台基线 c1c7547，网页登录凭据来自部署配置中的 username/password_hash，没有网页初始化API或用户账号仓储。部署工具为实机验收预置了 admin；用户未参与创建，网页也没有解释或接管流程。陪伴、模型、家庭、任务、人格等页分别维护登录表单。NAS公开只读session检查返回200、authenticated=false；本轮未读取真实密码、未写NAS。

现有模型管理页仅消费服务器预登记模板，不是任意供应商编辑器。登录、模型配置完成、真实对话成功是三个不同状态，不可承诺创建账号后无需任何配置即可调用模型。

## 新流程与边界

1. 新部署：服务器明确处于待初始化状态，网页先显示欢迎与创建管理员。账号及密码确认在页面完成，安装验证码来自部署提供的私有初始化信息；浏览器本地标记不能决定是否允许注册。
2. 已有部署：统一登录入口。预置账号可在认证后进入接管向导，设置自己的账号和密码；绝不清库、匿名覆盖或因为业务尚未配置就开放注册。
3. 登录成功：展示开始使用引导，明确账号、模型、角色/会话的真实状态，能直接继续原目标页面。可稍后配置并浏览其他功能，不虚构模型已可用。
4. 所有受保护页面共用登录入口；会话过期回该入口并保留目标。模型发布、设备控制等敏感操作原有的再次验证保留，但不重复要求创建或登录另一账号。
5. 保留页面配色、玻璃效果、已有组件和小屋任务边界，不以改版掩盖流程问题。

## 交付边界

- 平台前端：worktrees/USABILITY/tianshu-platform，codex/first-run-onboarding-20260926。
- 账号后端：worktrees/ONBOARDING-ACCOUNT/tianshu-platform，codex/onboarding-account-20260926。可选web_account配置为create（必须独立setup_token_env，省略旧username/password_hash）或claim（保持原凭据用于认证接管）。账号库与封条放平台数据卷；同源、CSRF、限流与权限继续由后端负责。
- 通用部署打包：识别setup_token_env，create不再索要预创建人类账号，claim保留原配置hash；初始化凭据只进入私有容器环境，不进入页面、公共回执或Compose。首轮31项打包测试通过。
- 当前resident安装器仍锁定已验收旧产品提交；本轮不改历史安装凭据、不重跑首装或自动替换镜像。支持新配置不等于现有NAS已更新。新的平台版本需按受控更新流程验证后发布；不能把旧镜像与新配置强行拼装。
- 恢复inventory按平台state卷识别所有SQLite与普通文件，账户文件及封条需作为同一状态组保留。不能仅复制账号库、遗漏封条，不能丢失账号状态后重新开放注册。
