# 多角色独立运行与网页管理

用户请求：天枢可创建多个运行角色，每个独立指定模型、人格档案、记忆、可用功能，分别驱动 BOT。沿用用户后续开发在可见 Sol/Luna 任务的偏好。总控负责边界、集成和验收，工作者在隔离检出完整实现。本卡覆盖旧 DSH-only 与历史轮次限制，不恢复旧任务。

## 产品验收目标

1. 陪伴内增加清楚的“角色管理”入口。左边角色列表/搜索/新建，右边名称、启用状态、人格、模型、记忆、功能；默认只显示常用设置，其余渐进展开。沿用已有视觉、React/Vite 和组件，不改小屋，不再把运行状态/历史协议说明堆到主页面。
2. 运行角色和可复用人格档案明确区分。可以新建/编辑/停用角色，为不同角色选择同一或不同人格档案；显示绑定的具体生效版本。档案后续修订不暗中覆盖所有角色，明确应用后才生效。已有 household 角色及人格必须原样保留。
3. 每角色可选已配置的提供商及模型，或显式继承全局默认。运行请求真实使用角色选择，固定到本轮快照；模型失效显示不可用，不悄悄换到另一角色/全局模型。轮次重试、供应商撤销、并发改配置不能串版本。不同角色模型不同必须用录制的上游请求验证，不能只测表单。
4. 每角色独立记忆域，默认仅自身记忆。角色内可配置记忆使用/新增记忆（仅映射现有真实支持模式），不允许任意输入其他 actor ID 借用其记忆。原始群聊/私聊观察档案与角色记忆必须区分，创建角色不自动获得历史全部私聊。首轮不实现跨角色共享；身份可共享，记忆可见性不能因此共享。记忆撤销、召回、候选、短上下文、缓存、日记和异步任务都必须防串角色。
5. 可用功能列表只显示实际接入并能强制约束的能力，可用与未接入区分。服务端在调度/执行处执行限制，不能只是提示词或前端复选框。至少覆盖本轮真实运行路径的对话、记忆读写及已存在可挂接能力；禁止虚构已集成工具/MCP/设备能力或任意代码工具。
6. 新角色可用于网页聊天与机器人接入/观察回复策略的角色选择，已有 NoneBot/AstrBot 协议复用。不新增隐式发言权限，群私观察/白名单/黑名单策略保持；默认观察的账号不得因创建/启用角色而发言。多账号/多连接可以绑定不同角色，不能抢别的连接回复或重复回执。
7. 多角色实际并行调度，不是只复制人格UI。角色停用阻止新轮次和未提交的新动作，已有记录保留；在途行为有明确一致性语义、结果不串流、不串BOT。共享模型并发上限继续生效，失败角色不阻塞其他角色。

## 所有权与实现边界

- Companion 拥有角色生命周期/人格引用/运行能力和本轮快照；Memory 拥有记忆和可见性；Platform 拥有提供商及模型绑定、来源授权和网页聚合。页面不能写对方数据库，不复制第二套人格/记忆事实。
- 先输出简短接口及所有权方案给总控，然后在本卡边界内继续完整实现，不必为常规选择停工。跨产品新接口在任务检出的 docs/contracts-candidates 下输出 schema/实例/双方测试；根 contracts 由总控发布，已发布合同不原地破坏。
- 动态创建必须贯通正式认证与授权目录，不能以修改进程 settings 内存、任意 allowed_actors 通配符或仅改 JSON 文件冒充持久角色管理。写入幂等、版本冲突保护、重启恢复、授权撤销、日志去敏继续成立。若分布式应用未完成，返回明确配置中/失败，不显示已生效。
