# 天枢 PG 专用链路优化与前后实测

**本地实现和隔离实测完成，尚未合入产品主线或部署。** 两阶段记忆召回三轮均改善，普通召回耗时中位下降9.15%、上下文下降9.55%，撤回后的两阶段召回下降11.98%。来源同步的字段请求约下降6.72%；关键词收益小且轮次方向混合，首次负向同步未证明稳定提速。普通短字段及写入对照出现不利结果，不能概括为PG所有路径均更快。

## 实现与完整边界

基线为最新已验收完整历史 `c696fd0de073dc375b161fb8192dc2713dc26b63`，运行候选 `06040aad9482f1f0ec8742f0a382daba9174f30a`；测试补充提交 `daef6b08fcc78570904a17b66d8de6f177f9e711` 与后续交接只改测试/文档，src tree保持一致。这里比较两套同依赖的候选镜像，不把c696基线冒称当前线上镜像。

- 记忆召回沿用现有PG read_batch，在来源准入之后合并正文/事实标记及projection/事实读取；外部排序后第二次operation批量重新核对组成员原值、版本、来源与projection。完整组和排序公式不变。
- PG预算按UTF-8外壳、完整组、数组逗号精确累计，减少整前缀反复编码；select/context/profile显式分派。SQLite仍用原预算策略。
- 资料库证据引用通过PG LEFT JOIN一起取得当前版本hash，省去每引用独立hash SELECT；项目、版本、allowlist、文件双读hash及最终证据校验保持。普通_query已有联表，这项额外收益只在恢复/check等_reference调用链归因。
- 来源物理负向广播改为集合UPDATE，保留每行revision trigger及epoch更新；最终invalid集合读取lineage，独立admission分块确认使用已有read_batch。未将有依赖的owner RPC并发执行。
- 完整合同和关系规则、作用域/权限、六次fresh revision与三个常见依赖RPC、第二次operation的新授权、锁后读取、CAS、跨actor撤回、负向先持久化、guard先于commit和PG同步提交保持；独立代码审阅未发现具体语义阻断。
- 共享存储固定0.1.3/019b954，contracts.py、adapter、schema/迁移、TLS与锁模型无改动。媒体和原文件继续放文件库，未转入PG或Redis。

## 实测协议

主比较24次客户端运行、3846次正式操作；独立引用补测6次运行、240次正式操作。均为三轮旧/新交替，第二轮交换版本顺序，一次一个活动客户端；时间内无profiler或计数hook。表为各轮p50/p95的中位数，负数代表耗时减少，不混成一个总提速比例。全部原始wall/process/thread样本、轮次方向与不利结果在JSON中保留。

全部已实现结果签名一致。旧memory_sql/source_sync签名仅比较无序语义组与完整成员，不比较全部授权封装或返回顺序；这些边界另由原生业务及专项功能测试覆盖。新两阶段召回签名保留scope/source/visibility等封装；Knowledge保留完整query响应与provenance，引用补测另绑定state与principal投影，并比较顺序。首次负向词法同分受生成ID影响，只比较完整内容。各签名的准确范围在formal.json中单列，未把旧签名夸成全字段证明。

两套离线wheel使用同一受保护基础镜像03ecca02及相同依赖闭包。实机PG17.6，fsync/full_page_writes/synchronous_commit均on；不改变生产PG参数。客户端512MiB、CPU0–7/shares128。服务器后台工作未冻结，观察负载见各run；CPU为客户端进程/调用线程，彼此重叠，不能相加，也不含PG服务端与远端owner。

主Memory负载300组起步，真实提交后365组；SourceAuthority负载300组/30来源，独立诊断40来源；普通资料负载200块并有闭包及导入样本；两阶段检索24组/32单元/24selectors。首次负向样本在独立夹具撤回16个单单元来源，另8个双单元来源继续有效，并确认epoch、guard、关闭重开与可见内容；不是全部24来源撤回。

owner响应和外部模型排序端口为确定性合成数据，实际使用产品SourceAuthority、Retrieval和原生SQL；不是生产owner TLS延迟或并发容量证明。旧memory_sql写入夹具使用LocalFixtureSources/LocalWorkflow，其source命名不能冒称真实SourceAuthority。
