# TS-126 媒体硬链接存储去重

用户要求保留 UP 主订阅和收藏夹各自目录，以硬链接共享同一视频，避免不同目录重复占空间。本轮从已部署 Platform `169effaf5332c45b3437961e3801779d8c985f8c` 演进，不混入另一对话尚未集成的供应商多模型变更。

执行中供应商多模型已由原对话独立集成并发布 `a53993c92612f61ca637552edb1709a1b434f038`。协调检出已快进到该main，本轮媒体提交将接在其后，部署前重新读取NAS基线；保留该已发布功能，不重做其实现或迁移。

在既有 FileOrganizer 与 `.tianshu-transfer` 控制目录内提供同卷共享视频文件，内容以已验证的长度与SHA256确定；跨卷 staging 首次复制一次进入媒体卷，后续目录硬链接。元数据/封面独立。共享文件采用无媒体扩展名的隐藏控制路径，避免媒体服务器将其当成额外条目。不改变现有全局BV/CID/画质下载去重或媒体数据库schema。

重试、并发和元数据更新复用既有库锁、成品回执与原子发布；视频绝不就地截断共享inode。硬链接不被文件系统支持时保留现有复制降级和明确结果，不谎称存储去重。转换已存在成品仅针对天枢有回执、marker与哈希匹配的当前视频，以临时硬链接加原子替换，保留独立元数据和任务记录；不扫描或改动不归天枢管理的媒体。

一个产品写者使用 gpt-6.1-sol/xhigh，独立 TS-126 工作树；其他既有代理并行审查方案及运维约束，不写同一产品文件。协调者负责集成、推送、NAS更新与当前测试目录的真实验收。验证覆盖跨卷输入到双中文目录同inode、旧成品转换、质量/内容不同不串链、元数据独立、删除一份不影响另一份、幂等重试与中途失败恢复。上线后用上轮真实视频验证两个目录的device/inode/nlink、分配块数与Emby识别/播放读取，临时订阅保持暂停。

根工作区原有混合修改保留；检查和分配器若受历史仓库状态影响，记录后从干净已部署版本建立任务工作树，不清理或覆盖既有项目。
