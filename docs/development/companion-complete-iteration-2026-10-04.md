# 天枢陪伴全面迭代计划

日期：2026-10-04。状态：C1 Memory、C2 Gateway、C3 Companion 已派发独立 worktree 实现；公共扩展接口正在收敛，尚未集成或部署。本文是本轮唯一计划入口，后续直接维护任务状态与决策，不另建重复方案。

## 目标与执行授权

用户允许大规模调整陪伴结构，要求先按最终形态规划、完整功能块并行实现、统一集成，避免反复搭建平行系统。产品实现和产品修复全部交给 GPT-6.1-sol / xhigh 子智能体；主协调负责架构、公共合同、分发、审查、合入和验收。沿用当前对话，不创建新窗口。此授权覆盖旧 DSH-only 等历史执行偏好。

一次迭代指一个目标架构、一套数据权威、一个整体发布候选和一次正式切换，不意味着一个巨型提交，也不承诺零返修。依赖仍按工程顺序实现，返修应收敛到同一设计，不能通过增加第二套系统绕开问题。用户随后明确授权推进全部实现、GitHub 提交与 NAS 部署。当前派发与逐场景证据维护于 companion-complete-execution-2026-10-04.json，不将正在开发称为已完成。

## 范围与完成定义

本轮完整交付以下陪伴功能，不用空页面、未接线接口或固定示例替代：

1. 同一角色的普通聊天、后台生活、主动表达、工具结果接续；多角色状态和受众隔离。
2. 自然记忆召回、近期关注、开放事项、承诺、指代接续、即时纠正、长期记忆修订和增量反思。
3. 独立时钟、全天计划、逐段经历、跨日活动、暂停恢复、日记、当地天气与时间。
4. 主动动机、机会竞争、合并延期、统一发送与真实回执；回应和未回应的有依据反馈。
5. 短期情绪、恢复与衰减；保留关系冻结和长期关系账本，关系不授予实际权限。
6. 日常穿搭、参考形象、生图与改图、角色相册、原图原文分享、作品持续修改。
7. 媒体发现与实际阅读、链接与上传材料、收藏与阅读进度；同一内容的共读或共同观看进度与插话接续。视频只声明实际取得的字幕、画面或片段覆盖，不以网页摘要冒充完整观看。
8. 网页和 QQ 的一致表达与按能力渐进输出；可信账号关联后的跨端话题接续。
9. 统一用户档案、角色生活管理、小屋活动和穿搭呈现、真实能力与任务状态、统一成本视图。

设计稿中的直播主播、完整游戏平台、手机常驻采集、摄像头/音响主动控制、通用插件市场和任意后端工作流编辑器，归独立扩展范围，不冒称本轮实现。现有相关功能不删除；本轮留下已有能力接口的接入位置，不预建专用基础设施。TTS 等既有能力可接统一表达，但新增实时通话和全双工语音不作为本轮完成条件。

真实供应商、媒体源和渠道逐项记录本地验证/真实验证/未配置。可配置实现通过不等于真实服务验收通过；缺少外部配置的功能不得标为生产就绪。

共同使用四种明确对象：

- 事项意图：还想做什么、为什么、面向谁、当前版本；不等于已经预约或执行。
- 有来源的认识：知道什么、何时观察、覆盖范围、不确定性、依赖哪条来源；过期不误删独立成立的意图。
- 活动与机会：活动进度/检查点，以及实际安排的下次运行；真实时区和 UTC 时间均明确。
- 结果引用：原操作、内容版本、实际投递结果；不复制造成事实矛盾的摘要账本。

对象需要 actor、对象 ID/版本和必要的作用域/来源；只给确有外部副作用的操作保留幂等/回执字段，不把所有内部函数都包装为通用协议。Memory、Platform、媒体 owner 之间仅通过正式接口，不直接读写对方数据库。

## 核心运行规则

聊天、时间机会、可信来源变化和工具完成进入同一角色上下文装配与行动流程。普通短对话可以一次生成完成；缺材料时才补查，复杂活动才继续工具调用。没有每分钟固定模型巡视，也没有每轮强制规划/审核/反思模型链。

日程保存未来意图，阶段发生后才记经历。重启补算当前状态与遗漏机会，不虚构离线期间已读文章、已完成作品或已发送消息。天气和聊天只修订受影响的未来安排。当前活动、穿搭、图片描述和小屋读取同一投影。

主动从实际生活、开放事项、约定、近期对话中形成有期限的动机。一个窗口合并相近机会；正在聊天时优先并入对话或延期。自然变化可在机会级选择中体现，不能每个 tick 独立抽签导致运行频率改变发送概率。思考频率、生活生成预算、联系频率与内容偏好分开，偏好不变成发送指标。

角色主动发送不伪造一条用户入站消息。主动与普通回复共用平台发送队列、取消、查询和回执；分别标明产生原因。发送成功才进入可确认的联系统计；失败、未知结果和用户尚未回复分别表示，不把提交请求算成已联系。不将沉默认定为反感、被忽略或自动扣好感。

纠正先约束当前上下文与待发表达；长期修订复用 Memory，只有获得真实写入回执才能声称已保存。反思按新增来源与有价值变化工作，可以不产生新记忆；只重算受影响内容，不重读全部历史。

媒体先有来源及实际阅读覆盖；生成先有原任务结果；原图入册后可以延后分享。图片里的服装不自动改变当前穿搭；明确换装才更新生活状态。人物身份参考、衣物、姿势与背景用途分开。生成结果未知时查询原任务，不直接重复计费重发。

跨端接续仅对已可信关联的同一人、同一角色和允许的受众生效。私聊内容不因同一个人出现在群里就复制过去。

## 跨产品接口收敛

主协调维护 contracts；实现者先提供生产者/消费者差异清单。复用 text-dialogue、profile-memory、role-relationship、life-read、bot-connection、web-conversation、model-protocol，不为每项 UI 新建协议包。

| 接口族 | 必要新增或变更 | 生产者与消费者 |
| --- | --- | --- |
| 生活与角色事项 | 活动检查点、穿搭、情绪投影、开放事项、相册/作品引用；管理操作与版本冲突 | Companion → Platform，Platform 管理 → Companion |
| 上下文与修订 | 有界相关检索、纠正提交与回执、反思增量提议及来源失效 | Companion ↔ Memory |
| 表达与发送 | 主动来源封套、输出单元、原内容引用、发送/部分/未知回执、取消与恢复 | Companion ↔ Platform ↔ 现有 QQ 适配器 |
| 模型执行 | 支持的流/工具/视觉能力、增量事件、用量、取消和失败边界 | Gateway → Companion/Platform |
| 媒体获取与原件 | 原对象/版本、可读范围、读取覆盖、产物与原操作状态 | 现有内容/资产 owner ↔ Companion，Platform 只聚合 |

先确认现有合同具体变更及最小 schema/正反样例，消费者才能并行编码。这里是接口责任计划，尚不是已发布 schema；不把草案称为冻结合同。重大变更保留明确版本，切换时旧新发送资格不并存。Memory 现有 select/profiles/revise、SourceAuthority.operation 和候选提交可复用；设计稿的 memory.extract/proposal.submit 不是当前可调用端口，不得直接按其名字编写消费者。新增提议至少明确目标/期望版本/证据、逐项回执与可查询操作 ID；反思另记录批次、项目与来源覆盖，以便部分失败续接。

## 迁移与整体切换

由各数据 owner 单写迁移；保留 actor/person/来源/作品与媒体 ID 及已有权限，不以新角色或新表空库掩盖旧数据。旧纯文本字段不能可靠转换为活动/事项时保留历史记录，不猜测补造。

开发在隔离数据与独立 worktree。先组装最终候选，使用有代表性的非空隔离库验证升级、重启、恢复和旧记录读取。包含普通聊天、既有日程、关系冻结、已发消息、在途/未知图片、跨日活动；绝不复制真实私聊内容入库。

发布前明确旧 worker、定时器、发送者的退出点，在途操作继续查询原账；切换只允许一个有效执行者。代码回退与数据库回退分别设计，旧备份不能无声覆盖升级后的新数据。生产数据库变化先有一致备份和实际可执行恢复办法；不以“重新部署旧镜像”冒称完整回退。

沿既有 GitHub/NAS 发布流程处理最终固定候选，不在每个小包完成后更新线上。部署、迁移、真实模型/图片调用及真实消息分别记录实际结果；本计划本身不启动外部动作。

本轮已确认的发布差异：Memory 与 Knowledge 共用产品源码但运行数据分别备份、分别升级，五个核心服务均纳入固定候选。Memory 先按 `migrate-context --backup` 升级既有 schema 3，保留配套 source-guard；Knowledge 的原件范围迁移在 C5 最终交接确认后执行。媒体解析依赖变化须由实际锁文件构建 Linux 镜像，不能沿上轮“依赖未变”的源码覆盖缓存路径。上一轮 OpenCode 的三服务 image-only cycle 及 settings_unchanged 断言不直接适用于本轮，复用其精确镜像来源、属主挂载检查和备份办法，并按本轮真实配置/迁移差异调整切换与恢复。

## 验收场景和停止条件

使用已有测试框架，按领域完成后集中验证。接口早期只做必要生产者/消费者样例，最终公共能力大改覆盖受影响套件；成功且输入未变的检查复用。无需新增基线系统、覆盖率门槛或重复审查流程。

1. 无聊天仍推进角色日常；未来安排不显示为已发生，重启后不虚构错过的经历。
2. 同一角色聊天能提及真实当前活动；重要聊天暂停活动，之后从原进度恢复。
3. 不带“记得/上次”关键词也能按需取相关记忆；长对话和隔日能接续事项，已结束话题不强行复活。
4. 用户当场纠正后本轮不再沿用旧事实；长期修订失败不声称记住，撤回来源后派生内容正确失效。
5. 主动与普通回复共用发送；用户正在回复时不插入重复主动；失败/未知不记成送达，不重复发送。
6. 回应、暂未回应、明确不喜欢分别影响短期状态与后续时机，未回复不自动扣好感，关系冻结保持。
7. 天气与活动影响穿搭；同一套衣服在多次图片中可延续；仅画参考服装不偷改当前穿搭。
8. 无收件人生成并入册，重启后聊天取回同一原图；结果未知查原任务，图像入口实际可配置可使用。
9. 阅读文章/视频保留实际覆盖；共读中插话后继续同一内容；收藏不自动触发发送。
10. 作品继续原稿和版本，日记使用实际经历，反思不把角色虚构经历写成用户现实事实。
11. 网页/QQ多段输出、取消、超时、部分成功和恢复正确；跨端只读取可信关联和受众允许的上下文。
12. 角色切换后用户、生活、相册、小屋一致；桌面/手机/宽屏可用，登录、真实天气、OpenCode 和已通 QQ 不回退。
13. 升级含非空历史与在途任务的隔离库后可读可续，旧执行路径不再运行；回退演练不遗漏新数据边界。

每个场景标明静态确认、隔离运行、真实外部运行、待验证，不用测试数量代替功能覆盖。性能记录普通聊天延迟、每轮/后台模型调用、媒体生成费用、任务积压；对比是否新增无意义调用，不编造未测阈值。

停止条件：范围内页面到接口、领域、存储及外部能力配置链路完整；所有旧路径已明确退出；相关验证充分；剩余外部配置与真实验收缺口明确。不能用“大部分完成”把未接通功能标 done，也不为凑完整追加无关生态。
