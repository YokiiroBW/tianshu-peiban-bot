# 机器人接入第一轮

用户授权 NoneBot 与 AstrBot 两者均接入，实机测试对象稍后指定。开发可见 Sol/xhigh 任务，总控负责契约审查、集成和 NAS；不自动向真实群/联系人发送消息，不启用未指定渠道。当前 NAS 已部署十服务，平台日志预算须保留 5000ms；本轮不重跑首装。

## 交付目标

完成可安装运行的两种机器人适配器及网页连接管理：从认证 SDK 事件，经正式平台来源登记与核心，收到真实模型结果，再经原机器人 SDK 发回原会话。真实发送前的持久意图、重复消息/重复回复去重、unknown 不重发、重连恢复、授权撤销、唯一回复责任都必须有有效测试。默认只支持文本；不伪造媒体支持或 SDK 回执。

管理员应能明确创建机器人连接、选择接入类型、绑定角色和允许会话、查看待配置/在线/失败与最后有效事件。机器人插件本地安装及填写连接凭据步骤必须具体；网页不假装可以远程自动安装插件。密钥只一次展示/遮罩，日志去敏，不暴露用户消息；设备监控不在本轮。

## 三个独立写者

- BOT-P：`worktrees/BOT-P/tianshu-platform`，基线 88c07ae，平台代码/网页/本产品依赖和迁移唯一写者。优先形成最小机器人接入 HTTP 边界草案，复用 Sources/register/dispatch/scope，检查 Core 回复当前是否可由平台可靠轮询/领取；将适配器需要的字段、认证、幂等、回执定义写入本产品 `docs/handoffs/BOT-HTTP-DRAFT.md` 并尽早通知总控。实现注册/授权/管理/接入状态和必要的可靠回复通道。不可把平台内部管理员 token 下发机器人。不得自行修改根已发布 contracts；候选提案由总控协调发布。
- BOT-N：`worktrees/BOT-N/tianshu-companion`，基线 3167798，仅 NoneBot integrations、独立桥接 transport 模块、N 专属测试/文档；根 pyproject/依赖锁以及必须的 Core 边界改动只有 N 可写，改前向总控说明。把薄桥装配为真实可安装 NoneBot 插件，首轮 OneBot11/NapCat 文本，TG 能力如未真实支持明确列出。核对官方 SDK，不复制旧授权漏洞；与 BOT-P 接口对齐后做真实本地 HTTP 联合测试。
- BOT-A：`worktrees/BOT-A/tianshu-companion`，基线 3167798，仅 `integrations/astrbot/`、`tests/test_astrbot_*`、A 专属文档。实现可安装 AstrBot 插件，复用领域边界、不启动第二个陪伴引擎、不将其他插件消息通通拦截。核对官方事件/回复/传播控制 API，兼容需明确版本；不修改根 pyproject/锁/Core/NoneBot。共享 transport 若必要由 N 单写，先明确协议并测试注入，不能把合成发送器放生产。

所有工作者可读主目录合同/其他写者的已提交接口，不能写对方检出。适配器实际 API 随 BOT-P 草案统一后由总控冻结，不各自猜路径。开发默认仅合成隔离数据；真实机器人安装/启用与网络发送由总控协调。当前未知真实宿主版本，不能假定 SDK 最新版就是线上版。

## 集成验收

先验开发 diff、安装/启动及生命周期、真实本地 HTTP 联合链路和故障回归，再由独立 Luna/max 审查固定提交。实机验收需确定账号/会话白名单，只有用户指定测试对象后才发送。状态分别记录本地通过、已安装、已启用、实机收发通过；任何一层不得替代下一层。

每任务提交代码与 `docs/handoffs/BOT-{P,N,A}-2026-09-28.md`，含提交、命令与结果、依赖、真实宿主未验边界。总控串行合并，不自行改产品 main 或宣告全系统完成。
