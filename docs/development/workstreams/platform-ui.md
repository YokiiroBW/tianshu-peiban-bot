# 平台网页、连接器与动态小屋并行开发计划

2026-09-14 · 开发准备稿；本轮只规划，不代表目录、接口、命令或业务已实现。

依据：[整体架构 V2](../../architecture/tianshu-system-architecture-v2.md)、[拟议接口目录](../../architecture/v2/interface-catalog.json)、[已认可视觉目录](../../../output/ui/README.md)。本稿服从工作区总开发流程；这里的项目内部路径是待脚手架任务落实的写入分区，不另行创建一套仓库布局。

## 1. 本线边界

平台项目集中在 `projects/tianshu-platform`，包含网页和平台后端连接器。它是协调检出，不是让三名编码体共用一个可写 Git 索引；每项并发任务使用总流程登记的独立 worktree，再由集成人合入。旧系统、NAS 和真实设备不因创建开发工作区而迁移或改写。

网页包含文字陪伴、小屋、记忆、资料与资源、家庭与服务、项目、任务与设置。实时语音通话、共同观影不在网页导航、浏览器权限、媒体依赖或首轮交付范围；历史第 18 张只作可选客户端参考，第 19 张只取移动布局。QQ/TG 语音消息能力由接入与核心线处理。

平台是统一交互入口，不夺取数据写入权：房间、人格、世界、日记和穿搭由核心负责；人物、记忆与研究资料由记忆负责；资产发布由 AssetLibrary 负责；模型真实调用与用量由网关负责。网页的设备按钮直接调用平台已登记能力，不能强制经过模型。

## 2. 可独立推进的任务与写入区

每个任务有一个主写入者。表中路径均相对 `projects/tianshu-platform`；若脚手架选用其他布局，开工前更新本表一次，不让各任务自行改名。

| 任务 | 拟议专属写入范围 | 产出与依赖 | 禁止顺手修改 |
| --- | --- | --- | --- |
| P0 平台脚手架与契约消费 | 根清单/锁文件、`apps/web` 入口、后端入口、CI、项目 `AGENTS.md` | 锁定实际工具版本、路由挂载口、契约消费方式、真实验证命令；先于分支任务合入 | 不能把所有业务模块先写成空壳框架 |
| P1 视觉基础与页面壳 | `apps/web/src/design/`、`apps/web/src/app/`、`apps/web/src/components/` | 单一令牌来源、导航、主题、抽屉、提示与状态布局；先提供 room 挂载口 | 不改 room 内部渲染、连接器、核心状态定义 |
| P2 设备能力与任务投影 | `services/platform/src/connectors/`、`capabilities/`、`jobs/` 及对应测试 | 第一条 HA 读状态/服务动作链；容器只读状态映射；消费统一命令与任务契约 | 不复制核心/记忆/资产表；不改前端令牌、路由与锁文件 |
| P3 动态小屋样片 | `apps/web/src/features/room/`、`apps/web/public/assets/room/`、对应样片测试/记录 | 独立路由内验证环境、交互、资产与设备性能；消费核心 I07 样例 | 不改全局主题、导航、通用控件、核心房间规则；不导入第二套渲染引擎到常驻包 |
| P4 真实页面贯通 | 逐批登记 `apps/web/src/features/<workspace>/` 和对应测试 | P1 稳定后，把一个工作区从样例数据接至真实责任方；依赖对应接口 | 同一工作区不得同时交两名作者；不因页面方便改责任方契约 |

P0 合入前，P1 可盘点现有材质和布局，P2 可整理已验证的外部 API 样例，P3 可列素材与交互验收场景；它们不能各自初始化框架、生成独立锁文件再硬合并。P0 合入后，P1、P2、P3 才可并发编写各自范围。

根清单、依赖锁文件、全局路由、设计令牌源、公共客户端生成输出、数据库迁移顺序和 CI 由平台集成人单写。任务需要新依赖或公共控件时提交具体用途与最小变更请求；集成人合入后，其余 worktree 更新基线。任务执行者可修改自己模块内的迁移提案，不能自行抢占全局迁移编号。

小屋模块向外仅暴露页面入口与已约定的状态/命令端口。P1 放置懒加载入口，P3 在内部开发；测试样例放在小屋专属目录，不能修改全局模拟服务来夹带房间状态。共享接口变更先由核心/契约责任人确认并发布兼容样例，再改消费者。

## 3. 视觉系统如何落地

现有可操作原型 `output/ui/management-v2/index.html` 已有浅色/深色材质变量、减少动态和减少透明度处理；它是提取依据，不是新生产应用的组件库。现有 `--ok` 绿色不能直接充当新容器运行色，容器必须遵循更晚认可的蓝、黄、红、灰状态规则。

P1 先建立一份位于 `apps/web/src/design/` 的令牌源，含颜色、材质、排版、间距、圆角、焦点、层级和动效。具体采用 CSS 变量源还是结构化令牌源由 P0/P1 在脚手架时选定一次；若有 CSS/TypeScript 输出，它们由同一来源产生，不能人工维护两份同名数值。只有项目需要跨工具生成时才加入生成工具。

业务页面消费语义令牌，不复制渐变和阴影值。小屋操作浮层消费同一令牌；房间材质、光照和窗帘物理参数属于场景资产/渲染配置，不强行塞入界面令牌，也不能影响全站状态色。

| 页面 | 保留的视觉与信息组织 | 不采用的替代 |
| --- | --- | --- |
| 工作台 | 近期事项、时间线、异常优先；乳白正文和少量毛玻璃浮层 | 每个数字一张大型卡片，装饰占据首屏 |
| 记忆 | 紧凑主题簇，选中再读来源/范围/版本；按需加载 | 全人物图谱一次绘制，点击即取完整画像 |
| 日记 | 日期目录与书页阅读，授权状态先于正文获取 | 全文先下载再用锁图遮住 |
| Docker | 细状态轨、名称、动作、实际状态/健康/采样时间 | 只有一颗绿点；未知等于停止；假波形 |
| 资料与项目 | 可检索列表、阅读区、任务和变更上下文 | 通用 KPI 卡片套所有页面 |
| 资源整理 | 画廊、相似对照、具体整理计划与分阶段结果 | 把模型“优选”直接映射成删除 |
| 小屋 | 场景为主，物件交互与可收起的控制浮层 | 用一堆管理卡片盖住室内画面 |

先做默认、悬停、键盘焦点、选中、禁用和实际可达的加载/空/离线/部分失败。浅深主题、长中文名称、移动重排、减少动态必须在首个贯通页面验证；不用先给所有占位页补不存在的业务状态。

## 4. 最小先行样片：两条可独立演示的结果

### 4.1 平台样片：家庭与服务中的单设备操作

页面壳包含精简导航、主题切换和工作台入口，第一条真实业务选择“一盏测试灯”：显示实体、来源、最后观测时间和可用动作；点击开灯经平台能力执行者返回受理结果，再等待 HA 观测。初期先用明确标记的固定样例验证界面，不接触真实设备。

最少覆盖成功、动作已受理但观测未变、实体离线、连接超时、权限拒绝、状态过期。任务详情展示 `(owner, job_id)` 与真实责任方；没有后台任务的短操作不硬造完整工作流。容器状态先用同一页内的只读列表样例验证四色及运行/健康区分，部署写入留到具体计划与执行接口就绪。

### 4.2 小屋样片：一个场景验证主要风险

固定视角，一个房间、一个窗扇、纱帘与遮光帘、两盏可独立控制的灯、桌椅、一个角色姿态。先用几何与有合法使用来源的最少素材证明行为，再替换为认可风格；不要先制作整套家具系统、复杂角色换装或开放编辑器。

优先验证 Three.js 正交视角轻量 3D；与已有 2D 候选做限时对照，记录遮挡、风摆、资产制作成本及代表手机表现后选择一条主线。对照可以是独立样片页面，不能同时把多套引擎塞进生产首页。没有兼容动画资产时明确显示静态姿态，不能宣称已实现角色动态换装。

样片分两个模式：本地演示状态用于验证画面；真实状态模式消费核心快照和事件。演示时间只改变本地预览，界面明确标注预览且不会发出写命令。普通自动模式读取核心时间基准、灯窗帘参数、变化起点和手动保持状态，帧插值在浏览器完成。

核心尚未提供 I07 时可以完成光照和控件样片，但不能通过“跨浏览器状态一致”“关网页仍继续生活”等真实验收。必须接入实际核心持久状态与版本冲突行为后，才进入生活能力联调。

## 5. 契约先行与切换真实接口的时点

当前 I01–I18 是拟议能力目录，不是可请求的 URL。本线只要求消费者实际需要的字段，禁止为了平行开发自行虚构第二套正式 API。

| 消费点 | 先冻结的最小内容 | 何时必须用真实责任方 |
| --- | --- | --- |
| 文字陪伴：I01/I18 | 消息分段、作者/渠道映射、受理与取消结果、会话标识 | 首次宣称网页文字贯通之前；防抖/两轮调度由核心验证 |
| 小屋：I07 | 房间/角色 ID、版本、时间基准、物件状态、手动保持、变更命令、冲突与增量恢复样例 | A07 两浏览器与关闭/重开验收之前 |
| 日记：I08 | 授权查询、拒绝结果、正文读取、内容版本 | 第一次可阅读真实日记之前；拒绝时网络响应不能含正文 |
| 记忆与知识：I03–I05/I11 | 可选字段、来源与范围、版本、更正、游标与空返回 | 开放真实人物数据、纠正或资料入库之前 |
| 设备操作：I09/I17 | 已受理/实际观测/未知结果、目标校验、任务责任方与取消回执 | 首次触碰设备、重试或重启功能之前 |
| 资源整理：I12 | 只读计划、暂存引用、来源版本、审批计划引用、发布及索引阶段 | 任何受管文件移动、覆盖、删除之前 |
| 图像任务：I13 | outfit 与生活版本、工作流模板、类型参数、GPU 队列、资产引用 | 主动或手动提交真实 ComfyUI 工作流之前 |
| 模型设置：I14/I15 | 凭据提交/脱敏读取、配置版本、能力验证状态、线路回执 | 提交真实 key 或宣称切换线路生效之前 |

样例数据应来自版本化契约样本，至少包含正常、空、超时、冲突、未知和部分失败；标记为样例环境。真实模式不在出错后悄悄回退样例成功。前端不能从内容自由文本猜任务是否完成，也不能把服务端错误改成“操作成功”。

平台同源入口可转发核心/记忆命令并订阅投影，但不得把浏览器声称的管理员字段当授权。提供商与连接器凭据只在服务端保存；前端仅显示脱敏值。浏览器构建产物、日志和可共享截图不得包含真实凭据。

## 7. 验收证据与真实命令登记

当前只有设计资料和演示页面，未发现新平台的 `package.json` 或 `pyproject.toml`，因此本稿不写假定的 `npm test`、`pnpm build` 或后端测试别名。已有 `tmp/research/check-management-ui-v2.cjs` 与 `check-remaining-ui-gallery.cjs` 用于旧原型/图片浏览页，它们通过也不能证明新平台业务完成。

P0 必须从实际创建的清单、脚本和 CI 登记以下信息到项目 `AGENTS.md`：安装/启动方法、格式/类型检查、最窄测试、相关模块测试、构建及浏览器验证的真实命令，以及必要环境变量的**名称和用途**。提交前按变更风险从低成本到高成本验证，不要求每改一行重新跑全套，也不随意刷新视觉基线。

| 验收 ID | 必须能观察到的结果 | 证据与限制 |
| --- | --- | --- |
| P-A01 视觉连续 | 银蓝/淡紫/浅粉材质来自同一令牌源；Docker 四色和选中态分开 | 令牌引用检查 + 1440px 桌面/390px 手机代表截图；不能以截图替代行为 |
| P-A02 可访问交互 | 键盘可到达/退出抽屉，焦点返回触发点；减少动态有效；长中文不遮挡 | 键盘走查、DOM 断言、200% 缩放和浅深主题检查 |
| P-A03 页面加载边界 | 非小屋页不启动 WebGL；进入小屋懒加载，隐藏/卸载后停止高频绘制并释放资源 | 网络/性能记录和资源清理断言；禁止只靠 CSS 隐藏持续绘制 |
| P-A04 灯窗帘因果 | 两灯各自照亮局部；闭窗仍透光；开度影响风，关窗后衰减；两层帘独立 | 固定输入状态下的录像/交互记录；注明资产与设备，不伪报真实天气 |
| P-A05 房间真实一致 | 两浏览器读取同版本；冲突显式处理；预览不发命令；手动保持不被自动覆盖 | 实际核心服务 + 命令/快照版本记录，对应 A07/A08 |
| P-A06 设备状态真实 | HA 受理与设备观测分开；离线/过期/未知不显示成功；容器健康未知不显示健康 | 适配器测试与真实测试目标的反馈记录，对应 A10 |
| P-A07 任务责任正确 | 取消转责任方；重复阶段事件不重复通知；部分失败保留失败阶段 | 重放/乱序/断线恢复测试，对应 A12；不要求自造通用任务引擎 |
| P-A08 日记和记忆范围 | 未授权的响应无日记全文；纠正和范围变化后刷新读取当前版本 | 真实服务响应断言，对应 A02/A05/A09 |
| P-A09 网页范围 | 导航、依赖与权限请求无实时通话/共同观影；文字与小屋正常 | 路由/权限调用检查 + 运行时走查，对应 A15 |
| P-A10 移动端实际表现 | 房间质量可降级、操作可用、页面无横向溢出 | 真机型号/浏览器/分辨率、帧时间与内存记录；模拟视口不能冒充真机性能 |

首轮性能先建立可复现基线：设备、浏览器、分辨率、资源版本、画质、冷/热加载都写明。LCP 2.5 秒、INP 200 毫秒、CLS 0.1 可作网页目标；样片没有线上 p75 数据时不能宣称达标。小屋帧率预算在真实样片与代表设备测试后确定；不把开发机瞬时 60 FPS 写成全设备承诺。

## 8. 每项任务的最短交接

任务记录只保留目标、允许写入路径、依赖契约版本、当前基线、已完成行为、实际验证结果与未完成事项。长截图/性能轨迹/日志存为引用，不复制进每次提示词。交接注明本任务使用样例还是真实服务；任何“完成”都能追溯到上表一个用户可观察的行为。

合入前由集成人检查改动范围与公共文件冲突，确认没有把样例成功路径带入生产、没有新增网页媒体范围、没有越权写核心/记忆/资产数据。集成后的相关贯通验证只在新改动影响它时重跑。小屋引擎选择、资产兼容或外部 API 未通过时记录具体缺口，继续其余独立任务，不靠截图把缺口标成已完成。
