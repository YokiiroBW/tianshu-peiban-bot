# 陪伴核心与记忆开发线

2026-09-14 · 并行开发任务规划 · 本文不表示项目已经实现或验证。

依据：[整体架构 V2](../../architecture/tianshu-system-architecture-v2.md)、[接口目录](../../architecture/v2/interface-catalog.json)、[防抖与消息组](../../architecture/message-debounce-and-bundling-design.md)、[画像粒度](../../architecture/profile-memory-granularity-design.md)、[核心流程](../../architecture/companion-core-flow-design.md)、[召回与整理](../../architecture/memory-recall-and-lifecycle-design.md)。职责冲突以 V2 为准。本文任务编号用于本开发线，可由总任务表映射，不另建一套重复进度账本。

## 工作目录与写入边界

| 开发线 | 主工作目录 | 权威对象 | 不得接管的对象 |
| --- | --- | --- | --- |
| 陪伴核心 | `projects/tianshu-companion` | 收件、消息组、轮次、发送与动作记录；人格、当前世界/房间/生活、穿搭、作品版本、日记访问决定 | 长期人物档案、记忆索引、提供商密钥配置、设备实际执行、受管文件移动 |
| 记忆 | `projects/tianshu-memory` | 人物/账号绑定、关系、画像、经历、记忆修订、来源与知识单元、索引及整理任务 | 角色当前世界/房间、原始聊天总档案、项目当前任务、资产物理目录 |
| 联合契约 | 根目录 `contracts/` | 已接受的边界格式、兼容样例与行为断言 | 公共业务核心、统一任务执行器、共享数据库模型 |

NoneBot 薄桥包属于陪伴项目，但运行时可独立进程。记忆通过接口服务核心；不得为图省事让两个项目互相导入内部模块或直接写对方表。共享 PostgreSQL 实例不改变数据归属。

同一时刻每个活跃任务绑定一个负责人及独立工作目录。同一仓库需要多人并行时使用独立分支/worktree，不让两个编码体共用同一个可写 Git 索引。主目录是集成检出，不因“所有项目在当前目录”就允许跨项目随意改文件。具体 worktree 位置和分支命名服从总流程；本文件不创建它们。

## 开工前共同锁定的小契约

契约负责人先将 V2 的能力名转成可运行项目使用的首版路径与字段。下面是首个贯通切片需要锁定的内容，不要求先写完 18 项接口：

1. `I01 / I02`：入站消息、受理回执、结构化消息组与发送回执；消息、轮次、段落编号分开，附作者、引用、修订和媒体引用。
2. `I03`：账号定位返回稳定人物编号；查找与经验证关联是不同操作。服务端确认渠道来源，不相信模型或浏览器自报身份。
3. `I04 / I05`：有界选择包、权威修订、记录/范围版本、完整依赖组、无结果与内部故障。补查累计使用同一轮预算。
4. `I15` 的最小调用边界：本轮的功能绑定和配置版本、时限、正常响应/流、用量已知或未知；不在核心自建另一套路由器。
5. `I18` 与 `memory.revised`：明确取消/完成、编辑撤回影响的目标与版本；普通新消息不是取消信号。

最少准备正常、重复、旧版本、越界、超预算、依赖不可用六类契约样例。样例含合成资料，禁止把真实私聊、模型密钥或家庭网络凭据提交到仓库。字段变更由提供方和当前消费者共同审阅；破坏性变更同时升级版本、样例和消费者，不靠所有分支“明天一起改”维持兼容。

## 并行次序

首版契约确定后，`C1` 与 `M1` 独立启动；核心使用契约替身继续开发，记忆用固定查询样本推进。`C2` 与 `M2` 对齐首个真实贯通场景，随后完成 `CM1`。`CM1` 通过后，核心的生活链 `C3`、记忆的整理/资料链 `M3` 可以并行；`C4` 等平台任务/生图接口就绪后接入，并在 `CM2` 验收。不要因为平台全部页面或所有连接器未完成而阻塞文字陪伴主线。

替身用于解除开发排队，不是集成完成证明。某依赖不可用时，该任务可以达到“组件完成、集成待验证”，不能把状态记成最终完成。两条线各自安排同仓库任务时也遵守独立工作目录规则。

## 陪伴核心任务

### C1 · 可恢复的输入、两轮调度与发送

**范围：** 实现 NoneBot 薄桥和核心受理边界、可靠短期收件、去重、结构化收集、防抖、轮次状态机、持久发送记录。先支持 QQ/TG 文字的标准格式，真实渠道先贯通一个，另一个明确保留验证状态；附件先保留引用和准备状态，不在此阶段实现全部多媒体。

**依赖：** `I01/I02/I18` 首版契约；可注入的计时器、生成替身和发送替身。不要在等待模型/工具期间持有整个会话锁。

**最小验收：**

- W=5 秒，0、2、6 秒续句在第 11 秒封存一次；W=0 立即封存；等于截止时刻的消息进入下一组。重复事件和旧计时器不延长窗口、不重复提交。
- 群内 A1→B1→A2 分人计时，保留 B1 的真实作者和相关插话引用；相同人在其他群或私聊的消息不合入同一输入组。
- T1 生成时，T2 完成自己的收集并在资源和实际依赖允许时开始处理；最多两个活跃陪伴轮次，群内多个角色共享限制。收集缓冲、已封存有界队列、生成容量与待发送记录分别计算，不偷换成无限后台轮次。
- T2 先完成仍按轮次/段落发送；普通新消息不取消或重启 T1；T1 失败/无回复会明确关闭，后续不永久阻塞。生成完成释放模型调用槽，但不能由此绕过会话活跃轮次上限。
- 队列满有明确受理/等待策略，不能静默丢消息或把未完整的句子当成可执行指令。重启恢复剩余窗口；回执不明先核对，不盲重发。

**交付证据：** 状态迁移表、可控时间的并发测试、一次故障恢复记录和渠道验证清单。不要把替身按序返回当成 QQ/TG 实际到达顺序保证。

### C2 · 最小充分上下文与一次主生成贯通

**范围：** 参与判定、当前话题、角色配置快照、记忆批量选择、主模型调用、受众/版本核对、真实投递。保留每阶段用时和本轮实际装配内容的受控调试入口。首个角色可配置人格，但不堆叠多轮规划、审核与反思模型。

**依赖：** C1；M1/M2 的首版真实服务；网关的 I15 最小可用调用。平台配置未全就绪可用本地安全配置进行开发，不将密钥写入样例，也不宣称正式配置链路已经完成。

**最小验收：**

- 问候可以使用零条历史记忆；“昨天那个安排”能按需取证；缺少依据时不靠熟悉语气编造往事。普通无工具聊天默认一次主要生成，调用次数可核对。
- 本轮只装配已选字段/完整证据组；没有候选全文、整份人物简介、账号历史或不相关兴趣。缓存随人物、角色、受众、用途与版本改变。
- T2 的独立准备不等 T1；依赖 T1 具体方案时，只在依赖处等待稳定结果。T1 草稿不能被当作用户已看到的事实，状态提交不按模型完成先后覆盖。
- 明确取消/完成及时更新当前执行状态；收到权威更正后，受影响的未发内容重新核对。已发送/已执行事实不伪称回滚。
- 记忆不可用时不使用无法验证的私密旧缓存；模型超时不重放已执行动作。Chat Audit 缺口与已归档状态区分。

**交付证据：** 核心→记忆→网关→真实消息渠道的一次正常与一次失败链路，附脱敏阶段用时、来源版本及调用统计。

### C3 · 同源的角色生活与房间状态

**范围：** 版本化人格/世界、角色当前日程活动和心情、房间灯窗帘、当前穿搭、手动保持与恢复自动。通过 I07 提供快照/命令/增量事实；网页渲染由前端线负责，核心不做逐帧动画计算。

**依赖：** C2/CM1；I07 和 `life.state_changed` 契约。无需等完整小屋美术资产交付。

**最小验收：** 同一状态版本驱动聊天称述、房间物件和穿搭引用；关闭浏览器后日程继续，重新连接读取当前快照；本地时间预览不产生真实状态或日记事件；两个客户端并发修改显式版本冲突；手动保持不会被日程覆盖。A 参与的事件不自动成为 B 的亲历，世界事实与角色获知记录分开，模拟事实不写成现实用户经历。

**交付证据：** 单角色一天的受控时间回放、多角色获知用例、网页消费者的真实状态读写记录。视觉样片通过与状态链路通过分别报告。

### C4 · 有因果的工具、创作与主动联系

**范围：** 长任务关联、工具/功能调用、写作配方、日记/作品版本、自拍的当前穿搭快照、主动分享候选及冷却。I09/I10/I13 的实际执行仍归平台或 NoneBot 功能入口；核心只拥有陪伴目标和关联记录。

**依赖：** C3；M3 的素材摄取与可检索事件；平台至少一个真实任务执行器；I08/I09/I10/I13/I17 的所需子集。GsCore、ComfyUI、日记可以在同一里程碑内分小批交付，不能因某个插件未接通而伪造回执。

**最小验收：**

- 先提交任务并得到真实受理结果，再表达进度；GPU 离线不阻塞普通对话。完成事件重投只续接结果，不重新生成图片或重复执行工具。
- 明确功能命令由单一回复责任方直达执行者，不占两个陪伴槽；自然语言调用同一执行函数，权限与来源不因走核心而扩大。
- 自拍使用本轮确认的 `outfit_id`、生活状态与工作流版本；“看看今日穿搭”不每次随机换装。生图成功与 AssetLibrary 文件可用分别确认。
- 日记有配方版本和素材引用，草稿/发布区分；不给无权调用者全文后再由前端盖锁。现实用户事实不由创作模型补写；材料不足允许短写或略过。
- 明确取消/已完成使待跟进候选及时失效；主动联系发送前核对最新事项和联系条件，不等待晚间整理。后台任务有独立限额与可取消状态。

**交付证据：** 至少一个真实功能桥接、一次实际 ComfyUI 任务、一次有来源的日记生成；各外部依赖分别标清已验证、失败或未验证。

## 记忆任务

### M1 · 稳定身份、语义记录与权威修订

**范围：** 人物/账号映射、群场景字段、关系与画像记录、来源性质、适用条件/可见范围、版本/修订/遗忘、最小摄取记录与 outbox。关系长期值归记忆，核心当前心情归核心；不得混为一张随生成更新的数值表。

**依赖：** I03/I05 与身份/范围契约。先用少量合成事实和精确查询，向量索引不是此里程碑的开工门槛。

**最小验收：** 同 QQ 账号跨群/私聊定位同 person_id；昵称/头像变化不新建人；跨平台关联需可验证证明。条件、否定、时间、转述/推测、来源引用均可表达；适用场景不等于读取许可。幂等修订与记录版本在同一权威提交内生效，相同键不同负载拒绝；历史可追溯，当前已撤回/删除记录不可用，索引重建不能复活它。

**交付证据：** 合成记录样本、身份冲突与旧版本写入测试、修订/遗忘恢复用例。此阶段不承诺自动正确合并所有同义记忆。

### M2 · 小而完整的选择包与更正失效

**范围：** I04 批量选择、精确查事项/字段、范围内关键词和必要语义检索、语义依赖组、预算、来源回读、缓存与版本校验。先完成有界精确/关键词路径，再以同一组问题验证语义检索是否补足间接表达；不先搭全能图谱。

**依赖：** M1；嵌入路线在接入前固定集合空间；Chat Audit 真实受限原文读取在 CM1 前至少验证一种已有路径，未就绪时源证据回读标明不可用。

**最小验收：**

- “晚上不喝咖啡，白天偶尔可以”不会被压成“喜欢咖啡”；一般偏好含例外时保留例外，明确场景问题只取完整适用条款。转述和条件计划不升级为亲历或已发生。
- 命中技术偏好不展开衣橱/音乐/整个人物；零项有效；多人共用本轮预算；补查和旧的已装配块均计入总额，预算不是填满目标。
- 必要依赖缺失、失效、超预算或不可读时，完整取舍或报告不足，不单独返回改变原意的残片；无权接收者看不到被过滤的私人记录存在性。
- 群场景读取不进入私密候选；允许共享的普通兴趣有显式投影和来源。相同问题在私聊与群聊不命中同一个私人缓存。
- 刻意延迟索引/丢弃失效通知后，更正、取消、遗忘仍通过权威版本核对生效；旧索引命中不使旧事实复活。服务不可用与无匹配在内部区分。
- 目标 tokenizer 不可核实时严格执行条目/字节上限，token 显示估计；不可伪报精确预算。嵌入模型更换不复用不兼容向量空间。

**交付证据：** 人工标注“最小充分证据”的样本集；同时报告必要证据覆盖、无关项、条件/主体保真、旧版本与越界命中、实际注入长度。短输出或高相似度不是成功判据。

### M3 · 增量整理、资料库与编码体接入

**范围：** 消费完整消息组与真实提交结果，形成候选及修订；知识来源版本、解析语义单元、研究笔记与定向查询；项目范围下的 MCP/适配入口。大型媒体由资产引用取得，原始聊天由 Chat Audit 保管，不复制资源整理器或项目任务系统。

**依赖：** M2/CM1；核心提交事件、平台任务投影及来源连接器的所需契约。先覆盖“一个网页/文件→可引用资料→一次项目定向查询”，再扩展来源格式。

**最小验收：** 普通整理不占当前回复等待链；重复事件不重复记忆/好感变化；候选生成不等于权威事实。背景工作断点继续且有独立预算，失效来源不能被旧任务重新写回。实际采用的研究来源可引用到版本，原文结论/模型推论/项目决定分开。Codex/Hermes 只检索获准项目与版本；接上 MCP 不宣称自动捕获其全部原生搜索。项目当前交接由平台负责，记忆只索引/提供短恢复包，不覆盖当前未提交工作。

**交付证据：** 一次真实来源导入与引用回读、一次编码体实际读写会话、一次取消/来源变更后的重试用例；未验证客户端单独列出。

## 两次联合验收

### CM1 · 第一条真实文字陪伴链

参加方：陪伴、记忆、模型网关；需要时联动渠道与 Chat Audit 维护者。以同一组私聊、群聊、两轮并发和更正样本跑通真实服务，而非互相调用 mock HTTP。

最低结果：一条实际入站消息形成消息组，经真实记忆查询与真实模型生成后送回渠道；随后在 T1/T2 重叠期间取消或更正，旧内容不继续产生错误动作。记录测试数据和配置版本、实际渠道、模型路线、阶段用时、故障点及清理方式。另一个平台未实测则保持未验证。

### CM2 · 生活、后台任务与恢复共同运行

参加方：陪伴、记忆、平台/网页、至少一个真实工具后端。运行日程、定向召回、资料整理和生图等后台负载，同时连续聊天；检查共用角色状态、前台余量、取消与回执未知恢复。内置队列用量和外部模型/GPU 限额都纳入观察，不能只证明各模块单独能启动。

端到端时间按防抖、排队、状态/召回、模型、必要工具、有序发送等待、渠道分别记录。此前自有开销 p95 500ms 是待测目标，不是阶段通过的既有成绩；不要相加各阶段 p95 冒充端到端 p95。性能样本要记录输入/输出长度、模型配置与并发负载，才可比较。

## 验证与交接保持精简

本轮只有规划，没有项目 manifests、测试脚本或依赖锁文件，因此这里不编造 `test:unit` 等可执行命令。每个项目建立实际脚本后，由该任务将真实安装、启动和验证命令写入项目 AGENTS.md/README 的唯一位置，总流程只引用它。确定性时钟/排序/版本规则用程序测试；语义选择用人工标注样本；真实集成用可复现且脱敏的运行记录，三者互不替代。

每个里程碑稳定后检查一次最终改动，再按真实项目配置执行语法/类型、最窄测试及受影响集成；跨项目契约变化执行当前消费者兼容检查。成功检查在输入未变时不反复重跑。不为单个可逆页面小改新增镜像实现的测试，但本文件中的并发、失效和范围边界属于必须验证的核心行为。

交接只保留一个当前检查点，推荐六项：任务与完成状态、对应提交/工作目录、已完成行为、实际验证与未验证范围、剩余阻塞/下一步、契约或关键决策引用。长日志留运行产物，设计正文不反复复制到交接；旧检查点随版本历史保存，不将每天的全过程追加进启动提示词。新踩坑先记项目，只有跨项目重复且有证据的结论再提交总错题本。

完成条件是可观察行为和证据，不是文件数量、模块数量或“服务可以启动”。一条外部依赖未真实接通时，清楚标记集成待验证，允许其他不依赖它的任务继续。
