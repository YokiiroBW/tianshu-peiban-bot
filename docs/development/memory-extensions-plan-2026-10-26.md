# 记忆扩展规划：历史查询、群图与 BOT 自主生活

2026-10-26。用户授权当前记忆核心推送部署；本文五项扩展只规划，尚未开工，不改变既有 AL 队列状态。

## 目标与复用原则

用户记忆回答“这个人大概说过、做过什么”，画像归纳相对稳定的认识；Chat 保存和查询原始聊天，补足归纳时丢掉的细节。BOT 自身记忆保存她真正读过、观察过、执行过以及由此形成的认识。各自有明确主体与来源，组合使用，不能互相冒充。

延续现有分段、多人物结构化整理和持久后台队列。精确人物使用真实 OneBot 账号绑定及 person_id，整理段另用 segment_id；昵称、段号和人物标识不混用。优先复用 Chat、Memory、Companion、Platform，不新建聊天库、图数据库、独立图服务或另一套整理队列。不追加逐句语义命中规则，不以总结满分为验收目标。

规划基于本批候选 Memory `62206f2`、Companion `68b85d0`、Platform `506a820`；实际生产状态另见本批发布记录。以下“将增加”均不是已交付功能。

## 五项能力及边界

| 能力 | 用户得到什么 | 数据与实现归属 | 首版边界 |
| --- | --- | --- | --- |
| Chat 全历史查询 | 按群/私聊、作者、时间、关键词查原话，并查看前后对话 | Chat 原文与搜索；Companion 使用真实只读工具；Platform 打开授权原文 | 可跨已采集/导入历史分页定位；不把整库放进提示词，不声称拥有从未采集的记录 |

## 现有能力与必须补齐的接点

Chat 已有管理端 `/api/messages` 的稳定列表游标、作者/时间过滤和前后定位，`/api/search` 已有关键词搜索但没有续页游标。独立服务候选 `/internal/evidence/read` 只能精确定位及每侧最多十条邻读，明确不保证完整、也未校验当前 Core 修订或 Memory 删除限制。Companion 当前仍报告 `chat_audit not_integrated`。因此先把现查询能力服务化并补稳定搜索分页，再接真实工具；不能直接把管理凭据或管理端响应交给 BOT。

Platform 已有“用户→群画像”页面，继续在该详情里增加历史、互动、话题和热度视图。Memory 已有多人整理的 topic、逐人覆盖、summary refs 及提交回执；增加同范围的只读投影即可，网页不直接读取内部任务表或私有 ledger JSON。现角色—人物好感账本继续负责 BOT 与用户的关系，群内 person↔person 互动不写入该账本。

BOT 原有 Life、Reading、Activities、RuntimeExecution、日记、主动表达和 Knowledge 内容授权都可复用。用户指定的《调研天枢 Bot 主动生活能力》要求的是“实际接触内容→产生理解与感受→形成后天兴趣与观点→影响日后计划和表达”，不是保存 BOT 的聊天复述。AL01/07 候选不能冒称 AL02–04 已集成。

两处真实缺口要先处理：Reading 的现 Life 事件仍可标为 fictional；activity-result 的 completed 只表示步骤处理结束。只有真实阅读覆盖、工具结果或发送回执支持的内容，才能记为对应亲历/完成。不能将这些现有标记批量翻为真实，也不能凭模型说“做完了”生成执行证明。

## 共用的数据约定

- 每次查询和可视化限定当前真实角色、账号可见范围及群/私聊。Chat 的 robot/account、原生 room 和 Memory 的 person/conversation 映射保留；同名、同 room_id 或同正文不能合人。跨账号只有可信身份映射才合节点，私聊不会因“同一个人”流入群图。
- 历史原文作为带作者、时间、locator/hash 和覆盖说明的证据；读取前仍核当前权限、修订/撤回与 Memory suppression。自然遗忘后可明确查档案；显式遗忘的内容不能借旧档案、旧 BOT 回复、日记或画像自动复活。独立聊天审计留存与 BOT 当前可用证据分开。
- 同一真实物理消息按现身份及版本去重，前台/旁听双入口不双计。BOT 流式分段先归为一次回复；reply 与 @ 指标可分列，合成总边时同一事件不重复相加。
- topics 的人物引用不证明每个人都同意或参与了共同经历。逐人的 memory refs、covered members 和原文归属仍保留；未整理、空结果、失效段都显示实际覆盖，不用 job 数冒充语义正确。
- Chat 原文与程序统计由 Chat 拥有；Memory 的话题/画像投影由 Memory 拥有；Platform 只组合展示。派生数据可重建，不成为第二份聊天原文或整理完成账本。

## 群图、点云和热度怎么做

首版默认选一个群、最近七天，可切换24小时、7天、30天及自定义区间；内部时间使用 UTC，界面明确本地时区。7天按小时、30天按天聚合，切桶不改变总量。页面并列显示原文覆盖、整理进度和待办，不等待整理队列全部排空才可使用。

关系图节点为真实人物、未关联账号或独立 BOT 类型；边先保存明确 reply/@ 次数、活跃天数和可追溯引用。首版不生成一个通用亲密分。同群共现只能列为共话题线索，不能造直接互动。若后续需要“关系较好”等描述，复用已有上下文整理结果，显示支持段及推测性质，不固定新增一次关系判断模型。

话题图先使用已提交段的 topic↔person↔summary 引用。topic_id 在段内有效，跨段默认各自保留；已有可复用向量时再做可解释的相似聚类。没有向量就先按原话题条目显示，不为画图调用新 embedding 或重整全库。

点云在浏览器内用现前端和 SVG/Canvas 布局。人物大小可对应活跃天数，话题大小可对应实际覆盖人数/有效段数，颜色与大小都有明确图例。建议初屏最多100节点、300边，超过后搜索或展开，并显示截取范围；显示预算不能改变后台真实统计或把未展示关系当不存在。首版不另外引入三维引擎，后续确有阅读收益再扩展同一视图。

热度至少分别提供消息数、去重活跃作者数、回复/@数及已整理话题覆盖；话题热度的分母只含已整理范围。查询与时间桶复用 Chat 现表和索引。Chat 目前没有跨产品完整变更流，旧时间的晚导入、修订和删除不能仅靠 sent_at 水位捕获；首版对选定窗口有界重算，规模确有压力再在所属库加可重建聚合，届时补真实变更键，不另起采集队列。

退群或撤权后，后续读取按现范围失效处理，旧游标和缓存不保留访问权。某人退群不自动抹去原合法历史，也不从历史发言推断仍在群。显式删除则移除其有效贡献或重算受影响桶；账号解绑/改绑不能把历史自动挪给新人物。

## BOT 自身记忆接入

沿既有 AL 队列推进，保持独立 actor 归属：

1. 原阅读、活动或发送的事实事务写稳定 source/outbox 引用，后台持久交付。来源由真实 owner 核实，重复交付沿原 receipt 恢复；unknown 动作不能靠重新执行来补记忆。
2. 在 Memory 产品内接独立 actor 存储/逻辑 schema，复用 StorageRuntime 和现有来源、回执、索引及失效机制，不复制用户 Store 全套 DDL。BOT 内部整理不推进用户 source_revision，actor 故障不迫使用户域回滚。
3. 先闭合一个真实网页/现有资料的阅读：读到哪里、理解了什么、有哪些疑问，再归纳认识、观点、后天偏好。已有阅读模型步骤可以顺带产出有据理解，不固定追加复述或裁判模型。自我画像、阶段自传和兴趣概况只是可重建投影。
4. AL01 候选当前只有 episode/receipt/check/withdraw 等能力；AL04 实施前需在同一候选命名空间补最小派生、查询和概况语义，再绑定真实 loader，不能暗扩用户 memory-context/v2。
5. 用户记忆、自身记忆、当前活动状态及外部原文按需要分别召回并带 owner/性质/来源。用户问自己的过去不强依赖 actor 域；问 BOT 近况才取她的真实经历。日记继续属于表达，不反过来充当经历证明。
6. 生活后台沿 AL05 处理既有前台模型槽误用、长步骤和多角色公平，复用小阶段/前台优先方式；不建立第二个全局调度框架。暂停或离线期间不伪造生活进度。

先做“实读→有源认识→后续交流/日记→次日继续”的最小闭环；账号发现、媒体覆盖、群主动参与、评论/点赞能力继续复用 AL07–18 的原任务，不复制新名单。私聊共同经历仍受原受众限制，actor_only 不能解释成可以公开。

## 完整功能块与顺序

| 顺序 | 完整功能块 | 依赖与完成标准 |
| --- | --- | --- |
| 0 | 当前记忆核心发布验收 | 单独记录实际源码、合同、迁移、备份和实机结果，不混入扩展实现 |
| 1 | Chat 授权历史查询与真实只读工具 | 原搜索/列表稳定分页、精确取文与来源/删除约束接通；真 Chat→Companion 联合验证后才去掉 not_integrated |
| 2 | 群互动与热度 | Chat 程序聚合＋原群画像页；多账号去重、时间桶、晚导入/删除重算及撤权正确，默认新增模型调用0 |
| 3 | 群话题投影与点云 | Memory 现段回执的有界只读投影＋Platform 同页布局；人物、话题与覆盖不串，刷新图不触发重新整理 |
| 4 | AL01 对齐、AL02/03 薄纵切 | 独立 actor 域、真实 source/actor 核验、单一实读事件到经历的幂等落账/读取/遗忘；不依赖完整外站账号能力 |
| 5 | AL04/05 与 AL06/10/13 最小闭环 | 有源认识/兴趣、自我检索、生活后台公平，实际用于一次后续对话/日记及次日计划 |
| 6 | 其余 AL 候选与联合实机 | 按原18项队列依赖回收；不是本次启动授权，不自动恢复已完成或中断任务 |

块1与actor候选的合同梳理可并行；同产品实现仍单写。块3依赖块2的实际群范围与统计接口，块5承接块4。每个完整块稳定后集中验证，不逐小改动全量重跑。

## 成本与验收

历史工具默认取一页，沿现列表默认50/最多200及精确邻读每侧10、总128KiB的有界读取方式；搜索翻页补稳定 keyset 游标，不无限循环翻页。普通回复仍用 Memory，需要原话、日期或精确历史证据时再查 Chat，不固定给每轮增加一次全历史查询。

群互动、热度、点云首版新增模型调用目标为0。话题复用现分段结果，未覆盖就显示未覆盖。确需历史回填时沿现队列低优先分批处理。BOT 自身记忆按实际新增内容/重要变化整理，复用既有阅读步骤；实施阶段先估算并记录实际调用，再使用批准预算。本次规划新增模型调用0，仍沿现累计上限18000，不自动追加。

沿现测试方式覆盖真实风险：跨账号同 ID、同名不同人、群私隔离、同秒翻页、晚导入、重复/丢回执、来源修订与删除、不完整覆盖、角色与用户相反偏好、阅读片段与全片区分、步骤结束与目标完成区分、重启恢复及真实 PG。查看实际模型输入与最终正文，不能只核 ID、数量和HTTP200。普通修辞不追满分，主体、主要含义、完成状态、受众及来源必须可靠。
