# PG短查询、来源同步与写入实测（2026-10-21，TS264/265/269）

本批已完成隔离开发与实测；生产仍保持Q15。数据来自同一NAS/SSD、相同基础镜像的合成工作负载。PG相对本轮旧版的改善、PG与优化后SQLite的差距、SQLite自身前后变化分别列出，不能合成一个全系统提速比例。

完整来源同步＋关键词PG从494.52降到270.66 ms，耗时缩短45.27%，相对优化后SQLite为0.983倍。短field从5.16降到4.48 ms，但仍为SQLite的1.532倍；本轮没有让所有PG场景持平SQLite。

PG新/SQ新低于1表示该场景PG更快。没有把未持平、变慢或长尾样本删除；来源完整同步的响应是公开合成owner数据，执行原生SourceAuthority和全部校验，未计真实远端TLS/上游或模型延迟。普通完整组与完整SourceAuthority是两种明确不同的负载。

原两suite共24次、4,560采样；独立SourceAuthority写研究另12次、720采样，均三轮交替四组合、每次只运行一个有界客户端。CPU affinity 0–7、shares128、每客户端512MiB，相同镜像基础和依赖闭包。source写种子300组/30源，纯提交及全流程各30次，写后365组；全流程另5次真实预热。不同研究的分母分别保留。

SQLite另做三block、四case各20对，合计240对/480次正式真实写入；另24对/48次预热不混入。每一对从相同物理DB、guard和合成状态复制，hash及fsync确认；两侧内部绝对路径、namespace、pool4和schema相同，先后顺序各半。每次原生提交后核对增长、ledger、guard变化，关闭重开、quick_check/FK与完整组内容签名；使用过的副本不能重用。没有用rollback或幂等命中代替写入。

本次配对未发现SQLite写入稳定退步；该结论限定于表中四种工作负载。

区间按block内完整pair重采样3,000次，只描述本次合成负载。普通顺序测试有明显I/O长尾，不能仅凭一次先后运行认定SQLite写入退步或全域零退步。配对的全部wall/CPU样本、byte证明、提交与重开结果均保留；不能外推所有并发、自动事实或远端来源工作负载。

实现复用原Store、SourceAuthority、Contracts、workflow、FactSnapshot和召回完整性规则。PG每次checkout仍重新设置三个会话值；原三条设置已经pipeline，本次合为单条参数化语句，减少协议命令和执行开销。来源快照原先逐条等待的独立SELECT改为原事务内批发，全部确认后才交出结果，锁/CAS后新语句、首次DML前的边界保持。[psycopg官方pipeline说明](https://www.psycopg.org/psycopg3/docs/advanced/pipeline.html)解释了减少往返等待的原理；服务端仍按语句顺序执行。

短field/item仅把组/lineage元数据合并，来源全部准入后才批读正文；超过512组不截断，回原分批路径，原生EXPLAIN确认额外lineage子计划没有执行。事实marker未启用不访问事实表；失效projection对应坏事实JSON不提前解码。PG bump将原7条SQL改为3条同事务读取/UPSERT RETURNING/历史记录，SQLite维持原SQL。索引准备只合并同一次调用内重复读取，下一调用重新读当前事实。

通用合同准备只缓存不可变、本地、静态schema的解析目标，registry更换即重建；每次仍完整检查当前文档。使用官方[validator扩展](https://python-jsonschema.readthedocs.io/en/stable/creating/)和[referencing公开API](https://referencing.readthedocs.io/en/stable/api/)，动态/歧义/外部/非2020方言与解析失败保留官方路径，没有复用权限或来源判定。两个后端都出现来源CPU改善，表明这批收益是SQL往返与通用合同准备共同作用，不能全部归因于PG。

未采用全局自动prepared：原生微实验虽有收益，仍保留prepare=False、setup-only pipeline、Row和executemany合同。[PG17 PREPARE文档](https://www.postgresql.org/docs/17/sql-prepare.html)说明计划与会话/search_path的关系；本产品存在临时关系与未限定表名，不在本批扩大兼容语义。微实验只指导设计，不计入正式应用数据。

权限、完整组、撤回、来源revision/epoch、全域receipt冲突、NULL alias、CAS、六次新鲜来源revision调用、锁后独立快照、guard-before-commit及持久性保持。SQLite仍WAL/FULL，PG fsync、synchronous_commit、full_page_writes保持开启；未调低持久性换取速度。

验证：共享97通过（其中15项为显式PG节点）；产品相关249通过＝102原生PG＋147本地/替身。SQLite完整仅跑一次：1,624通过、103跳过、1项已在e1复现的account-403预期与实际400差异。产品原生首轮248通过/1项新测试夹具失败，原因是seed隐式事务被首轮rollback撤销；测试先提交seed后仅补跑失败节点1通过，运行源码不变。原失败、修复和XML hash都保留。全局workspace check受既有TS016 dubious ownership影响，没有修改全局safe.directory，也未称该检查通过。
