## 必须实现

1. 统一 QQ ID 规范化且拒布尔、浮点、Unicode伪数字、空值/缺失/冲突等。可信 OneBot user_id 唯一锚定发送者；self_id、实例和群号保留来源范围。同 QQ 经多 BOT/群私保持一个平台档案，不同 QQ 同昵称不合并。审核 NoneBot/AstrBot 两条已支持通道，不能只保护其中之一；未实测宿主如实标注。
2. 独立用户档案沿用现有 person_id，不制造第二套人物库；记录平台账号和可用称呼，昵称/群名片按来源/群范围展示，不覆盖身份。后台能查看 QQ 档案和账号；对新观察账号的登记必须走正式授权/幂等路径，不绕 Memory SourceAuthority，不因建档启用回复。缺少显示名时正常回退，实际字段来源核对后接线。
3. 受现有管理员登录保护的 QQ 管理身份设置：列表、新增/撤销、备注、适用角色/会话/受控能力范围，持久化、重启恢复、版本冲突保护及去敏审计。普通网页/聊天/服务来源不能写该表，聊天中 admin 字段不得赋权。默认空授权、不自动把真实测试 QQ 或第一个说话的人设管理员。QQ群角色和后台账号不隐式等同。沿用现有页面风格，普通用户可理解的文案，不展示令牌/内部实现噪音。
4. 可验证的服务端身份投影：框架生成本轮发起人、每条作者、当前权限版本与角色/受众；人格只影响表达。固定规则和可信元数据不混入昵称等自由文本。发送给供应商的真实 messages 必须证明身份分离和每条来源；模型无凭据，不能改写请求主体/回复目标。管理员识别本身不得额外授予原系统不支持的工具能力。
5. 敏感管理操作保持后台入口；模型提出的记忆/能力请求需走既有真实授权链。明确当前实际可执行入口及每处防护，不能虚构通用工具网关。读资料前按角色/群私/来源过滤；不能将私人材料送入群聊模型后依赖输出过滤。管理员消息后普通成员不继承权限，多人合并批次的操作发起者必须确定。
6. 撤销/角色停用/策略变化在生成期间发生时，实际未提交操作及发送前重新验证，缓存包含相应版本。服务不可用不得使用过期管理员权限；结果不明确保持原 unknown 不重发语义。不要把在途授权语义只实现到新请求。
7. 历史、摘要、记忆材料均带来源，不得把“自称管理员”提升成权威身份；模型没有写身份/授权配置的路径。模型输出走普通文本发送，不二次解释 CQ 指令/伪造 @全体。未支持的引用、转发/媒体继续明确 unsupported，不能静默丢段后当完整授权操作。
8. 平台独立数据归属保留，未来关联位置有说明；本轮不实现 TG/Hermes 身份适配、跨平台关联写接口、后台合并档案或真实权限预置。
