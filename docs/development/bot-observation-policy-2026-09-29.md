# 机器人观察建档与回复策略

状态：2026-09-29 设计与实现任务；未实现、未部署。覆盖旧机器人任务卡中“只有逐会话、逐作者白名单才能接入”的产品限制，不放宽其他产品身份与来源边界。

## 用户要求与解释

用户要求参考“我会永远陪着你”：默认监控机器人收到的所有群聊和私聊、自动建档，默认只观察不搭话；可选择仅观察、白名单、黑名单，群聊/私聊独立设置。

本轮暂按“名单控制回复，观察默认覆盖所有收到的会话”解释，已向用户发出异步澄清。若用户另有回复，总控同步后更新。群聊允许回复时默认仅直接 @机器人触发，私聊允许回复时正常响应；这项为设计默认值，不是用户已确认的原话。主动搭话保持关闭。

## 参考核查

来源：https://github.com/menglimi/astrbot_plugin_private_companion ，核查固定提交 2313fd12e1bd9b72f6db9aca17cde4359102341e；本地只读参考 .runtime/reference-private-companion-20260929。

- main.py 的群观察投影含 observation_only=true、enabled=false、private_companion_enabled=false、proactive_private_enabled=false。建档不等于开通回复或主动联系。
- core_store.py 的 _group_allowed_by_access_mode 在观察准入处使用名单。本项目按用户要求重新定义语义，不直接复制参考插件整套行为或源码。

## 产品行为

以已在网页连接并确认真实在线账号的适配器账号为边界，不扫描未接入账号或抓取历史消息。首次接入不再强制提供具体会话、允许作者或回复角色才能保存；观察无需模型或回复角色即可工作。

群聊和私聊各有独立设置：观察开关（默认开）、回复模式 observe_only / whitelist / blacklist、相应会话名单、默认回复角色。另有明确的停止观察选项，不能把回复黑名单误称“不收集”。群名单填群号，私聊名单填对方账号，不再要求逐个登记普通群成员才可回复；精确成员禁答作为独立高级设置保留。

| 模式 | 观察与建档 | 回复 |
| --- | --- | --- |
| 仅观察（默认） | 开启观察的账号中所有新收到会话 | 永不生成或发送回复，@也不回复 |
| 白名单 | 同上 | 仅名单内会话允许触发；空名单全不回复 |
| 黑名单 | 同上 | 除名单内会话外允许触发；空名单表示全部会话可触发，保存时清楚显示效果 |

回复许可与触发条件分离；允许回复不等于每条群消息都回复。观察历史不能在切换模式后补发回复。旧连接的精确范围不能被升级静默放大；旧实例保持原范围，显式启用账号级新策略后才扩大观察。

网页沿用既有设置子页面与样式，在机器人页内分“连接与账号 / 群聊策略 / 私聊策略 / 已发现会话”。自动展示观察到的群、私聊对象、成员、最近观察时间和计数、实际归档状态与失败原因，并能从会话条目加入回复名单，不要求手改配置文件。只读预览明确说明当前哪些会话会观察、哪些可回复、触发方式。保存并读回真实服务状态，不能只有表单没有后端效果。

## 架构与边界

1. 新增真正独立的观察入站链：宿主接收 -> 规范化 -> 持久队列 -> 平台/陪伴观察接收 -> 来源授权与档案/记忆存储。禁止把观察消息送入现有聊天 dispatch 再靠空回复补救；观察不得创建生成任务、调用聊天模型、创建发送意图或自动开启主动联系。
2. 宿主同时采集真实 conversation/author/self_id/event_id/time 与 bot mention 标记。NoneBot 观察不能 block 其他插件；只有获准并成功接管的回复消息才占回复责任。AstrBot 同样区分观察和回复阻断；“天枢不回复”不保证其他宿主插件不回复，界面要准确标示边界。
3. 档案应可持久读取，区分会话、参与人及来源消息；按平台/实例/机器人账号/会话类型/会话ID/发言人隔离。群观察不能直接变成私聊共同经历；显示名称不是跨账号合并身份的证据。长期记忆复用现有 Memory 来源与访问合同，不能读写其他产品数据库。先查可复用的来源入库路径，无法适配则提出最小合同扩展并真实联合验证，不能用孤立计数表宣称记忆链已打通。
4. 建档与事实索引无需模型；可选语义画像提炼另受预算与配置控制，不能收到每条消息就调用模型。非文本事件至少明确支持范围与观测状态；不能声称已归档媒体正文或自动下载附件。排除机器人自身回流，真实SDK身份不可从页面任意伪造。
5. 策略为单一可测试决策模块，宿主、平台的判定与发送前重查一致。版本/幂等键持久，旧队列只观察、不因新许可升级回复；降级为仅观察/禁用后撤销未发送回复。发送仍有独立持久意图、真实回执、unknown不重发。
6. v1合同已部署，不修改原语义让老端误判。以显式能力协商或独立v2扩展实现；老插件不能假装支持全量观察。协议失败默认不回复，保留可恢复观察队列，界面显示降级。
7. 队列、档案查询分页、保留期与容量都必须有界；过载显示积压/失败而非成功吞掉。业务归档与运行日志分开；运行日志记录关联ID、策略原因、计数，不输出密钥和聊天正文。现有全量运行日志要求保留。

## 开发与验收

完整功能块交可见 Sol/xhigh 新任务开发，主协调者负责审查集成。独立产品 worktree，禁止直接修改 projects 集成检出、小屋资产或不相关产品。任务拥有 Platform、Companion（含 NoneBot/AstrBot 插件）的本轮代码；Memory 若确需扩展，先提交具体合同提案给总控，避免自行伪造已发布来源事件。根合同只能先交候选草案，不自行发布或覆盖旧包。

必验：群私独立三模式与空名单；新群/新私聊自动建档；仅观察即使被@也无模型调用/无发送台账；同ID跨账号跨群不串档；默认观察不依赖模型；两宿主真实框架钩子；观察不阻断其他插件；重复/断线/重启不丢档不重复；旧观察切换可回复不补发；策略收紧在排队及发送前生效；旧v1不回归；管理员认证/CSRF；网页真实API群私分别保存与会话名单操作。合成服务通过不称NAS或QQ收发通过。

本轮研发不向真实QQ群或私聊发送消息，不擅自变更线上策略或其他宿主配置；部署前总控检查实际补丁、迁移/备份方案及验收证据。默认仅观察的实际部署可按用户当前授权推进，真实回复测试对象仍须由用户指定。

## 2026-09-29 Memory 扩展放行

开发核查：现有 turn-commits 只能承接真实封账轮次，source-sync 的逐角色 admission 不能直接表达无回复角色的观察授权。总控批准本任务单一实现者在独立 Memory worktree 扩展观察来源 ledger、档案与受权读取，禁止伪造 turn_committed。产品目录为 C:/YOKI/Codex/bot-observation-worktrees/platform、companion、memory；Memory 基线由开发先核实回报。

新合同在开发者根 worktree 的 contracts/observation-source/candidate-v1 准备，首版1.0.0；schema、manifest、样例和三方能力/调用身份矩阵一并提交总控审查，不自行发布或修改现有合同。内部URL可采用 /internal/v2/memory/observations，合同版本与URL版本分开明确。

观察来源由 Platform 为管理员已登记的真实适配器账号签发；Companion 持久 inbox 后由 Memory 持久归档。不要求回复角色但仍须独立观察授权、来源归属与范围版本。读取、停止观察、撤销/删除、积压重放均需明确语义；Memory未落库仅标待归档。必须真实贯通档案读取，不以独立计数替代记忆归档。所有实现仍限定本地研发与合成测试，NAS及真实回复未变更。
