## 领域权威和共同材料合同

| 领域 | 唯一职责 | 消费约束 |
|---|---|---|
| Sources 与 Identity | 原件、来源可用性、授权、真实人物和群主体 | 历史也服从当前遗忘与权限；显示名或模型输出不能授予身份 |
| Memory | 事实、经历、事项、不可变反思原件、事实修订、时间查询、群词义 | 可证明历史记录存在，不决定 Companion 当前习惯是否仍生效 |
| Companion | 习惯/兴趣当前投影、明确反馈、规则修订、表达样例 | 历史反思不是新的独立支持；撤回和冻结必须影响运行消费 |
| Conversation 与 Life | 当前请求理解、用途、完整单元预算、实际取材冻结及未发送结果处理 | 不能直接读写另一领域的私表，不能把模型成功当作动作成功 |
| Models 与原队列 | 请求身份、物理尝试、资源准入、结果/unknown 与实际 usage | 等待和执行计时分离；不复制原未知请求或制造回执 |

公共类型只承担小型引用和记录，不替代领域服务。ML-01 只固定跨域必需语义；Coverage、Support 等内容仍在所属领域演进，不要求每类材料先实现同一套大对象或新表：

- `MaterialRef`：domain、kind、stable_id、revision、semantic_role、origin_ref、source_refs。用于身份、去重和版本核对。
- `BehaviorBinding`：rule_id/revision、原 proposal_id、反思类型、preference_kind、状态、范围和有效期。当前状态只有 Companion 可写。
- `SelectionRecord`：原 request_id/round/attempt_id、purpose、材料版本、是否最终装入、原因、估计 token 和冻结时间。只保存有界候选和最终材料的引用，保存在已有请求或 turn 附属数据中，不复制正文或全部候选库；它证明实际取材，不证明模型遵守或效果因果。
- `CoverageAssessment`：原件可用性、必要上下文、候选范围、逐目标处理、提交、索引及评估依据。与原缺项共存。
- `SupportProvenance`：实际支持子集、完整生成依赖、独立事件、反例与反馈。不同集合不能互相替代。

Memory 存储模块不增加对 Companion 私表的依赖。Conversation、Life 和原生工具适配层通过领域端口批量判断行为资格；如需候选提示，属于可重建投影而非第二份活动规则权威。当前行为读取只查当前规则状态与已有来源，不回调完整 Memory 投影，避免递归依赖。

### 接口候选

正式实现由 ML-01 固定以下语义，方法名可沿用现有端口：

- Companion 批量状态读取接收 context、purpose 与 rule_id/expected_revision 列表，逐项返回当前 revision/state、结构化对象/范围/用途/有效期是否匹配，以及明确原因。复杂自然语言条件继续作为材料保留，不能伪称已由程序精确判断。
- Memory 证据单元保留 reflection_kind、origin_ref 与可证明的 behavior_ref；不能据“来源仍可读”补造当前行为许可。普通行为消费与历史依据读取由调用方明确区分。
- Conversation/Life 的选择器接收同一类完整贡献，冻结前调用各领域批量版本复检；最终生成 SelectionRecord。一个引用检查失败只舍弃该可选单元，必要依赖缺失则如实返回诊断。
- 原生 Memory 工具适配层使用同一行为解释接口，History/source trace 可以给出旧依据，但不得把它转成现行规则。运行装配从上层注入端口，不让 Memory 存储代码反向依赖 Companion。
- 当前规则在请求冻结后变化时，批量状态端口区分实质内容/适用性变化与仅新增支持/统计。只有明确影响本请求实际使用规则的失效，才沿既有未提交控制路径处理；原请求不重写，已经提交或未知的外部效果继续由原回执描述。

## 写入与学习链路

### 有效输入和唯一提案身份

不可用附件保留原事件身份和缺项。文字、引用等可用部分继续接收；纯不可用附件也应保存“收到但未理解”的状态。接收恢复沿原幂等入口与回复所有权，不重新发出一条伪造历史消息。

现有模型协议已经按 subject 分组，已有编译器负责 op_id、CAS 和覆盖字段。第二版继续使用目标内的 n1/n2 局部别名，由程序按冻结 subject 顺序、目标内操作顺序与输出槽位映射为全批唯一引用，再交原提交器产生正式对象身份。两个目标各有一个 n1 合法；同一目标两次声明 n1 仍有歧义，必须明确诊断，不能按顺序猜改。

同目标引用仅解析本组；跨目标新对象使用显式 subject_id/local_ref，原冻结 rN 引用保持。Claim、Matter、link 与 transition successor 共用局部映射，先收集声明再解析引用，并复用现有操作依赖/类型校验。无需新建通用图编译器或强迫模型改用一套操作坐标语言。运行记录只证实 duplicate_create，尚未证明每个实例都是跨目标重名，因此不能承诺消除所有模型格式错误。

这只能消除格式身份碰撞，不能自动证明两个事实是否相同。来源、人物归属、完整目标覆盖、read_set、CAS 和严格领域验证保持。旧冻结请求按原协议观察/恢复；新默认请求只使用一套协议。失败提案不通过猜改旧输出强行提交。

### 共享材料和可理解的覆盖

分区继续按角色、会话和真实授权域划分，不按发言人拆成重复调用。消息按来源版本和原定位去重；引用/回复/事项关系帮助选择上下文，但无法可靠确定的语义关联仍标为未知。

模型视图保留人物、原作者、否定、条件、时间、实际结果与关系双方。完整来源闭包、权限、修订、游标和机械诊断由程序与冻结请求映射持有。当前已有紧凑索引/重排文本及关系端点去重，不作为本批新增成果重复实现。

输入和输出容量联合决定材料范围。输出容纳不了时按完整消息与依赖范围分段，保留每个目标的 changed/no_change/unresolved；不按每人固定条数省内容，不在截断后部分提交。200000 是上限，不新增一个更小的硬门槛，也不要求每次填满。

覆盖报告至少区分：

| 项目 | 典型状态 | 处理 |
|---|---|---|
| 原件可用性 | text available、media unavailable、revoked、unknown | 可用部分进入，缺原件不编造内容 |
| 必要上下文 | available、required missing、unknown | 有界补查或保留未决 |
| 候选范围 | ranked bounded、optional omitted、unknown | 说明范围有限，不能冒称所有旧记忆已比较 |
| 逐目标语义 | changed、no_change、unresolved | 每个冻结目标明确覆盖 |
| 提交与索引 | applied/failed；ready/pending/unavailable | 模型成功、领域成功与可检索分别记录 |

没有声明依赖不等于已证明省略内容无关。旧 completed_with_missing 不能靠重新分类变完整，也不以降低该比例作为效果验收。

### 当前习惯和明确纠正

每条习惯使用稳定 rule_id 和 revision，多次有依据的新 proposal 可以修订同一规则；原 Reflection/Proposal 继续保留。内容含义分成当次要求、持续明确偏好和推断习惯，分别保存对象、用途、范围及已知有效期。

当前授权用户的明确要求可覆盖对应范围的旧推断，但不改变固定人格、工具权限或其他群成员的控制权。临时“今天少开玩笑”不永久化；持续“以后别这么称呼我”不能因话题改变漏掉。不能仅按最后一句话全局覆盖，也不把引用文本当作授权命令。

明确反馈通过原 request_id/CAS 命令及原对话身份处理。界面操作和已经解析的原生命令在原命令事务中调整对应规则，不等待 Growth。自然语言纠正先作为当前请求被遵守，再沿原真实事件整理并持久修订；不能用关键词或“最新一句话”直接判定永久偏好已经写入。可由取材清单定位原规则，但取材本身不证明反馈一定针对该规则；归属不明时保留未决，不全局误删。当前已遵守、长期已提交、仍待整理分别表达，常规学习不新增逐条人工批准。

独立支持使用真实事件身份去重。模型 support_ids 是支持子集，整批 episode_ids/原件闭包仍是生成依赖；机器人自己的复述、日记转写、样例重复使用、没有投诉，都不是新增正反馈。旧支持子集只有从原结果可靠恢复时才补索引，否则保持未知。

已解析为同一规则的重述服从已有撤回约束，不能换 ID 自动恢复；无法证明同一性的语义近似继续保留分歧，不建立全局词面黑名单。

## 读取与实际消费链路

### 先理解当前对话

当前材料选择保留同一预算，采用有依据的顺序：

1. 固定人格/工具规则、当前输入和可确定的回复、引用、工具依赖。
2. 本轮问题所需事实与词义、适用于当前对象/范围的明确表达要求。
3. 相关未结事项、一般事实与有范围的推断习惯。
4. 确实有帮助的表达样例。

这是按用途形成的相对关系，不是每类固定比例。必要对话和核心证据不能被可选样例挤掉。自然语言复杂条件不伪装成程序已严格判定；无法可靠识别的依赖应明确范围有限。

管理页面继续稳定分页。运行取材在限量前应用 actor、授权范围、active、用途与对象过滤，候选被丢弃后有界补位；不能继续使用按 ID 前 40 项作为运行时完整集合。检索相关性保持到装配，不被固定类别优先级无条件覆盖。

运行读取直接取得适用规则及必要来源，不再调用成长管理 view 的审核/重试统计、Memory style_view 和其他无关投影。每条规则一个引用/版本/来源单元；只有有明确依赖的内容作为不可拆的一组。保持批读，避免从一个大包改成逐条 SQL。

近期消息在转换成模型消息前保留 message/turn/event、来源和回复关系，按完整单元选择后再汇总直接来源。当前 conversation_provenance 把近期候选全部先列为 mandatory 来源的做法应收敛。只有从未参与模型调用或衍生计算且最终未采用的候选，才能排除其直接依赖；实际使用的摘要、反思、重排结果等仍保留原完整生成闭包和失效约束。不能从模型未标 support 的材料推断它未被读取。

本轮已接收消息不必等待后台安静期或后续整理才进入理解。直接复用现有近期会话/原件与已观察 Episode，按真实来源关系去重；明确纠正优先于对应旧推断，普通更新、传闻与不明冲突保留各自时态。这里不新建短期事实库，也不承诺所有自然语言纠正即时写入长期状态。

### 历史反思与当前行为的一致性

普通取材中的 style/interest 反思要保留类型和行为引用。当前行为由 Companion 判断，不能仅因原来源仍可读便重新生效。同源、同用途的反思与规则只选择一次；如果问题本身需要比较历史与当前，保留两者关联，不当成两份独立支持。

适用入口包括正常聊天、Life 规划、Growth/日记取材、memory.search 等原生工具结果，以及 source trace 后的历史解释。历史追问可以返回已撤回原文，必须明确它是历史依据而非当前表达要求。不能只改成长页面或只改 ContextAssembler 的一条调用。

最终请求冻结前批量复核来源、规则状态及 revision。冻结后按实际已选 rule_id 和语义内容判断兼容性：仅新增支持、管理统计、无关对象/用途的变化不取消回复；撤回、明确纠正或适用范围实质失效才影响相应未提交结果。可沿既有修订内容/原因或确定性语义指纹判断，不新增全局状态版本服务。

检查位置落在 Conversation 结果处理、ExpressionRenderer.release 及 channels.deliver 的既有未提交检查处，覆盖等待渲染和发送队列期间的变化。由上层注入领域读取端口，发送模块不查询 Companion 私表。每次只批量核对实际跨越边界的相关身份，不加轮询或判断模型。一般可选习惯状态读取失败不等于已确认撤回；当前明确禁止性要求无法复核时按未决处理。

尚未提交且确定失效的表达沿原取消回执记录原因；已提交、已开始多段投递或 unknown 结果继续原对账，不能宣称全未发送或自动补发。Life 后续纯规划使用新状态，原 Action/Receipt 保留。

### 低开销检索

延续同一 MemoryQueryPlan 和候选存储。可靠的 subject/matter/time 信息先做结构过滤，不可靠推断回到通用混合召回。中文优先整词、短语与姓名，并保留受控的单字回退。

词法和向量在现有连接池额度内并行独立阶段，继续稳定批读、批量来源证明、ANN 不足补位、MMR 和最终复检。失败支路不抹掉已证明有效的结果。普通精准单对象或 list 查询避免无益重排，歧义和接近候选再按需执行。选用多少候选由相关场景对照决定，不把任意阈值当作质量保证。

先做请求内计算复用及同语义索引向量复用。跨请求成功查询向量缓存仅在重复负载确证收益后采用，容量/TTL 有界并绑定 profile 和授权/来源上下文；最终答案和权限判定不缓存。没有收益时，完成“请求内消除重复”即可关闭该设计分支，不留下未完成的必需能力或新开关。

生成输入 200000、向量阶段 2 秒及嵌入/重排 30 秒执行窗口保持；排队不消耗执行时间。不通过提前截断所有远端请求制造 unknown 来取得快响应，也不默认更换模型、向量库或全局数据库配置。

## 按需个性化能力

表达样例用真实 turn、回复/引用和合并关系建立，不能采用相邻消息配对或固定 50/100 字切片。样例归 Companion，只保存规则版本与原文引用。发生、生成、发送、送达和明确反馈分别表达；历史说法不把人名、地点、数字和事实带入当前世界。

优先提供清楚的适用规则，具体措辞确有帮助时才附样例。没有合适样例正常回复。既有后台 Growth 批次负责候选形成，不在前台增加每轮评价模型；样例重复使用不能自行强化支持。

群词义复用 Memory Claim 修订和 Identity 的真实 group:<conversation_id> 主体。language.term_meaning 保存词项、解释、说话者、assertion、范围及歧义；一个人这样说不证明群体共识，更不构成群体 self_confirmed。人物别名仍归 Identity。词义在原多人整理请求里生成，只为当前输入命中的词项提供有界解释，默认不主动复读黑话。

## 历史和存量修复

Episode 确实存在更新写者，新增语义版本快照；提取游标和处理状态变化不复制正文历史。Reflection 当前同 proposal_id 内容不可变，继续保留这一约束，取消上一版通用 Reflection 修订表建议。行为演进由 Companion 规则修订记录承担。

历史查询区分有效时间、记录时间及当前状态；迁移前不可还原历史不倒填。当前事实、未结事项、完成事项和旧修订只是在同一权威存储中按用途排序，不另建冷热事实库，不按固定天数硬删除。

存量补偿复用原批次、队列与唯一整理 writer。稳定缺口身份绑定原 Episode/源版本、缺项语义及修复对象；算法版本属于某次尝试，不能因为升级算法就把已修复缺口变成新任务。计算前再次判断缺口是否仍存在，已修复或被新事实替代时记录原因并跳过。只有原件仍可用且有权读取的材料进入。

同缺口有运行/unknown 尝试时先观察原结果；确认可新尝试后才登记独立 attempt_id，全部费用和未知继续计量。幂等可以防止盲目重复提交，不能保证外部 unknown 绝不重复计费。补偿读取当前事实，旧材料不能自动覆盖较新变化；记录时间为本次补偿，有效时间依原件。

新输入优先，在已有队列与资源准入允许时按等待年龄有界推进补偿；不另改全局调度，也不让“新输入优先”变成存量永远不处理。功能包完成要求补偿机制可续跑、可对账，实际已修复范围和待原件/unknown/待处理范围另报；自然存量清零不是发布前提。不能从备份复活遗忘来源，也不能把临时不可达退休为永久缺失。

新增 Episode 快照、习惯修订和样例引用必须加入原来源失效/遗忘传播。原 failed/unknown、模型尝试、源 ID 和审计保留，补偿失败不通过清错误冒充成功。

## 验证和收益判断

复用当前 scripts/evaluation/memory_closure 及相关 Memory、Companion、上下文与页面用例。验证范围与这次实际改变相称，不新增全产品测试、双后端矩阵、固定样本量或 CI 门禁。

1. 确定性行为核对覆盖身份/状态、CAS、来源与撤回、真实引用、完整单元预算、协议身份和恢复。用隔离合成数据，不复制真实私人聊天入库。
2. 已知 24 故事只作回归，不再称盲保留集；新增保留故事按未覆盖行为选取，冻结后评阅。按同一故事及其改写/派生事件家族隔离，不能把近义改写分置回归和保留集；用于调参后即转为已知回归。结构化落库、最终请求和回答分别判断，原文补答与未决结果单列。
3. 对相同人格/模型/语料/授权/配置比较“当前实现与核心修正”；只对相应场景追加有无样例、词义、重排或缓存的对照，不跑全组合。
4. 评估归属、知识变化、条件偏好、历史时间、适当拒答、撤回后行为、不过度个性化及指代理解。按真实适用机会分别记录必要材料遗漏、无关个性化侵入和纠正生效；接收、当前消费、长期提交及索引就绪的时间分别报告。按低频参与者和错误类型看结果，不用总消息量稀释失败；适用场景比较有规则无样例和带样例，保留评分分歧及小样本局限。
5. 用原 Models 回执计入所有物理尝试、补查/纠正/重试、embedding/rerank；缓存与 reasoning 分列，不重复相加。缺计量/费用保持未知。冷/热查询、队列/执行、阶段及全量 p95 都报告，不能只展示最快子集。
6. 不预设“降本 20%”“8 秒内”或更低 completed_with_missing 比例为发布门禁。参数选择以相关场景质量保持且实际冗余、时延/用量改善为依据；不能以少记、误分完整或频繁制造 unknown 换漂亮数字。

需要的代表反例包括：前 40 条失效、第 41 条有效；撤回规则经 Memory 工具返回；当前明确要求与持续/临时偏好；同 kind 多版本；预算紧张的“刚才那个”；交叉发言/合并回复；词义跨群冲突；旧材料补偿与新事实冲突；来源撤回发生在选材后；缓存 profile/权限变化；机器人自用习惯不增加支持。第二版补充：仅新增支持不取消回复；渲染/发送等待期间撤回；未整理新消息与旧事实冲突；未采用候选来源变化；跨目标 n1 重名与目标内歧义；算法升级不重复修复已闭合缺口。以上按影响范围复用或补充必要用例，不强制重复整套验收。

本地实现通过、生产版本健康、真实外部行为、长期质量四种结果分别记录，不相互替代。真实模型对照、自然 QQ 观察和存量补算在后续相应授权范围内执行，本轮没有开展。

## 发布和回退方案

完整功能包收齐并通过受影响验证后，由当时明确的生产唯一写者串行发布。仅备份 Memory、Companion、请求附属数据等实际受影响域，保留配置、挂载、原件、模型回执和非目标服务。

发布读回实际版本、启动健康和受影响入口，单独核对新增规则/经历历史与覆盖诊断。存量补偿在新输入优先的原队列中后台续跑，不能为了收口一次全库重放或重发历史消息。

旧冻结请求继续由有限原协议读者观察。新请求只有新默认写入器。回退包必须识别新增协议并停止不兼容写入；不直接启动不认识新批次的旧镜像。回退代码/调度时不全库恢复旧状态以抹掉期间正当业务修订。已执行外部动作只保留原回执，不自动反向操作。
