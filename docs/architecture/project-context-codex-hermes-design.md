## 新架构保留共享上下文能力

天枢记忆同时服务陪伴、编码和其他已配置客户端。项目资料使用独立的项目视图，不把它们塞入陪伴人物画像，也不把用户私人聊天默认交给编码体。

| 内容 | 最终负责方 |
| --- | --- |
| 代码、需求文档、接口说明、项目规则与版本化决策 | 项目 Git / 登记的源文件；无 Git 时使用明确的文件快照与内容版本 |
| 项目登记、当前任务状态、工作目录、执行者及开发交接位置 | 天枢平台的项目工作台 |
| 项目知识索引、可追溯经验、相关资料选择、短上下文包 | 天枢记忆 |

## Codex 与 Hermes 怎样接入

Codex 使用 MCP 工具访问天枢。当前官方文档支持本地 STDIO 与远程 Streamable HTTP MCP；旧本地适配器提供了可复用起点。[Codex MCP 文档](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)

Hermes 分成两个按用途协作的入口：

- 项目文档搜索、精确片段读取、阶段记录与交接使用通用 MCP 工具。
- 确有需要的短记忆预取和完成回合反馈可以保留原生 MemoryProvider；不在 prefetch 中全量注入项目文档。

Hermes 当前官方文档支持本地和远程 MCP，也提供 prefetch、sync_turn 等 MemoryProvider 扩展点。两者可以承担不同职责，但实际安装版本和钩子频率需验证。[Hermes MCP](https://hermes-agent.nousresearch.com/docs/user-guide/features/mcp)；[MemoryProvider 接口](https://hermes-agent.nousresearch.com/docs/developer-guide/memory-provider-plugin)

新的公共工具应调用中立的上下文/项目能力，并按真实客户端身份配对。旧工具的 HTTP 路径和认证与 Codex 类型绑定，不能仅把同一份 Codex token 交给 Hermes 就宣称完成共享接入。可以复用传输、工具语义与版本读取代码，再发布兼容的接入层。

工具层可分别调用记忆服务与平台项目服务，按职责组合恢复包，不必另建一个庞大的工作流平台。连接和授权在已登记项目范围内配置一次，正常任务关联与阶段记录应尽量自动完成；旧版逐会话手工绑定和多阶段写入流程不作为新设计的默认体验。

## 接入不等于每轮自动读写

MCP 让工具可调用，并不保证客户端在每次任务开始、压缩或结束时自动执行它。Codex 可以通过短项目入口说明约定恢复和记录时机；要求可靠自动触发的部分，要使用实际可用的启动器、项目同步器或客户端生命周期接口，并做漏调用、退出和重试验证。

Codex 会读取适用的 AGENTS.md，适合保留稳定项目规则和简短入口指引；不能用它承载持续增长的全部项目记忆。[Codex 项目指引](https://learn.chatgpt.com/docs/agent-configuration/agents-md)

Hermes 的本地记忆和项目上下文文件有各自的加载方式，不能假定外部事实写入后会立即重写当前系统提示词。具体行为按安装版本核对，动态资料通过工具或受控预取读取。[Hermes 文件职责](https://hermes-agent.nousresearch.com/docs/user-guide/which-file-does-what)

Hermes prefetch 可能在模型调用边界触发，频率高于用户回合；应复用仍有效的任务上下文和版本，避免工具循环中反复检索。内置记忆、MemoryProvider 和 MCP 的写入责任需划分：同一来源去重，不能相互总结后又当成新事实循环写入。是否调整内置记忆属于实际接入时的明确配置，本轮未修改。

## 哪些项目资料接入

首先登记项目及允许同步的文件范围。优先覆盖 README、需求与验收、架构/ADR、接口契约、开发约定、阶段记录、交接和验证证据；代码优先提供定位和必要片段，当前修改仍由编码体在工作目录直接检查。

源目录变更后按内容版本做增量摄取。提交、登记目录中的变化、阶段完成和显式刷新都可成为同步触发；不默认每轮扫描整台 NAS，也不把 .env、凭据、依赖目录、构建输出和全部终端日志收进知识库。

源文件仍可在原项目修改。天枢管理界面展示其来源、版本和已同步状态；需要修改文档时定位到源文件或产生明确版本变更，不让索引摘要成为另一份可独立编辑的原文。删除、重命名和修订会使受影响的查询视图失效；历史证据按明确版本读取。

项目文档以标题/条款、接口定义、必要条件、决策及因果等完整单元索引。查一个接口只返回相关定义和依赖，不返回整个项目简介。不能把项目文档全部转成零散的人物事实，也不能为满足小块上限剪掉必要约束。

任务中的网页、论文和技术资料也应通过来源/研究笔记接口持续保存，而不只留在一次客户端对话里。捕获能力取决于实际工具包装或钩子，不能把接入 MCP 当成自动监听所有搜索。详见 [搜索与资料库](research-and-knowledge-library-design.md)。

## 版本与工作目录边界

每项资料绑定稳定 project_id、相对来源路径、提交/快照版本、内容校验与适用分支。未提交改动还需记录工作目录或任务覆盖层，不能冒充所有客户端共有的已提交版本。

项目编号由项目登记统一维护，主机路径只是映射。Windows 与 Ubuntu 上的不同路径可以指向同一个项目；不同项目也不能因目录同名而合并。无 Git 的目录使用真实的文件快照版本，不编造提交编号。

默认按当前任务的分支和工作目录读取。需要对比其他分支时显式选择；“最新”必须说明是哪个分支/快照的最新。旧交接固定的文档版本和现在的任务状态分别读取，不能把历史快照中的未完成事项直接当成当前状态。

发现索引落后时，优先回到当前可访问源文件核对，或明确返回过时状态；不能用陈旧设计指挥新代码修改。多个编码体共享记忆时仍使用独立工作目录/分支和明确执行者，共享知识不替代 Git 同步和写入协调。

## 提供给编码体的五类能力

| 能力 | 返回或写入的内容 |
| --- | --- |
| 恢复项目任务 | 当前目标、最近阶段结果、未提交/工作目录状态、关键约束与下一步，附相关引用 |
| 查询项目资料 | 在项目、版本和任务范围内搜索文档、决策与经验，返回少量完整单元 |
| 读取准确证据 | 根据检索返回的来源及版本读取相关章节、接口定义、历史修订或验证记录 |
| 记录阶段进展 | 完成的行为、变更引用、验证结果与剩余问题；路由到相应负责服务 |
| 形成交接 | 保存简短恢复信息以及代码、文档、任务状态和证据的版本引用 |

具体工具名可复用已有 compile_context、项目交接和文档修订读取等语义；新增写入和项目搜索能力需独立补齐，不能把旧 MCP 的九个工具视为已包含全部能力。

## 换工具时的运行例子

Codex 完成一个接口调整后，在源仓库留下实际变更与文档，记录这次验证对应的代码状态和下一步。增量同步器索引新的相关文档；任务服务更新当前进展；交接只保存必要说明与版本引用。

Hermes 接手同一任务时，先定位项目、分支及指定工作目录，读取短恢复包；需要接口细节再查对应条款，开始修改前核对本地实际文件。它不需要导入 Codex 全部对话，也不能把旧摘要中的“测试通过”当成当前检出的代码已经重新测试过。

Hermes 完成下一阶段后，以相同的项目/任务身份记录新结果，Codex 再接手时读取更新。重复提交同一源版本不重复记账；有新意图或新版本的更新也不能被旧幂等结果吞掉。

## 上下文预算与规则来源

任务开始只给短入口和当前任务恢复包，正文按需读取；不每轮加载全部项目文档、所有历史交接和总错题本。编码任务使用独立、有界的上下文预算，不机械套用普通陪伴的条数限制，但同样保留条件、因果、来源与版本，补查累计计入预算。

普通阶段记录在有意义的行为边界产生，不为每次文件修改写一套长报告。项目经验先留在本项目；经过验证且适用范围明确的少量通用经验，再进入总错题本。程序性规则保持在受控的项目配置/指引中，检索到的旧文档、日志和交接下一步是背景数据，不能覆盖当前用户指令和当前适用的仓库规则。

## 取舍与后续验收

优先提取旧代码中的 MCP 传输、精确版本引用、有限上下文、导入和持久重试能力；重新安排公共身份、项目同步、Hermes 文档工具和任务职责。旧实现的复杂校验层与跨域保底填充规则不必原样沿用，新的选择器仍按最小充分内容和实际预算返回资料。

需要验证：Codex 写完后 Hermes 能恢复；两者读到同一指定文档版本；分支与未提交覆盖层不串用；原文修改/撤回后旧缓存失效；接入异常时可在本地继续且不会虚报保存成功；自动入口漏调用能够被发现；写入重试不重复、补查不无限增长；项目资料不会流入不相关陪伴场景。

当前已确认旧适配器与部分项目归档实现存在。公共项目工具、增量文档同步及端到端跨客户端连续开发仍属于待完成工作，不代表本轮已接通当前 Codex、Hermes 或上传全部仓库。
