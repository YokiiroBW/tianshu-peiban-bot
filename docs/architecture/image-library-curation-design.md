# 图片资源库整理与成本设计

日期：2026-09-13。状态：目标设计与估算方法，尚未实现或进行真实图片评测。用户希望把 NAS 的照片、动漫图、表情包等登记为待整理源，新建资源库后进行查重、优选、分类。本次未扫描、上传或更改真实 NAS 文件。

## 产品流程与职责

选择 NAS 源目录 → 登记待归类批次 → 新建/选择目标资源库 → 本地扫描与特征提取 → 查重分组、分类候选、优选建议 → 必要时视觉模型复核 → 预览整理计划 → AssetLibrary 执行归档并更新索引。

登记“待整理”首先是状态变化，不要求把所有文件搬进同一个目录。目标库未知时使用“待归类”，目标已知而尚未归档时使用“待整理”。保留真实目录及关联文件关系，排除输出目录回流和重叠扫描，已有受管库不能被当成新入站目录重复接管。

AssetLibrary 负责资产编号、文件事实、特征缓存、查重关系、规则、计划、物理操作与展示；天枢负责接受目标、选择分析能力、模型路由和跨功能任务入口。具体格式分析交给 AssetLibrary 的 Provider/Worker 扩展，天枢不再建立另一份资产数据库或移动引擎。Knowledge 只读取需要知识化的资料引用；图片标签和全部图片不自动变成陪伴记忆。

“照片库、插画库、表情包库”可以有各自真实根目录。另以标签和集合表达“动漫 + 表情包”“某次旅行 + 风景”，同一资产可以出现在多个逻辑集合中，不为每个标签复制一份原图。物理归属和搜索分类分别管理。

## 分层处理

| 阶段 | 建议方式 | 输出及限制 |
| --- | --- | --- |
| 只读扫描 | 文件属性、可解析元数据、内容版本、关联关系 | 断线与无法读取不等于文件已删除；不靠文件名认定身份 |
| 精确查重 | 大小等信息筛选候选，再读取完整强哈希；涉及清理时复核文件版本及内容证据 | 同内容组不自动合并资产身份，也不直接删除副本 |
| 像素与近似查重 | 解码后的像素证据、感知哈希、局部比较、视觉向量等 | 感知相似只生成候选；编码、色彩、透明度、方向和动态信息需分别处理 |
| 技术质量分析 | 解码完整性、尺寸、压缩痕迹、模糊度等本地指标 | 大尺寸不等于真实细节更多，指标不等于收藏价值 |
| 初步分类 | 已有标签/目录、可用本地 OCR、图片分类器与视觉向量 | 生成多标签候选与待复核项；先评测照片、动漫、表情包各自效果 |
| 语义细化 | 配置的本地视觉语言模型或云端视觉模型 | 处理模糊类别、细致描述、文字语气、个性化挑选等；输出短结构化候选 |
| 计划与执行 | AssetLibrary 统一规则与文件操作用例 | 源目标、变更项、冲突、复核项和实际执行结果可查看 |

大库不逐张与全库全部图片比较，也不逐对调用大模型。先通过索引和有界近邻查询找候选，再对小范围证据复核；候选召回可能漏检，不能宣称穷尽所有相似图片。

同一份字节内容可复用内容分析结果，但不同文件的目录、拍摄上下文和用户标签不因此自动相同。近似图片不能直接继承代表图的全部文字、角色和语义结论；代表图只适合生成待验证的组级建议。

## “优选”必须知道在选什么

| 资源 | 可以帮助选择 | 应保留的区别 |
| --- | --- | --- |
| 照片 | 同场景连拍中的清晰程度、曝光及用户指定偏好 | 不同表情、人物组合与事件意义；艺术性虚焦不自动淘汰 |
| 动漫图 | 同源版本的完整度、可见细节、压缩损失等 | 不同表情、服装、裁剪、作者修订与文字版本 |
| 表情包 | 相近用途、文字可读性、常用偏好 | 文字、反讽和语气不同；故意低清可能是表达的一部分 |
| GIF/APNG 等动态内容 | 动态完整性和代表帧辅助判断 | 静态预览相同不能证明动画重复；抽帧不足则保持待复核 |

优选默认产生推荐顺序、依据和可对比版本。用户可只展示优选、收藏候选或生成清理计划；“不入精选集合”不等于“删除原文件”。精确副本也可能是有意跨库收藏。RAW 与 JPEG、Live Photo 的照片与视频、配套说明和系列图片要保持关联。

人物身份、作品角色与作者归属不能由模型猜测直接变成正式事实；可引用已有可靠元数据，未知则保留未知。分类评估采用有标注的抽查集，不能将模型自报的置信度当成真实正确率。

## 模型与 token 预算

本地哈希、文件属性检查以及本地运行的非生成式 OCR/分类/向量计算不产生云端大模型账单，但仍消耗磁盘、网络、CPU/GPU、内存和时间。本地运行生成式视觉模型仍有 token 和推理计算，只是不按云端 API 收费。

云端图片理解的输入计费与模型、图片尺寸和细节配置有关；还需计算文字提示和模型输出。不能使用生图报价计算图片分类成本，也不能套用“每张图片固定多少 token”。仅减小 JPEG 文件字节数不保证图像 token 减少；调整像素尺寸/细节参数也需核对具体模型规则，并验证小字与细节是否仍可读。[OpenAI 图片理解与成本说明](https://developers.openai.com/api/docs/guides/images-vision#calculating-costs)（2026-09-13 核对）

令 N 为本次需要重新分析的唯一内容数，r 为需要云端分析的比例，复核和重试分别追加请求。总输入为各请求的图片输入、文本上下文和工具结果之和；总输出按实际可计费 usage 统计，包括提供商规则下的推理消耗，不能只数可见标签字数。

以下仅演示计算，**所有比例和单图 token 均是假设，不是实测或某款模型报价**：原始 10,000 张，精确查重后剩 7,000 份唯一内容；其中 20% 需要云端分析。假设每份平均 800 输入 token、80 输出 token。

| 方案 | 云端分析图片数 | 输入 token | 输出 token |
| --- | ---: | ---: | ---: |
| 每张均上传分析 | 10,000 | 8,000,000 | 800,000 |
| 查重后仅处理需要云端的内容 | 1,400 | 1,120,000 | 112,000 |
| 全部使用本地处理 | 0 | 云端为 0 | 云端为 0 |

前两行暂不含额外批次提示、重试、复核及其他计费项目；若 800/80 来自完整实测均值，已经计入的部分不得再重复相加。混合方案的 86% 降幅完全来自示例假设，不是目标保证。相同比例下，十万张将上述 token 乘以十。若输入、输出单价分别为每百万 token P、Q，则示例混合方案对应 1.12P + 0.112Q，另加未包含项目；不在未选择线路前估报货币金额。

先按照片、动漫、表情包、动态内容和难例抽取一批代表样本，例如 300 张，记录实付 usage、分类正确率、误并风险、待复核比例及每秒处理量，再估算全库。这个样本量是试跑建议，不代表统计充分或已经试跑。相似图片优选需抽取完整候选组，不能仅随机抽单图。

## 控制长期成本

1. 内容特征、OCR 和模型候选结果缓存到资产侧。缓存键包含内容版本、分析器/模型版本、提示模板和分类体系版本；仅失效受影响步骤。纯移动路径不重跑内容理解，依赖路径的分类规则则应重算。
2. 日常只处理新增与变更内容。模型改变导致向量空间变化时需明确迁移或重建，不能把不同向量空间的结果直接比较。
3. 按需求选择字段：粗分类只要少量标签，表情包检索可加 OCR 和短语气说明。详细逐图描述、全库长评语和多轮审稿作为额外能力计费。
4. 图组请求可以减少重复提示，但多图仍计算图像输入；拼成联系表不等于免费，且容易丢失小字、差异和资产对应关系。疑难项再读细节，不牺牲完整语义换低费用。
5. 设置每批云端图片上限、并发上限和预算预留，收集实际 usage 后结算；接近预算或提供商用量不可用时停止追加云端任务，并展示剩余待处理量。预算估计误差和在途请求需预留余量，不能无依据保证精确硬金额上限。
6. 分类、优选、描述各自可选“本地 / 混合 / 云端”；模型上限之外还要限制 NAS 吞吐与 GPU 占用。与 ComfyUI 共用电脑时排队调度，聊天和前台浏览优先。目录可配置内容是否允许发给云端，避免通过后台整理默认上传整个私人照片库。

## 执行体验与当前缺口

界面提供批次总览：待扫描、完全重复组、相似组、分类候选、优选候选、需复核、已归档，以及本地进度、云端用量和估算余量。支持按组对比、批量采用建议、暂停和继续，不需要逐张发一次聊天请求或逐张弹出确认。

AssetLibrary 当前需求仍将未确认 AI 结果作为候选；正式标签和 AI 推断的物理变更通过可审阅的计划确认，已允许的入站确定性规则可自动执行。未来若扩展自动采用 AI 分类的范围，应明确更新该产品规则和验收标准，而不是由天枢连接器绕过。源变化、目标冲突、受保护资产、跨库有意副本和失败恢复沿用资产核心规则。

当前只读查询、浏览、预览和内部操作计划基础，不等于完整图片查重、优选、分类或生产归档已经交付。详细代码依据与接口缺口见 [AssetLibrary 协作设计](assetlibrary-nas-organization-design.md)。本次只新增设计，没有改动 AssetLibrary 仓库、生产写入口或 MCP 实现。

可借鉴 Immich 的自托管机器学习与候选重复组：其配置说明采用 CLIP 向量寻找可能重复项，并明确阈值扩大可能引入误报。这支持本地提取特征后复核的方向，不能证明我们的混合图片库达到相同效果，也不要求再引入一套完整相册管理系统。[Immich 系统设置](https://docs.immich.app/administration/system-settings/#duplicate-detection)；[重复项工具](https://docs.immich.app/features/duplicates-utility/)（2026-09-13 核对）

后续验收重点：相同文件复用分析但不误合并身份；换字表情包与动画不误删；系列/复合资产不拆散；源变更使旧计划失效；任务重启跳过已有成功结果、文件操作不重复执行；云端响应不确定时先按提供商能力查询状态，没有幂等保障时不得承诺重试不重复计费；所有模型候选均关联正确资产版本；分类错误可批量修正；云端禁用时仍完成本地可做部分并明确未完成项；预算触顶可断点续做；标注候选与正式归档状态始终一致。
