# 画像分层与最小充分召回

日期：2026-09-13。用户已明确要求：画像与记忆必须按相关小块取用，禁止把整份画像或大量历史默认放入上下文。本文将该要求具体化为设计约束；字段、预算和选择算法仍待实现及评测。

本文细化并收紧此前“每轮小画像/关系快照”的说法：准备回应时只装配必要字段。画像摘要、人物详情页和主题目录不作为默认提示词内容。允许返回零条画像；预算是上限，不是填满目标。

用户进一步确认：语义完整性优先于块大小。目标是在保留原意、适用条件与必要依据的前提下减少内容；不能为追求更短而改变主体、事实、因果或确定程度。条数与长度预算约束选择方式，不定义切块边界。

## 分层结构

| 层 | 保存什么 | 怎样取用 |
| --- | --- | --- |
| 人物索引 | person_id、平台账号绑定、昵称历史、头像引用 | 程序用于定位；模型仅接收当轮需要的称呼/人物标签，不接收完整索引与头像数据 |
| 交流锚点 | 当前称呼、必要的表达方式、此角色与对方的交流尺度 | 每轮判断哪些字段确实需要；已在当前情境中明确的有效信息不重复加入 |
| 主题画像原子项 | 某个偏好、习惯、环境事实或明确约束 | 先选本轮相关主题和字段，再取独立条目；不展开整张主题卡 |
| 场景与关系条目 | 某群中的表达偏好、某角色与此人的约定、适用场景 | 与主题项使用同一条目机制，按人物、角色、会话及条件选择；熟悉度不决定设备权限 |
| 经历与原始证据 | 一件事的必要经过、原因、结果及原文引用 | 先取能支持当前回答的最小充分片段；需要原话或解释原因时再限量展开 |

这些是查询和组织层次，可以先由一个关系库及必要索引承载，不要求五套存储或服务。人物、群、角色和世界资料分别有主体，不把群画像或角色自身设定混入用户画像。

## 画像按主题索引，按条目返回

主题目录用于路由，例如“交流方式 / 技术解释”“创作偏好 / 图像”“娱乐兴趣 / 游戏”“设备环境 / 生图设备”。目录深度和字段名先保持简单稳定，常见同义表达映射到同一字段；不让模型无限生成新的目录树。

同一人物可以拥有许多主题条目，但一次请求只读取它需要的几个字段。比如已知当前任务是排查报错，优先查询技术解释偏好与相关设备事实；该人的服装、音乐和其他群聊习惯没有因此被一并加载。

存储和索引保持小粒度，召回与提示词装配则以完整语义单元为单位：可以是一条自足记录，也可以是少量具有必要依赖的记录组合。不能在数据库中拆成小条目，随后又拼成整份画像生成 embedding 或每轮读取整段摘要。

人物详情页可以按主题组合展示，也可以按需生成阅读用简介；它是管理视图。主题标签或轻量主题索引可用于检索路由，但命中主题不能自动展开全部子项，也不能把主题简介整体交给对话模型。

## 一个原子项如何定义

原子项是“能够独立判断真伪、适用性和版本的一条完整陈述”。最小单位要保留主体、否定、条件、时间和来源性质；不以固定字数、句号或向量切片长度作为唯一边界。

以下为虚构示例，不写入真实用户画像：

| 原子项 | 应保留的语义 |
| --- | --- |
| 用户甲在技术排障时希望看到具体步骤 | 偏好只适用于技术排障，不能变成所有聊天都要求长篇回复 |
| 用户甲在群 G 希望少用表情包 | 群 G 是适用条件，不能推成所有群和私聊都禁止表情包 |
| 角色 A 与用户甲约定周末看电影，后来用户甲取消 | 约定对象、角色、时间与当前取消状态一起决定能否跟进 |
| 用户甲说项目 P 当时暂停是因为设备资源不足 | 保留项目、当时、用户自述和原因，不能泛化成用户缺乏开发能力 |

一个偏好可以独立保存，相关原文由引用关联。遇到“因为……所以……”或“只有……才……”时，条件和因果是必要内容。可以将事实与证据分别存储，但选择器必须把回答所依赖的必要条件一起带上。

## 存储颗粒与召回单元分别设计

存储拆分便于独立更新和定位；召回单元负责让本轮模型正确理解。命中片段只是入口，不能因为某句话相似度最高，就把它从必要的上下文中单独拿走。

优先把不可省略的条件直接存入原子项。确实需要独立保存的多条记录，用少量明确依赖关联；召回时补齐必要成员，重新核对整组的范围与版本，再整体保留或整体放弃。依赖只扩展到本轮理解所需的边界，不展开整个人物或话题的全部历史。

| 必须保留的关系 | 切分和装配规则 |
| --- | --- |
| 主体、转述与指代 | 区分是谁的说法、谁的经历；指代无法确认时保留歧义，不按最近出现的人名猜测 |
| 条件、例外与否定 | “排障时讲详细”不扩成“一直讲详细”；“暂时不需要”不扩成“从不需要” |
| 因果与转折 | 回答原因时保留关键原因和结果；不能把“因为时间不足”概括成“没有兴趣” |
| 时间与修正 | 当前认识按有效版本表达；询问过去时保留当时条件，不能把旧情况当作现在的状态 |
| 提议、计划与已发生 | “有空的话想去”保持条件性意向，不变成已约定，更不能变成已经去过 |
| 确定程度 | 转述和推测不能经压缩变成确认事实；无法确定讽刺或玩笑时不直接固化为偏好 |

例如“平时简短些，但排查报错时希望给出具体步骤”：问一般交流习惯时，应同时保留默认偏好与例外；已经明确是排障任务时，只返回“排查报错时希望给出具体步骤”即可。是否需要相邻内容由本轮问题决定，不机械固定带前后若干句。

预算不足时，先移除无关或重复的完整单元，再尝试忠实的限定字段投影。仍放不下，就分步取证、明确不足或询问；不能拆掉必要条件继续使用残片，也不能静默突破预算。把多个条目合并成一段文字，不能重置它们已经占用的本轮预算。

依赖的一部分无权读取、已失效或丢失时，剩余片段不能自动视为完整证据。仅当剩余信息可以独立支持当前陈述时才使用；否则保留缺口，且不向无权接收者泄露被过滤资料的存在性。

后台提取和摘要时，应检查限定字段、人物归因与原文的对应关系；上线前用带条件、否定、转述和修正的样本检验语义保真。运行时程序检查已声明的必要依赖与版本，语义不明时有限回读或核验，不为每轮普通聊天增加完整的多模型审查链。

## 建议的逻辑记录结构

| 字段组 | 最小含义 |
| --- | --- |
| 定位 | 稳定条目编号、主体、类型、主题/字段 |
| 陈述 | 一个值或判断，以及不可省略的条件、否定和限定语 |
| 适用性 | 适用会话、角色或场景、有效时间；描述在哪些情况下成立 |
| 可见范围 | 当前接收者和角色能否读取/使用；与适用性是两个概念 |
| 可信与修订 | 用户自述/观察/推断等来源性质，当前版本及有效/撤回/冲突状态 |
| 证据与依赖 | 原消息或真实事件引用；确有必要时，链接一小组解释条件或冲突证据 |

避免把所有条目变成自由文本 JSON 大包。字段可先针对常见事实和偏好规范化；复杂经历保留一个有边界的事件片段。数量庞大的来源列表和历史版本留在服务端，不随每次命中整体返回。

同一字段的重复表述可以合并证据，不增加多个等价记忆块。更具体的场景条目只在该场景中生效；不自动覆盖全局偏好。出现矛盾时检查是否为时间变化、不同条件或明确纠正，不能仅按“更具体”或“更晚”机械取胜。

## 从请求到最小充分包

1. 从当前消息与有限话题窗口明确本轮需要的对象、用途、主题和字段。优先复用任务类型与明确实体；指代不清就做有限解析或询问。
2. 先确定允许主体、角色所知、场景与版本范围，再查缓存或索引。跨群、跨角色和私人资料过滤对每一层都有效。
3. 有明确字段时直接查结构化值；模糊描述时在允许范围内搜索原子项。主题路由不确定时，可扩大相关主题的候选搜索，最终只返回选中条目及理解它所必需的依赖。
4. 服务端筛选、按需重排候选，去除重复、失效和不适用的条目。候选集与最终注入集分别限制，不能把整个候选集发给对话模型让它筛选。
5. 按本轮问题检查主体、条件、否定、因果、时间、来源性质与冲突是否完整，补齐必要依赖后成组选择。已经在当前情境中的有效信息不重复注入；依赖当前情境的条目不能在后续脱离该情境的轮次中直接复用。
6. 按贡献和成本选择最小充分集合。找到了支持本轮所需内容的集合就停止，不为用满 top-k 或 token 预算补充旁支资料。
7. 在渲染后的最终记忆段上检查条目数量、字节与可核实的 token 预算。完整条目放不下时选择更窄查询、标记不足或询问；不截掉条件、否定或关键结果。
8. 生成阶段若发现一个具体证据缺口，可以申请一次预算内的定向补查。补查与已加载内容共用本轮总预算，不能靠多次调用绕过限制。

召回的目标是“支持当前需要的内容”，不是让向量相似度最高的若干条目自动进入提示词。语义精度没有办法仅靠分块和固定阈值绝对保证；可由程序保证的是范围、条目数、内容边界、版本规则和上限，语义是否充分仍需要用真实问题评测。

## 给模型的内容应是字段投影

对话模型收到的是已经筛选和渲染的相关陈述，例如：

> 技术排障时，用户甲偏好具体步骤。来源：用户自述；适用范围：技术排障。

模型不需要同时收到账号绑定历史、头像 URL、完整昵称列表、全部兴趣、所有关系数值、全部来源消息、向量分数和每个字段的变更历史。

关键限定语、必要的来源性质、时间和证据标记仍保留。内部条目编号、检索分数、范围判断与详细追踪可留在程序元数据；它们不必全部进入模型提示词。当前提示词中已有的信息，按条目编号与版本或等价语义避免重复。

## 首个可评测的预算草案

以下数字是普通陪伴聊天的起始草案，不是已接受的性能指标，也不是已实现的保证。预算只针对画像与长期记忆内容，不包括核心人格、用户原消息、必要近期对话或工具操作的独立业务输入。

| 分区 | 数量上限草案 | 内容 token 上限草案 |
| --- | --- | --- |
| 交流锚点 | 最多 3 个必要字段，允许为空 | 64 |
| 主题 / 场景 / 关系画像 | 合计最多 4 个原子项，允许为空 | 256 |
| 经历与原文证据 | 最多 2 个证据单元，允许为空 | 384 |
| 整段画像与记忆 | 含分隔符、必要标签、补查内容 | 总上限 768 |

证据单元可以包含一件事不可分割的条件与因果，但不能把一整章或数百条消息包进“一个单元”。普通模式再施加最终记忆段 UTF-8 字节上限，例如 3072 字节，并保留各条目的完整边界。每个单元仍受分区和总上限约束。

涉及多个群成员时，共用一份本轮预算，不按人数倍增。连续同一话题的旧记忆也计入当前装配预算，不允许每轮追加后从不移除。删除或替换历史记忆段不会删除正式长期记录。

只有实际使用且可核实的目标 tokenizer 才能报告精确 token 限额；未知中转模型的 token 数不能伪装成精确值。无可靠 tokenizer 时仍执行条目数和 UTF-8 字节硬限制，并标明 token 数是估计值。

“整理我们过去一个月的约定”之类请求，确实需要更多相关事件。此时按明确任务采用分页、逐段取证和有界汇总，每次调用仍受预算限制；不把普通聊天额度永久放大，也不把整份画像当作捷径。

## 如何避免越用越大

正式画像保存原子项，管理视图按需组合。缓存保存已选条目编号、版本及必要字段投影，而不是完整人物简介。某条偏好改变时更新对应条目及相关快照，不重写整个人的画像。

主题索引可以更新，但主题命中只用于候选路由。不存在“命中一个偏好后自动加载父画像”“命中一个事件后自动展开该人的所有经历”这样的默认行为。

依赖展开必须有边界，普通模式只允许小范围、预算内的必要补充。依赖环、缺失证据、过大的因果链或无法压入完整单元时返回不足原因，不进行无界图遍历。需要精确原因时，允许一段稍长但完整的事件证据优先于多个无关短句。

## 缓存、更新与隐私

沿用召回设计的角色、人物、受众、用途、话题与版本约束，并将条目版本加入缓存有效性判断。记录“适用场景”不能替代读取权限；一条私人偏好即使与群内问题相关，也不因此获得跨场景使用许可。

允许跨场景使用的普通认识应形成单独、可追溯且经过范围处理的字段投影。不能缓存完整私聊简介后仅通过删名字脱敏。含不同可见范围的复合证据，应只在允许读取全部必要内容时整体使用；否则返回受限场景下真正可成立的概括，或者保持缺口。

正式记录纠正或撤回后，依赖它的摘要、画像投影、索引和缓存要失效。向量相似度高不意味着旧版本仍可用。私密条目被过滤的具体原因和存在性不向无权接收者披露。

## 验收要同时证明“小”和“够用”

| 情形 | 必须观察到的结果 |
| --- | --- |
| 问候或简单闲聊 | 没有无关兴趣与经历；可只用已有情境，画像召回为零 |
| 技术排障偏好 | 只取技术解释偏好与本次确需的环境信息，不取衣橱、音乐等主题 |
| 场景差异 | 技术群的严谨偏好与游戏群的玩梗偏好分别适用，不全局覆盖 |
| 偏好带条件或否定 | 最小块保留条件和否定，不能因为压缩而改变含义 |
| 默认习惯含场景例外 | 一般性提问保留默认与例外；针对明确场景只选完整适用条款 |
| 转述、模糊指代或条件计划 | 不换主体、不猜归因、不把意向变成确定约定或既成经历 |
| 必要依赖被过滤、失效或挤出预算 | 整组检查后取舍，不能单独使用会改变原意的残片 |
| 当前事项已取消 | 返回当前有效状态，不用旧约定或更相似的过时摘要 |
| 询问往事原因 | 返回必要的事件和因果，不只给一个失去上下文的关键词 |
| 多人群聊 | 本轮全体画像与记忆共用预算，不随参与人数线性膨胀 |
| 命中大量候选 | 最终只出现选中原子项，候选全文和人物简介不进入提示词 |
| 必要证据超预算 | 标记不足、分步检索或询问，不静默截断、不偷偷扩大预算 |
| 连续多轮和二次补查 | 旧块更新或移除，新增块不会无限累计；补查合并计入总预算 |
| 语义精度 | 对照人工选出的最小充分证据，检查漏掉必要项及混入无关项 |

可观测指标包括：最终条目数、最终渲染长度、重复率、必要证据覆盖、无关条目比例、条件保留率、过时版本命中和越界读取。仅有短输出、较高相似度或满足 top-k，不能证明召回精准。

## 与当前方案衔接

情境装配模块输出“需要哪些字段或证据”，天枢记忆返回经过范围和版本校验的字段投影及证据单元；核心只装配最终选中内容。人物详情页与日记/长篇创作采用各自有界读取方式，不复用一个默认返回完整资料的接口。

这项约束应作为后续实现验收条件。当前只形成设计和可核对的示例契约，没有开发新的记忆引擎，也没有修改现有运行数据。
