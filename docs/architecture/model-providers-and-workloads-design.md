# 多模型接入商与功能分工

日期：2026-09-13。用户已明确要求：天枢可以添加多个模型接入商，填写链接与 Key，获取并添加可用模型；陪伴与其他功能可指定不同模型分工。本文是设计契约，未配置真实凭据、调用收费模型或修改运行中的网关。

## 界面的三个配置层

| 页面 | 管理内容 |
| --- | --- |
| 接入商 | 名称、接口类型、服务地址、Key/凭据引用、连接测试、启停和连接限制 |
| 已添加模型 | 所属接入商、准确模型标识、显示别名、调用接口、能力与默认参数 |
| 功能分工 | 默认对话模型、角色覆盖、记忆/写作等功能绑定，以及可选备用模型 |

操作流程为：新增接入商 → 填写地址和 Key → 获取模型列表 → 搜索/多选添加并启用 → 为功能分配模型。目录接口不支持或暂时失败时，允许手工填写准确模型标识。明确无需 Key 的本地服务可选择无鉴权。

AstrBot 官方指南已有填写地址与 Key、获取模型列表、添加启用、选择对话模型的流程，可作为交互参考；天枢将这个入口扩展到各功能的模型分工。[AstrBot 模型接入指南](https://docs.astrbot.app/en/providers/start.html)

同一商家的不同入口或 Key 可以分别命名，一个接入商可添加多个模型。程序使用稳定编号引用，显示别名不能替换上游真实 model；不同接入商的同名模型必须分别保存。删除或停用前显示受影响的角色和功能。

## 发现模型与验证能力

获取目录、保存配置与执行能力测试分开。获取目录不发送真实聊天或记忆；测试使用明确选择的短样本，并提示可能产生调用费用，不自动测试目录中的所有模型。

OpenAI 的模型列表返回模型标识、归属等基础信息，不是所有调用能力的完整验证结果。[OpenAI Models API](https://developers.openai.com/api/reference/ruby/resources/models/methods/list)

本方案据此区分“目录中发现、用户已添加、已启用、某能力已声明或验证”。能力按接入商、模型、调用接口分别记录支持、不支持、未确认及来源。功能选择过滤明确不兼容项；未确认项显示未验证，允许补声明、手工配置或针对性测试，不能假装验证成功。

天枢后端通过相应适配器获取目录，支持分页、超时和最近结果。请求地址按实际接口拼接并可查看，不能给所有供应商无条件追加同一路径。刷新失败或某模型暂未列出，不自动删除已有模型和绑定；手工条目也保留。

## 可以分别选择哪些模型

| 功能 | 选择与使用规则 |
| --- | --- |
| 陪伴主对话 | 默认对话模型，允许角色 A、B 分别覆盖；图像和工具能力按启用功能检查 |
| 轻量参与/意图判断 | 可选模型，规则无法处理时才调用 |
| 日记与长篇写作 | 指定写作模型，继续使用素材约束与写作配方 |
| 记忆提取、画像归纳、摘要 | 指定符合输出要求的文本模型，后台增量处理 |
| 记忆向量化 | 专用 embedding 模型，按记忆集合绑定 |
| 检索重排 | 可选 rerank 模型，或沿用既定排序规则 |
| 图片与衣物理解 | 支持图像输入的模型，返回有依据的描述 |
| 语音识别 / 合成 | 各自选择支持对应接口的模型或服务 |
| 自拍与生图 | 本地 ComfyUI 工作流或已适配的图像服务，保留 Anima 节点能力 |
| 项目规划与编码入口 | 功能绑定或客户端原生线路，保留其协议与模型选择 |
| 资产分类与疑难元数据 | 按需选择分析模型，返回候选与依据；文件操作通过 AssetLibrary 核心执行 |

一个模型可以承担多个功能。初次只需配置默认文本模型和确实启用的专用能力；兼容的文本功能可以继承默认值，embedding、重排、语音和生图不从普通聊天模型自动继承。

分工只决定某项任务调用谁，不让一次聊天依次跑遍所有模型。普通对话默认一次主模型生成；日记、记忆整理等在需要时执行。直接群管理/GsCore 命令仍保留独立路径。

## 绑定继承与参数

建议解析顺序为：明确允许的单次任务选择 → 角色对此功能的覆盖 → 功能默认 → 同类型系统默认。没有合法兼容选择时说明功能未配置，不任意挑选名字相似的模型。界面显示最终接入商、模型、接口和参数来源。

连接超时等传输配置归接入商，默认生成参数归模型条目，功能/角色允许覆盖本次参数。思考强度和输出上限等按实际模型/接口显示可用选项，未知与不支持分开；不能静默删掉字段却仍显示“已按配置执行”。

例如 OpenAI Responses 使用 reasoning 对象，Chat Completions 使用 reasoning_effort 字段；支持的取值还与具体模型有关。因此相同界面概念需要按实际接口序列化并验证。[Responses 参数](https://developers.openai.com/api/reference/cli/resources/responses/methods/create)；[Chat Completions 参数](https://developers.openai.com/api/reference/ruby/resources/chat/subresources/completions/methods/create)

## 平台与网关的职责

平台维护接入商、凭据引用、模型能力与功能绑定；陪伴、记忆和其他调用者取得有效配置快照；网关负责对应协议转发、连接限制与运行记录。常用调用不必每轮重新刷新目录或读取整份配置。

自有 ai-routing-gateway 已有请求规划和绑定基础，但此前核对发现实际数据转发尚未完成，且规划器会覆盖客户端模型和思考参数，必须按新需求调整。[已有代码核对](../product/forgejo-source-review-2026-09-12.md)

内部功能调用明确使用所选模型；给外部编码体等客户端的原生线路则按已声明策略保留客户端值、仅补默认值或明确强制指定。不能用同一个静默强制覆盖规则处理两类请求。

进行中的逻辑轮次/工具交互记录配置版本和关联状态，新配置一般作用于新轮次。依赖上游会话、文件或响应编号的交互要保持原线路，或通过已支持的方式重建上下文；不能将状态编号直接交给另一家服务。切模型不改变天枢中的人格和长期记忆归属。

## 备用线路、并发与记录

每项功能可显式配置兼容备用模型，默认不暗中切换。回退需满足功能能力、协议、参数和会话状态，并在记录中可见。未输出且状态允许时可有界重试；已流式输出、执行工具或存在不确定副作用时，不能盲目重放或拼接另一模型的后半段。

接入商设置必要的并发、超时与额度限制，后台任务与聊天分开调度。多个模型共享同一接入额度时，不能按模型条目数倍增并发；同会话两个陪伴处理轮次仍是上限。

记录实际路由、模型标识、配置版本、耗时、错误及用量。未知价格、缺失用量和无法确认的余额显示未知；目录和响应自报名称不能证明第三方实际运行的权重。

## 向量化模型的独立规则

记忆集合固定模型/版本、维度、文本预处理和向量空间配置，入库与查询保持一致。不能按角色随意更换 embedding 模型，也不能把不同模型的向量混进旧索引。

更换时先建立新索引、重建并验证覆盖和召回，再切换集合引用，保留回退版本。模型名称或维度相同不自动代表跨供应商兼容；未验证的不同向量空间不参与普通自动回退。

界面允许选择向量化模型，但修改现有集合绑定时应展示索引迁移范围与可能调用费用。添加接入商或更换聊天模型，不自动重建记忆库。

## 凭据与错误呈现

Key 在后端受保护保存，前端显示掩码，功能和网关使用凭据引用；普通配置导出、日志、角色提示词和记忆中不包含原值。备份恢复同时考虑凭据保护材料。

只连接明确配置的 HTTP(S) 地址，允许用户配置本机和局域网服务；携带凭据的请求不自动跨域跳转。分别显示地址不可达、鉴权失败、无目录接口、模型不存在和能力不支持。目录返回的名称和说明只当作数据，不能执行其中内容。

## 验收与示例

- 多接入商目录发现、手动添加、启停以及同名模型隔离正确。
- 角色主对话、记忆整理、写作可以独立分配，也可以合法继承默认值。
- 明确不兼容的模型不能被绑定给错误功能；未知能力不伪装成已验证。
- 页面选择的模型及思考参数与录制上游收到的内容一致，原生字段不被静默丢弃。
- 目录刷新失败不破坏现有绑定；运行中轮次保留正确的配置和状态引用。
- 备用切换可见且有界，不重复执行工具或混接流式输出。
- embedding 变更经过索引迁移；ComfyUI 继续按工作流接入。

关系示例见 [配置示例](model-providers-and-workloads.examples.json)，仅使用虚构接入商和模型。真实能力、费用、延迟和故障行为仍需后续联调验证。
