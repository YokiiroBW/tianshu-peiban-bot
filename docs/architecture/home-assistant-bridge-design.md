# 天枢与 Home Assistant 智能家居接入

日期：2026-09-13。用户询问 Home Assistant 是否可作为智能家居接入方，并由天枢调用。延续总蓝图的 HA 优先方向，本文细化职责与接口使用。没有连接真实 HA 实例、获取令牌、导入设备或执行控制。

## 两种入口，共用一个连接器

聊天路径：QQ/TG → NoneBot → 陪伴核心理解请求 → 天枢 HA 连接器 → Home Assistant → 设备或设备网关。

界面路径：天枢智能家居页面 → 同一个 HA 连接器 → Home Assistant → 设备。明确的界面开关不必先调用对话模型。

状态返回：HA 状态事件 → 天枢连接器更新当前读数与状态 → 界面刷新；仅与对话或获准自动任务相关的变化才交给角色处理，不对每一次传感器变化调用大模型。

| 负责方 | 职责 |
| --- | --- |
| 天枢界面与陪伴核心 | 展示、自然语言理解、设备别名和范围选择、角色可用能力、结果表达 |
| 天枢 HA 连接器 | 配置连接、读取实体能力与状态、映射明确目标、调用动作、订阅变化、处理断线与结果 |
| Home Assistant | 各品牌集成、设备与实体状态、服务动作、已配置场景/脚本及固定自动化 |
| 设备、网关或厂商服务 | 实际硬件通信及可提供的控制和状态回报 |

天枢智能家居页继续使用自己的视觉语言，不需要嵌入整个 HA 控制台。设备发现和品牌配对可留在 HA；天枢选择需要展示和允许角色操作的设备/场景，避免复刻各厂商设备协议。

## 官方接口与动作语义

建议使用 REST 查询/动作接口与 WebSocket 事件订阅；也可在同一 WebSocket 上调用服务动作。读取当前状态、服务目录与连接身份，与控制设备分别处理。[REST API](https://developers.home-assistant.io/docs/api/rest/)、[WebSocket API](https://developers.home-assistant.io/docs/api/websocket/)（2026-09-13 核对）。

控制实体应调用对应服务动作，例如灯具的 turn_on；不能用 POST /api/states 修改状态字符串来冒充实际开灯。该状态写入接口只改变 HA 中的状态表示，官方文档明确说明不会与真实设备通信。

连接器维护房间/别名与实际实体、能力的映射。当前状态列表不等于完整房间、设备登记信息，相关登记接口和目标实例能力要在接入时验证。只读传感器不显示控制按钮；亮度、色温、温度范围、窗帘位置等按实际可用能力显示。相同名称可能对应多个房间，目标不明确时先消歧。

服务调用返回、HA 状态变化、设备确实回报目标状态是不同证据。返回值可能包含期间其他实体的变化，必须按目标和关联信息核对。仅有指令回执时表达为已发送/等待反馈；集成若使用乐观状态，不能将其直接宣称为硬件已确认。

断线后恢复连接、重新订阅并校准当前状态；旧值标注更新时间及可用性，不把 unknown/unavailable 显示为关闭或零。重复请求优先采用明确目标状态动作；结果不确定时先查状态，不能保证 HA 所有动作都天然幂等或重复执行场景没有副作用。

## 配置与自动化

天枢配置 HA 地址和凭据引用，凭据保存在后端；模型只接收获准设备或场景及其参数。页面选择可用设备只是配置入口，实际动作范围仍由后端执行检查，不能只靠前端隐藏按钮。已有角色能力设置复用于此，不新增复杂的逐条审批体系。

固定且无需 AI 判断的规则适合留在 HA，例如已配置的灯光场景、定时和传感器联动；天枢调用场景或提供自然语言入口。同一规则不在两边各运行一份。不依赖天枢的规则可在 HA 及其设备链路正常时独立工作。

读取状态和确定性界面操作不需要对话模型；自然语言理解及确有需要的主动判断才产生相关模型调用。HA、厂商服务和所选 AI 线路的运行成本分别考虑。

## 小米设备

小米提供官方 Xiaomi Home Integration，可作为米家设备接入 HA 的候选。[XiaoMi 官方仓库](https://github.com/XiaoMi/ha_xiaomi_home)（2026-09-13 核对）。

设备支持和本地/云端路线取决于型号、所在地区、所选集成与网关。该官方集成文档对中枢网关、本地控制和部分设备类别有具体限制，因此“HA 部署在局域网”不等于“所有小米设备都能脱离云端控制”。它与其他 Xiaomi/miio 接入方案应分别核对，不能混为一个无差别组件。

首次接入应逐设备确认能看到哪些实体、哪些可控制、哪些只读、状态是否有设备反馈，以及断网时实际行为。本次未取得用户具体设备与网关型号，未承诺全量覆盖。

## 与角色小屋分开

角色小屋中的虚构窗、帘、台灯继续归陪伴环境系统；真实家庭设备归 HA 连接器。可在明确建立映射后让选定真实传感器影响小屋氛围，或启用特定联动；不能因为角色在自己的房间里睡觉，就默认关闭用户家中的实体灯。

当前仍是接入设计。后续需在实际 HA 实例中验证目标发现、开关/参数控制、状态回报、断线恢复、场景调用和界面同步；现有设备视觉稿不代表已经完成连接。
