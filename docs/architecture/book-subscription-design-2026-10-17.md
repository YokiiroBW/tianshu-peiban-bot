# 天枢书籍订阅与 EPUB 整理设计

历史设计参考：本文保留实现前的候选方案及当时调研状态，不代表全部候选能力已实现。当前部署结果以 [TS188 发布记录](../development/books-deployment-2026-10-17.md) 和产品书籍说明为准。

2026-10-17 · 设计草案。依据用户本轮“先参考设计订阅”的要求，覆盖书源管理、聚合搜索、预览、订阅下载、书库元数据匹配与 EPUB 整理。本文与[交互原型](../design/book-subscription-v1/index.html)供功能评审，尚未实现后端、派发任务或部署；原型使用明确标注的示例数据。

## 产品目标

在现有“订阅下载”中增加“书籍”，用户导入阅读 3 书源，搜索书名或作者，试读后订阅。后台获取现有章节并持续追更，补齐封面和书籍资料，在 NAS 留下一本可持续更新的 EPUB。已下载内容在来源失效时仍可阅读。

完整主流程：**导入书源 → 聚合搜索 → 详情与正文预览 → 订阅下载 → 元数据补全 → EPUB 入库 → 增量追更**。单次下载和本地文件导入也进入同一整理流程。后续 AI 听书与共读复用本轮保存的章节、段落及版本定位。

## 页面与操作

入口建议为“订阅下载 → 书籍”，页内分为“聚合搜索、我的订阅、本地书库、书源管理、整理设置”。下载任务仍进入现有下载中心；概览增加书籍的追更、下载和成品统计。正式路由在装配时沿当前导航登记，保留现有音乐、视频和旧书签。

| 页面 | 用户能完成的操作 |
| --- | --- |
| 聚合搜索 | 搜书名、作者、ISBN；选择来源组；结果逐源出现；按连载状态、作者、来源筛选；同书候选聚合后展开来源差异 |
| 书籍详情 | 查看简介、封面、作者、来源、最新章节、更新时间和已有本地版本；展开目录、选择章节试读；切换来源；单次下载或订阅 |
| 元数据编辑 | 按书名与作者或 ISBN 搜本地/连接书库及在线元数据；并排比较候选；逐字段应用、手动编辑或保留原值 |
| 我的订阅 | 查看已取章节、最新发现章节、当前缺章和 EPUB 版本；立即检查、调整周期、暂停/恢复、换源、停止追更并保留文件 |
| 本地书库 | 查看/搜索成品、预览正文与目录、下载 EPUB、查看来源和缺章、重建 EPUB；导入 TXT、Markdown、HTML、EPUB |
| 书源管理 | 粘贴 JSON、上传 JSON、导入规则直链、订阅规则集合；分组、启停、更新、导出、看失败原因和恢复最后可用版本 |
| 整理设置 | 设置现有 NAS 目标目录、书库连接、元数据提供方、追更周期、成品命名、封面/语言/转换设置 |

预览展示真实取得的正文，目录分页读取，不以搜索摘要代替试读。未下载章节可按需取回；离线时展示已缓存内容和缓存时间。登录、章节受限、来源故障和解析不兼容分别显示，不能把它们当作“本书无更新”。

## 两类订阅分别管理

**书源订阅**更新“如何搜索和提取内容”的规则，**书籍订阅**更新某一本书的章节。源集合更新不自动订阅其中所有作品，也不重置用户已保存的书籍。

规则入口接受单对象或数组，保存原始 JSON 及来源地址、获取时间、内容摘要和最后可用版本；启用状态、分组、优先级、登录会话和用户覆盖分别保存。按书源身份与集合归属更新，不仅凭显示名称合并。集合移除的规则标为上游已移除，已有订阅仍可使用本地保存版本。

导入时逐条给出结果，坏条目不覆盖已有好条目；本地修改的规则保持覆盖，用户可恢复上游版本。集合更新使用 ETag/Last-Modified（上游提供时）与内容摘要，源站不可达时保留最后成功规则并退避。普通源无需额外确认即可启用，失败源不阻塞其他来源。

用户给出的 [yckceo](http://www.yckceo.com/) 在本次 HTTP 与 HTTPS 读取中均不可用。它只作为来源发现入口记录，不能把网站首页假设成 JSON 订阅地址；恢复后需要实际规则链接或导出的 JSON。现在仍可通过本地文件、粘贴和其他真实规则直链完成导入。

## 阅读 3 规则兼容与执行

保留 `bookSourceUrl`、`bookSourceName`、`bookSourceGroup`、`searchUrl`、`ruleSearch`、`ruleBookInfo`、`ruleToc`、`ruleContent`、`ruleExplore` 和未知扩展字段。按来源实际能力使用搜索、详情、目录、正文、分页、请求头、编码、Cookie/登录与脚本功能；不把 JSON 结构导入成功显示成整条规则可运行。

推荐架构为**复用阅读 3 服务端规则引擎，由专用解析进程执行，天枢维护订阅和成品**。现有 Python 平台通过小型适配层取得统一搜索、目录与正文结果，不在主进程重新实现一套 CSS/XPath/JSONPath/JavaScript 方言。解析进程随部署包管理，用户正常导入时不用另开软件操作。

引擎候选需要在实现时固定版本后验证：历史 [reader3_server 的 API 文档](https://github.com/taotaoping/reader3_server/blob/master/doc.md)提供阅读 3 来源与换源参考；当前 [hectorqin/reader](https://github.com/hectorqin/reader)主线描述的是来源插件体系，不能直接认定等价于历史 reader3 JSON 引擎。[LegadoParser](https://github.com/821938089/LegadoParser)提供 Python 解析实现，但作者明确只有部分 JS 支持，不能仅用它宣称完整兼容所有书源。本轮不指定未经验证的生产镜像。

实现必须覆盖静态选择器、分页、UTF-8/GBK、变量与正则替换；JS、WebView、登录挑战按选定引擎分别报告支持情况。不兼容的源保留并显示所缺能力，可换源继续；不静默丢弃脚本后返回错误正文。阅读原应用专有的 Java/Android 调用不假定可直接移植。

解析工作进程限制单次时间、内存与响应大小，不挂载平台密钥、数据库和全部 NAS。网络请求沿已登记来源/书库连接，外部书源不能借重定向或脚本访问 NAS 管理接口；用户明确配置的内网 OPDS 连接单独允许目标。正文进入预览与 EPUB 前移除可执行脚本和表单。以上在内部处理，复用既有认证和连接管理，不增加日常审批流程。

## 聚合搜索与书籍身份

按来源组并发搜索，单源超时不拖住其他结果；展示完成数、失败数与可重试来源。分页以每源游标记录，避免第二页结果重复或丢失。取消搜索只取消本轮请求，不影响后台订阅。

搜索聚合与文件合并使用不同标准：标题/作者归一化可形成候选组；确定同一作品还需要来源 ID、作者、语言、目录等证据，出版物优先核对版本和 ISBN。不同译本、修订本、同名作者和同名作品保留分组，不能仅按标题归并下载。

本地已有书先显示已有内容与缺失章节，确认可复用后直接建立订阅关联；多份订阅引用同一受管成品。来源绑定记录 `source_id + source_book_id/url + source_revision`，内部 `book_id` 不随名称和封面变化；同一作品的不同正文版本另外保存 `edition_id`。

## 下载与追更

首次订阅默认下载当前可获取的全部章节，生成 EPUB，并启用追更；只想下载一次时使用独立按钮。追更默认每 6 小时错峰检查，可选每小时、每天或自定义；来源限流和用户已有设置优先。该数值是可调整产品默认，不是来源服务承诺。

同源默认一个内容请求在途，源间有界并发；429/Retry-After 和临时错误退避，共享同一来源的请求节奏。扫描目录后只拉新增、缺失或已确认修订的正文；源未给出内容更新时间时不能声称仅靠目录发现所有旧章改文，提供“检查旧章”操作。

章节保存稳定内部 ID、来源定位、卷/章标题、顺序、正文摘要和内容修订。换源先核对作品及目录映射，映射明确的复用；章节拆分、合并或版本不一致时展示差异，不直接按章序覆盖。源站删除章节时先保留本地原文和状态，避免追更变相删书。

每本书以章节为恢复单位；单章失败可单独重试，断线/重启继续原任务。任务进度区分“发现章节、获取正文、整理资料、生成 EPUB、归档”，不以完成 HTTP 请求冒充成品发布。合并同一书的重复下载与重建请求，订阅暂停、当前任务取消和删除成品是不同操作。

缺章时允许先阅读已经取得的内容，明确展示缺失章节；用户可以导出标为不完整的版本。自动发布只替换进度更完整或明确修订的版本，不能用缺章新结果替换上次完整成品。整批章节处理后合并生成一次 EPUB，避免每下一章就全书重打包。

## 元数据与书库

元数据与正文来源分别保存。可搜索的书库包括天枢本地索引、用户已连接的 OPDS/Calibre 等目录；通过书库公开接口读取，不直接改对方数据库。OPDS 提供目录、可选搜索与获取链接，具体服务是否支持搜索按实际发现结果显示，不能假设所有书库都有同一端点。[OPDS 1.2 规范](https://specs.opds.io/opds-1.2.html)

| 来源 | 使用方式 |
| --- | --- |
| 书源详情 | 网文的标题、作者、简介、分类、连载状态、最新章节与封面首先取自实际详情 |
| 本地与连接书库 | 按 ISBN、书名与作者搜索已有出版物/版本资料，避免重复整理 |
| Open Library | 作为在线书目候选，区分作品与具体版本；中文网文覆盖不作保证。[Search API](https://openlibrary.org/dev/docs/api/search) |
| Google Books | 可按标题、作者、ISBN 查询；配置 API key 与网络后使用，不作为下载前置条件。[官方 API](https://developers.google.com/books/docs/v1/using) |
| Calibre 元数据插件 | 作为已配置插件的可选接入，支持标题、作者、ISBN 与封面/OPF 输出；插件可用性按安装版本检测。[官方 CLI](https://manual.calibre-ebook.com/generated/en/fetch-ebook-metadata.html) |

中文元数据不足时保留书源资料并允许编辑，不默认假定有稳定免费豆瓣 API。明确匹配后自动补空字段；用户修改过的字段保持人工优先。候选不明确时展示差异，由用户点选字段，下载与追更继续进行。

字段包括标题、副标题、作者、译者、简介、封面、语言、分类/标签、系列与序号、出版社、出版时间、ISBN/外部标识，以及网文状态和来源。ISBN 是版本属性；没有 ISBN 的网文使用内部标识，不填假 ISBN、不把系列编号当 ISBN。每项保留来源、来源值、更新时间和人工覆盖。

## EPUB 与 NAS 整理

章节内容统一为稳定章节/段落 ID 的 XHTML，保留卷层级、图片和必要注释；正文使用明确编码，广告清理使用来源规则和可预览的替换，不依赖大模型改写原文。TXT 识别编码及章节标题，自动判断不可靠时允许调整分章规则并预览；原件保留。

标准章节和 HTML 目录直接构建 EPUB 3；本地文件的格式转换优先调用已选定版本的 Calibre `ebook-convert`，复用其转换能力，不以改后缀代替转换。EPUB 导入保留已有结构，修改资料后重新打包；PDF 的版式转换和扫描 OCR 不纳入本轮常规输入，后续单独设计。[Calibre 转换工具](https://manual.calibre-ebook.com/generated/en/ebook-convert.html)

EPUB 包含正确的 `mimetype`、`META-INF/container.xml`、OPF 元数据/manifest/spine、导航目录、章节 XHTML 和本地封面/插图。验证结构、资源引用、目录顺序与缺章声明，使用 EPUBCheck 验证代表性产物，并在常用阅读器中实际打开；校验不只是 ZIP 能解压。[W3C EPUB 3.3](https://www.w3.org/TR/epub-33/)

目标沿现有媒体目录配置，建议布局为 `书籍/<作者>/<书名> [短ID]/book.epub`，同目录保存 `cover.jpg`（存在封面时）、`metadata.opf` 与不含会话信息的 `source.json`。真实挂载路径由部署设置给出，文档中的布局不是已经存在的 NAS 路径。

同一 `edition_id` 保持稳定成品路径；用户修改标题不会在下一次追更中悄悄移动目录，整理移动是独立操作。章节缓存进入受管工作区，按内容摘要复用；原始导入文件、受管成品与外部原位文件分别登记。先在同一文件系统暂存、验证，再原子发布；失败保留旧成品，复用现有保留与恢复机制。

EPUB 正文 ID、内容修订与来源映射为以后 Fish Audio 分章生成、音文同步和 AI 共读提供定位。当前任务只设计书籍内容获取和整理，尚不触发 TTS 费用，也不把整本小说写进人物记忆。

## 开发顺序与验收

按完整功能串行推进：先完成书源导入和引擎适配、聚合搜索与真实章节预览；随后接入同一下载中心的首次下载与增量追更；再完成元数据书库连接、EPUB 成品及整套网页。全部属于首个书籍订阅功能的交付范围，不以单独完成导入或静态页面宣称功能完成。这里没有创建或占用 TS 任务号。

重点验收：混合有效/失效规则集合导入与失败更新保留；CSS/JSON/XPath/脚本及分页样本的明确兼容结果；多源部分失败和同名不同作者；实际正文预览；1000 章目录分页与断点恢复；重复订阅不重复下载；新增/修订/缺章和换源映射；人工元数据不被覆盖；有效 EPUB 实际阅读；NAS 目标失联/空间不足/发布中断后旧成品可读；未配视频仍可用书籍；视频和音乐任务不受新分流影响。优先使用自建夹具和公开可访问样本，真实来源成功与隔离样本成功分别记录。
