## 1. 这次收敛的结论

保留五个主要工程单元：**天枢平台、陪伴核心、天枢记忆、模型运行网关、NoneBot 接入层**。每个单元内部按业务模块组织；模块框不是微服务数量，也不要求五台机器。数据库、队列和文件存储先复用现有基础设施，成熟外部软件继续承担自己的职责。

网页成为统一入口，包含文字陪伴、动态小屋及管理功能。实时语音通话和共同观影退出网页页面、默认导航、首期浏览器权限和媒体运行依赖；历史效果图仅保留为**可选独立陪伴客户端**参考。这不删除 QQ/TG 的语音消息识别和可选语音回复，也不要求现在新写一个客户端。

核心原则是“同一件事只有一个权威写入者”：角色的此刻状态由陪伴核心决定；人物与记忆由记忆系统管理；项目运行与设备操作由平台协调；文件由 AssetLibrary 管理；原始消息由 Chat Audit Core 保管。网页、任务中心、星图和模型提示词读取这些状态的投影，不能各自维护另一套事实。

## 2. 网页信息架构与视觉如何落地

主导航按使用目的组织，二级页面在所在工作区内切换。移动网页重新组织阅读与操作顺序，不将整张桌面缩小。25 张补全图包含流程和历史客户端参考，不代表需要 25 个一级菜单。

| 工作区 | 页面与主要行为 | 数据责任方 | 视觉组织 |
| --- | --- | --- | --- |
| 工作台 | 今日事项、角色近况、待处理任务、设备异常 | 平台聚合其他责任方投影 | 安静的摘要与时间线，重点异常优先 |
| 陪伴 | 文字对话、角色概览、人格、共享世界 | 陪伴核心；人物资料引用记忆 | 角色上下文持续可见，管理字段折叠 |
| 小屋 | 床与闹钟、窗灯帘、衣橱、书架、日记入口 | 陪伴核心；图片与附件引用资产 | 场景为主、操作浮层为辅，提供普通列表操作入口 |
| 记忆 | 人物、群画像、账号关联、记忆星图、纠正、召回检视 | 天枢记忆 | 紧凑主题簇 + 可读详情，渐进加载，禁止全量图谱一次注入 |
| 资料与资源 | 研究资料、搜索、资产库、订阅、下载归档 | 资料归记忆；资产归 AssetLibrary；订阅下载归平台 | 资料用列表与阅读区，图片用画廊，整理用对照与计划 |
| 家庭与服务 | Home Assistant、NAS/路由/节点、容器、游戏服、身体趋势 | 外部系统原始状态；平台映射与操作 | 清楚显示来源、新鲜度、待确认和失败原因 |
| 项目 | 仓库、任务、工作目录、文档、交接、经验 | 平台 + Git；记忆提供检索 | 项目任务与变更优先，短交接可展开追溯 |
| 任务与设置 | 各类任务、通知、模型线路与用量、连接器、系统偏好 | 平台；任务执行状态由各责任方提供 | 任务进展与服务健康使用不同字段，不混成一颗状态灯 |

日记和创作是小屋内物件可打开的独立阅读/编辑视图，不需要在场景中完成所有操作。模拟日记的密码/访问决定由核心保存，前端不能下载全文后只盖一把锁；管理者的后台访问权与角色关系剧情分别说明，不把虚构好感当系统管理员权限。

采用已有低饱和银蓝、淡紫、少量浅粉的材质方向。毛玻璃主要用于导航、浮层和场景操作；正文使用较实的乳白/深色可读面板。圆角、间距、字体、焦点与状态色从一份设计令牌产生，先提取当前原型的实际值，避免另抄一份冲突配色。没有业务信息的装饰卡片不扩展为后端模块。

Docker 沿用 A 细轨：蓝色表示已知运行且无已知故障，黄色表示处理中或待核对，红色表示已确认异常，灰色表示停止、暂停或不可用；文字仍分别标明未知与停止。“运行中”和“健康检查通过”是两条独立状态，选中高亮不覆盖状态轨。其他任务页面沿用色彩语义，但使用任务自己的状态名称。

动效服务于状态变化：列表重排、抽屉切换、进度更新可轻缓过渡；不制造假的活跃波形。支持键盘焦点、减少动态、加载/空/离线/部分失败、深浅主题。小屋之外的工作区不常驻启动 WebGL；重场景、星图和长列表按需加载，截图不是性能验收。

## 3. 五个工程单元与内部模块

### 3.1 天枢平台

内部模块：管理会话与简单角色权限、连接器配置、提供商配置、项目工作区、设备运维、订阅下载、任务与通知投影。平台为网页提供同源 API 聚合入口；对记忆、房间、日记等写操作转交各自服务，并保留原始错误与版本信息。

平台不介入每一条 QQ 闲聊的关键路径。陪伴核心可以直接访问记忆与模型网关。明确的网页开灯按钮不先让模型“理解一下”；聊天中的“打开卧室灯”需要解析目标后调用同一能力执行者。

任务中心存 `(owner, job_id)`、面向用户的摘要、阶段、事件游标和链接。各责任方保存完整任务与重试状态，取消也转给该责任方。平台通知记录投递结果与去重键，角色是否主动分享由核心的参与规则决定。

### 3.2 陪伴核心

核心独立于 NoneBot，以 API、事件和能力接口连接它。初期以一个模块化后端和后台工作进程实现，下列模块不各自部署：

| 模块 | 职责与主要输出 |
| --- | --- |
| 事件入口与对话调度 | 标准事件、防抖收集、封存、两轮并发、明确取消、按序发送 |
| 参与与关系表达 | 是否回应/主动联系、群内话题与对象、关系尺度、冷却；持久关系读记忆 |
| 角色与世界 | 人格版本、世界设定、当前世界/房间、角色已知范围引用 |
| 生活状态 | 日程、活动、短期心情、当前穿搭、目标与待办，时间驱动和事件驱动更新 |
| 上下文装配 | 选取本轮所需状态、完整语义记忆块、工具能力和版本快照 |
| 表达与行动 | 生成回复、能力调用、任务关联、结果表达，限定调用次数与时间 |
| 写作与创作 | 日记、作品、写作配方、证据素材包、草稿与发布版本 |
| 场景协调 | 灯窗帘等物件状态、手动保持、自动恢复、前端状态增量 |
| 提交与后台整理 | 回复与动作记录、状态变更、可供记忆提炼的事件；不阻塞普通发言 |

“像一个人”来自有因果的连续状态：今天有何计划、刚发生何事、当下能做什么、对方是谁、什么值得主动联系。不能靠每分钟让大模型随意写一段生活；也不把一条情绪化生成直接变成永久好感。关系变化有来源、限幅、幂等键，稳定人格只有明确的编辑或演化流程才能改写。

共享世界不等于全知角色。世界事件标明参与者、可见者与获知途径；角色 B 没在场时，只有在获准收到通知或听 A 讲述后才获得该经历。模拟生活属于虚构事件，现实用户事实来自真实对话/设备证据，两者不能互相伪装。

### 3.3 天枢记忆

内部包含人物登记、关系/画像、情境与事项、检索投影、资料库及索引任务。人物 ID 由记忆模块签发并保持稳定；外部账号使用平台命名空间和不可变账号标识绑定，群昵称与头像仅作展示。

稳定 ID 配合数据库索引可以减少重复匹配和关联查询，但它本身不会降低模型生成耗时；实际速度仍取决于批量查询、缓存有效性和返回内容大小。

长期聊天原文由 Chat Audit Core 保存，记忆只保留引用、提炼结果和版本。资料库保存来源记录、版本、解析结果、完整语义单元和研究笔记；大附件或纳入资源库的文件通过 AssetLibrary 的资产引用取得，资料整理不直接移动 NAS 文件。

记忆是查询服务，也是带修订语义的数据服务。新事实、否定、更正、遗忘与范围改变不能只更新向量库；权威记录先提交，查询按当前版本过滤，后台再重建索引。缓存、引用片段和日记素材也必须失效或重新授权。

### 3.4 模型运行网关

平台管理服务地址、凭据引用、模型目录、能力验证状态，以及对话/写作/记忆提炼/视觉/嵌入等功能绑定。网关执行请求、并发限制、超时、流式传输、用量记录和明确的兼容回退。

内部功能选择绑定模型；接入网关的外部 Codex/Hermes 客户端则保留其选择的模型、原生协议与思考字段，除非该线路有显式映射。不靠统一成最低功能接口解决兼容问题。模型列表可见不代表图像、工具、推理参数已经验证可用。

有状态响应引用与会话保持上游黏性；不能把一段流跨接两家，也不能在工具执行结果不明时盲目重放。向量集合固定嵌入空间，改模型需迁移/重建；维度相同不代表语义空间兼容。价格或用量未知就标未知。

### 3.5 NoneBot 接入层

负责 NapCat/OneBot11 与 TG 适配、标准消息包、发送回执、附件引用、连接状态，以及明确指令的分流。核心作为独立服务接入，NoneBot 内只安装薄桥接插件与需要的直接功能插件。

群管理与 GsCore 的明确命令可以独立执行；自然语言工具调用复用这些执行入口。同一条事件有唯一回复责任方，不允许插件与陪伴核心抢答。独立功能不依赖核心推理，但若共用一个 NoneBot 进程，仍共享进程故障和资源，不能宣称完全隔离。

## 4. 数据归属与最少必要边界

| 权威对象 | 唯一责任方 | 其他系统如何使用 |
| --- | --- | --- |
| 人物、账号关联、群画像、长期关系 | 记忆 | 核心/网页按范围读取选定字段；头像缓存有更新时间 |
| 人格、世界设定、当前世界、房间与角色状态 | 核心 | 网页渲染；记忆索引历史事件及获知关系 |
| 会话轮次、发送记录、正在进行的承诺动作 | 核心 | 平台任务投影；记忆保存可检索事项与已完成事实，取消以核心当前执行状态为准 |
| 原始聊天 | Chat Audit Core | 核心保有恢复所需的短期收件记录；长期证据通过归档引用取得 |
| 画像原子项、经历、已整理事项、检索版本 | 记忆 | 核心、项目工具按请求范围查询 |
| 来源、研究笔记、知识索引、入库任务 | 记忆 | 网页阅读，核心检索；源文结论/推论/项目决策分开 |
| 作品内容版本、日记访问决定、衣橱穿搭关系 | 核心 | AssetLibrary 保管媒体文件；知识模块仅按需索引可见作品 |
| 资产 ID、受管文件位置、元数据、归档执行 | AssetLibrary | 平台提出计划、下载器交付暂存文件、核心引用图片 |
| 提供商配置与功能绑定 | 平台 | 网关读取版本化配置与凭据引用；网页只见脱敏值 |
| 模型请求与真实使用记录 | 模型网关 | 平台汇总展示，未知字段保留未知 |
| 项目登记、任务、工作目录、当前交接 | 平台 | Git 保存已版本化文档；记忆仅索引和生成短恢复包 |
| 设备/容器实际状态与操作结果 | 对应外部系统 | 平台缓存带新鲜度的投影，命令回执与观测结果区分 |

同一台 PostgreSQL 可按产品分 schema/用户复用，物理共址不允许跨模块随意写表。初期先用关系数据、全文和已有合适向量索引，不强制增加图数据库、Kafka、服务网格或分布式事务。关系网络可以由有明确边的关系表形成。

只保留必须的安全边界：管理员登录身份、聊天人物与虚构角色分别编号；连接器凭据留在服务端；调用检查实际请求人、目标和能力范围；群/私聊信息范围在取数据前确定。好感度决定表达风格和剧情访问，不能授予删除 NAS 文件或重启路由的权限。

个人常用操作可配置简明默认权限。新容器部署、覆盖/删除文件、大范围网络变更先产生可审阅的具体计划，再确认一次；不用把每次查状态、开灯或复述结果都变成审批流程。网页、导入文件、检索资料和模型输出都不能给自己扩大工具权限。

## 5. 一条消息如何运行

1. NoneBot 接收事件，生成稳定去重键，保留作者、平台消息 ID、时间、引用、顺序和媒体引用。原文独立送入/接入 Chat Audit Core；归档暂不可用时不阻断闲聊，但记录待补档状态，不虚报已永久保存。
2. 明确功能指令先分流。普通对话按会话与回复目标收集，群聊还保留参与者与话题线索；不同人的消息不能揉成“某一个人说的一句话”。
3. 有效续句重置自定义静默窗口，默认示例 5 秒；没有默认强制最长等待上限，用户另行启用才使用。封存为有序消息组后进入处理链。
4. 每个逻辑会话最多两轮活跃陪伴处理，多个角色共享此限制。T1 封存后新消息进入 T2 收集，T2 窗口结束即可准备/生成；不因普通新消息取消或重做 T1。多出来的封存轮次进入有容量上限的队列，满时使用明确的等待/溢出策略，不能静默丢弃。
5. 核心确定本轮参与者、受众、请求人能力、角色和世界版本，装配当前话题与少量状态。每轮检查范围和版本，但历史召回按实际需要发生。
6. 无工具的普通聊天原则上一次主要生成。工具、查资料、自拍等按需展开；只在相关步骤使用额外模型，不固定叠加规划、审计、反思三次请求。
7. T2 可与 T1 并行，但依赖 T1 的“那就这样做”要等待具体依赖结论。T2 在最终提交前核对已承诺回复/状态版本；只有真实冲突的依赖片段需要更新，不能抢先产生相反承诺或重复操作。
8. 发送按会话轮次有序，媒体生成等长任务可先回执再异步回报；生成快不等于可以超车发出。网络回执不明时标记未知并核对，不能靠重发保证“恰好一次”。
9. 提交轮次状态与后台整理事件。明确的取消/撤回/“已经完成”走及时更新通道，使过期主动关心和待执行动作失效，不能等晚间写日记才反应。

真实响应时间 = 防抖等待 + 排队 + 状态/召回 + 模型与必要工具 + 有序发送等待 + 渠道时间。此前自有开销 p95 500ms 只作为待测目标，不是已验证性能。记录各阶段分布，先减少串行往返与无效召回，再考虑拆服务。

## 6. 记忆与资料怎样保持小而完整

查询返回的是本轮最小充分证据，不是完整人物简介。稳定身份投影、群场景风格、关系表达尺度、当前事项与历史证据分别选取。没有相关画像就返回零项；一个兴趣命中不展开整个人物。

每个单元必须包含改变含义所需的条件、否定、时间、主语、来源和不确定性。例如“晚上不喝咖啡，白天偶尔可以”不能切成“喜欢咖啡”。有相互依赖的单元作为语义组保留；预算不够时换为经验证的完整短表述，或整组不取，不能截掉否定来凑 token。

范围过滤先于召回；群聊请求不进入私聊专属证据。公开兴趣可以拥有显式可共享的脱敏事实投影，私密原始经历仍不外泄；本人私聊可识别并回答自己的相关事实。在群里不适合展开时使用自然的保留表达或转私聊，避免用错误的“不认识/不知道”掩盖范围限制。

请求一次批量返回字段与证据，同时附 `record_version`、来源、有效期/范围版本、实际 token/字节和排除原因。缓存键包含角色、人物、受众、会话/项目范围及版本，不能只用 query 文本。原子项数量与预算值可配置并通过样本调节；旧稿数字是演示起点，不是本次冻结上限。

资料流程为：网址/文件/研究中实际采用的来源 → 获取与版本记录 → 解析 → 保留完整语义的片段 → 研究笔记 → 可引用资料。自动研究仍保留来源与查阅时间，搜索结果标题不能直接变成“证据证明”。只保留实际阅读、引用或明确选中的来源，不默认保存每个搜索命中。

Codex/Hermes 通过 MCP/适配器读取项目短恢复包、定向检索、写研究笔记和经验；接上 MCP 不会自动捕获它们所有原生浏览和文件操作，需要对应工具包装、事件钩子或明确写回。被本机实际写入的资料目录仍需正式导入任务，不能宣称已经进入线上记忆库。

## 7. 小屋、日常、写作与图片共用一条生活链

核心保存 `actor_state` 与 `room_state` 的版本，房间不是每个浏览器的私人副本。日程推动活动，例如“准备阅读”生成活动变化，可提出开台灯；手动保持中的台灯不会被自动覆盖。角色回答、今日穿搭、自拍请求和日记素材读取同一版实际状态。

小屋服务端保存时间基准、窗开度、纱帘/遮光帘开度、灯具状态、手动/自动模式和变化起点。浏览器按这些参数插值计算帧；关网页后生活与日程继续，重新进入读当前状态，不补播整晚动画。时间预览只在本地预览，不改变真实状态或触发日记、提醒。

推荐先做 **Three.js 正交相机、固定视角轻量 3D** 的环境验证：保留 2.5D 视觉，但让窗框、灯具、家具遮挡有可计算几何。正交投影能避免物体因离相机远近而在画面上缩放，适合固定视角场景；最终是否采用仍取决于真实资产、风格和终端表现。[Three.js 正交相机文档](https://threejs.org/docs/pages/OrthographicCamera.html)。

首个样片只做一扇窗、两层帘、两盏独立灯、桌椅与一个角色姿态，验证白昼变化、局部照明、遮挡、风摆衰减、手动保持和手机性能。与现有 2D 候选对照后选一条主线，不同时常驻 Phaser、Pixi 与 Three.js。动态阴影、透明材质和角色资源都需要预算，不能靠一张概念图判断。[Three.js 阴影文档](https://threejs.org/manual/en/shadows.html)。

窗户关闭仍可透光，窗帘拉合影响光照与遮挡，外来风随开窗程度变化，关窗后逐渐衰减。昼夜以设定时区为基准，真实天文模式还需地点/窗向；天气预设不能冒充实时天气。减少动态时仍显示正确的物件状态。虚构小屋与真实 HA 设备使用不同命名空间，只有显式映射才能联动。

衣橱保存衣物描述、参考图、可用生成参数和适用活动；核心决定今日 `outfit_id`。ComfyUI 连接器映射已审查的本地 Anima 工作流版本、允许修改的节点与约束，保留角色/画师/LoRA 固定部分，同时支持完整工作流模板和有类型参数；不让用户一句话任意执行节点文件操作。NAI/GPT Image 作为不同能力后端，不假装节点级等价。

自拍任务读取穿搭、当前活动与场景引用后进入 GPU 队列。GPU 离线可等待/取消/显式换后端，普通聊天继续。小屋角色动画需要对应模型、骨骼或分层素材；一张 Comfy 图片不自动变成可换衣服的动画角色。没有兼容小屋资产时显示真实可用表现并说明，不能让房间穿 A、自拍穿 B 而都标作同一套实时外观。

写作配方由核心版本管理，至少包含素材依据、叙述视角、文风、禁止捏造的事实、篇幅和质量检查。日记使用当天有意义事件与角色感受，允许想象性表达但不编造现实用户行为；素材不足可以写短或略过，不强凑满页。长篇作品维护大纲、人物/伏笔约束和章节摘要，每次取相关局部，不把全书逐轮塞入。生成草稿与正式发布版本区分，修订保留来源关联。

## 8. 其他能力的真实执行路径

| 需求 | 执行路径 | 完成的判断 |
| --- | --- | --- |
| GsCore/群娱乐 | 明确指令 → NoneBot 功能入口；自然语言 → 核心 → 同一桥接入口 | 获取实际插件结果，由单一责任方回复 |
| 上网/推送 | 核心意图或订阅 → 平台搜索/RSSHub连接器 → 记忆资料整理（按需） → 核心决定分享 | 来源可追溯，推送去重，有时效和联系冷却 |
| 漫画/小说/音乐/视频 | 平台聚合来源 → 下载器暂存 → 校验 → AssetLibrary 归档 → Komga 等刷新 | 下载完成、文件归档、资产索引、阅读器索引分别显示 |
| 照片/动漫图/表情包整理 | 平台提交整理目标 → AssetLibrary 只读扫描 → 本地查重/特征 → 少量视觉疑难判断 → 归档计划 | 原始文件、近似版本、动画/附属文件的关系保留；优选不等于删除 |
| 智能家居 | 网页明确操作或核心意图 → 平台 HA 连接器 → HA 服务 → 观测状态 | 发出命令不等于设备已执行；离线、乐观状态、旧状态有标识 |
| NAS/路由/远程节点 | 平台连接器/节点代理 → 受限查询与已登记动作 | 逐设备能力和采样时间；断连不是 CPU 0% 或已停机 |
| Docker/Dockge | 平台部署计划 → 唯一 Compose 配置写入者/执行连接器 → 容器运行时 | 端口目录等先审阅；部署、运行、健康检查结果分开 |
| MC/其他游戏服 | 平台登记实例 → 管理连接器 → 开停服/白名单命令；后续模组扩展 | 停服、保存世界、备份分别确认；记录执行结果 |
| Notify/手环 | 已验证的手机桥/HA 导入 → 平台健康数据视图 → 核心获准的关心 | 逐字段来源、可用性与时间；趋势不是诊断，型号能力待核对 |

平台不假定 Dockge 已有稳定 REST API，也不绕开其配置管理随意改同一份 Compose。HA 的实际设备动作使用服务调用，不能写状态表冒充控制。[Home Assistant REST API](https://developers.home-assistant.io/docs/api/rest/)。

资源整理成本由“本地处理数量、需视觉判断比例、分辨率/批次、模型线路”决定；先生成用量估算与队列预算，增量缓存避免重复分析，当前没有真实 NAS 数据集成本成绩。ComfyUI 的本地 GPU 成本与外部模型 token 分别显示。

## 9. 项目、文档与编码体协作

登记仓库、所在主机、工作目录、默认分支和已有文档。一个并行任务一个独立工作目录/worktree；跨主机使用各自检出，不能让多个编码体同时操作 NAS 上同一份可写 Git 索引。共同管理的是仓库历史、任务与约定，不是强制共享一个正在修改的目录。

项目页保留精简的当前状态：目标、约束、最近验证、未完成步骤、必要引用。完整设计与交接文件在 Git 版本化，旧交接归档；记忆按版本增量索引，恢复时返回短摘要与按需原文。后台记忆不能覆盖当前工作树中尚未提交的事实。

踩坑先归项目，有明确触发条件、症状、原因、修正和验证；跨项目重复且证据充分的经验才晋升总错题本。不把每段失败日志永久贴进总提示词。接入规范需要 Codex/Hermes 等客户端合作遵守，不能保证绕过天枢操作时仍自动捕获每个细节。

## 10. 通信接口、状态和恢复

[接口目录](v2/interface-catalog.json) 是拟议契约，不是已经存在的 URL 清单。初期内部 HTTP JSON 处理查询和命令，网页以 SSE 为常见任务/状态订阅候选；确需双向连续交互时再采用 WebSocket。模型流走原生流式接口，不塞进业务事件格式。

公共标识包括 `request_id`、`event_id`、`person_id`、`actor_id`、`world_id`、`conversation_id`、`turn_id`、`asset_id`、`project_id`。管理调用另有认证主体 `principal_id`；人名、群名、文件路径不充当跨模块唯一身份。

命令包含 schema 版本、调用来源、目标、幂等键、预期对象版本和时限；需要授权的身份由服务器认证结果填入，不相信浏览器或模型自己声称的管理员字段。结果区分已受理、执行中、成功、部分失败、失败、取消、状态不明。外部系统无法保证幂等时，连接器必须保留“未知结果”并支持核对。

业务事件用于已发生事实，如状态改变、任务阶段、记忆修订。责任方事务内写业务状态和 outbox；消费者按事件 ID 去重，处理乱序/版本缺口，必要时重取快照。至少一次投递是实现目标，不能声称全链路恰好一次。早期可采用数据库持久队列和轮询，已有队列可复用；不先为了统一总线引入复杂集群。

网页订阅丢失时按游标恢复；游标过期或有版本缺口就重取快照。状态包含 `observed_at` 与来源，缓存超期显示未知/过期。前端乐观修改只能显示“正在提交”；服务端冲突返回最新版本，不让两个浏览器静默覆盖。

### 主要故障的预期表现

| 故障 | 对用户的行为与恢复 |
| --- | --- |
| 模型超时 | 当前轮报告失败或采用已配置的兼容回退；不重复已执行工具 |
| 记忆服务不可用 | 使用仍能验证范围/版本的基础状态，或说明暂时无法核对；不使用无法验证的私密旧缓存 |
| Chat Audit 不可用 | 短期可靠收件记录待补档；网页标明归档缺口，核心继续可用的对话 |

| 平台不可用 | QQ 核心闲聊可直接走记忆与网关；已配置直接指令按自身依赖工作，网页和平台操作不可用 |
| 核心重启 | 从持久轮次/动作状态恢复；先核对发送与工具结果不明的记录，不无脑重放 |
| NAS/资产服务离线 | 文件不可读取/待归档有明确状态，不编造整理成功 |

## 11. 工程组织与家庭部署建议

建议保留产品级仓库边界：平台（含网页）、陪伴核心（含薄 NoneBot 桥接包）、记忆、模型网关；NoneBot 作为独立运行进程，桥接包不因此必须单独建仓库。已有外部项目保持自己的仓库。公共契约使用小型版本化目录/包与兼容样例，不建一个包含全部业务逻辑的“公共核心”。

新 Python 后端可采用 FastAPI 异步入口配后台任务，复用旧项目适合的组件；前端推荐 React/TypeScript 模块化工作区，小屋渲染按需加载。具体版本在实现前锁定，不在设计阶段安装一批框架。异步 I/O 不会自动让 CPU/GPU 重活变快，重活由有界工作队列承担。[FastAPI 并发文档](https://fastapi.tiangolo.com/async/)。

| 设备/环境 | 候选职责 | 条件 |
| --- | --- | --- |
| Ubuntu 笔记本或另一台稳定常开主机 | 平台 API/工作进程、核心、记忆、网关、NoneBot | 先确认常开、电源、实际资源与依赖；不是要求五台机器 |
| 群晖 NAS | 文件库、备份；按资源承载数据库、Chat Audit、AssetLibrary、Komga 等 | 具体型号与现有负载未核定，不能承诺吞吐或所有服务都适合放 NAS |
| 当前 Windows 生图笔记本 | ComfyUI、GPU 工作流与开发环境 | 睡眠/离线可排队；不能成为普通聊天的必要依赖 |
| 浏览器/平板/手机 | 网页操作和本地场景渲染 | 小屋质量按设备调整，隐藏页面暂停高频绘制 |
| HA/游戏服/远程节点 | 各自原生服务与必要连接器 | 放置按已有部署决定；未确认已安装/已连通的能力不标完成 |

对话、后台研究/记忆、下载/资产分析、GPU 生图分开限流和排队，配置小而明确的并发与预算。初期不做通用分布式调度平台。记录首字时间、完整回复时间、各队列等待、召回预算、外部调用结果和实际用量，并注意日志脱敏。

备份覆盖权威数据库、原文、资产文件、Git、必要凭据恢复材料；索引可重建但不是备份替代。删除/遗忘的标记与恢复流程一起设计，旧备份恢复后重新应用删除记录，不能让已撤销的私密资料重新进入召回。旧系统正式迁移前仍是它自己的生产事实来源。

## 12. 按完整目标拆开发，而不是边做边发明边界

先冻结职责和对外契约，再以可演示的贯通能力开发；不一次写完全部框架。视觉认可转为组件和真实状态之前仍有验证工作。

| 阶段 | 交付边界 | 验收门槛 |
| --- | --- | --- |
| A：原型与契约 | 当前 V2 总稿、公共标识/契约样例、页面壳与一个小屋环境样片 | 原型覆盖核心交互/失败状态，小屋选定主渲染路线，已有项目能力盘点可复现 |
| B：最小陪伴贯通 | QQ + 一角色 + 记忆 + 模型绑定 + 防抖两轮 + 网页文字/状态查看 | 本节 A01–A06 通过；重启与重复事件不会乱发或重复执行 |
| C：生活与多角色 | 共享世界、日程、衣橱/自拍、日记、小屋、主动关心 | A07–A09 通过；状态一致、来源可追溯，GPU 离线不阻塞闲聊 |
| D：平台能力与资产 | HA、GsCore、任务中心、订阅/下载、AssetLibrary、容器/节点/游戏服 | A10–A12 通过；真实回执、部分失败与归档边界正确 |
| E：项目与扩展 | Codex/Hermes、资料自动沉淀、项目经验、TG/其他角色与可选连接器 | A13–A15 通过；角色/平台范围与协议兼容真实验证 |

TG 与项目接入若优先级提高可提前做，不改变责任边界。可选实时通话/观影客户端单独排期，不成为上述网页和核心的验收依赖。此处阶段是建议，没有编造开发工期；协议兼容、小屋资产和现有项目写入接口是主要不确定工作。

### 替换旧系统的迁移边界

先登记各项目当前版本、生产数据、实际写入者与接口缺口，再用脱敏样本验证契约。角色、人物、原文、资产和项目分别迁移并建立旧新 ID 映射；完整备份与恢复演练之后，新系统先做只读对照。切换时按责任对象停止旧写入者，再启用新写入者，避免两边同时改同一份状态。

回退方案要覆盖新系统已经写入的数据，而不只是把网页地址切回去：保留变更日志、可兼容导出和核对步骤；不可自动回退的变更明确列出。旧系统在实际切换与恢复验证前不删除，本设计也没有触发迁移。

### 主要难度与提前验证项

| 范围 | 相对难度 | 最先证明什么 |
| --- | --- | --- |
| NoneBot 接入与明确指令 | 中；协议有复用基础 | 事件身份、附件、回执、唯一回复责任是否正确 |
| 陪伴状态与双轮对话 | 高 | 并行轮次的因果依赖、发送顺序、重启与动作恢复 |
| 记忆与资料 | 高 | 最小语义召回质量、隐私范围、更正失效与索引延迟 |
| 动态小屋 | 高，素材工作占比大 | 真实遮挡/灯光/角色风格与移动端成本，先做样片 |
| 模型网关 | 中到高 | 多原生协议、思考参数、工具流和有状态切线路 |
| HA/GsCore/RSSHub 等连接器 | 逐项中等 | 复用真实接口，能力差异和失败回执 |
| 资源归档与旧系统迁移 | 高 | 唯一文件写入者、可审阅计划、恢复和索引一致性 |

难度等级是对本需求的工程判断，不是工期估算。可以复用现成连接器降低接入成本，但无法省去陪伴一致性、小屋素材和真实数据迁移的验证。

| 编号 | 需要实际证明的行为 |

| A01 | 同一账号群私聊保持同一人物；不同平台不会仅凭昵称自动合并 |
| A02 | 私聊秘密不能在群召回中出现；允许共享兴趣可用；否定/条件不因切块丢失 |
| A03 | 5 秒内的续句重置等待，封存后新消息形成第二轮；第三轮排队，有序回复 |
| A04 | T2 在 T1 未发完前开始可独立工作；依赖 T1 的动作不会抢跑、重复或互相矛盾 |
| A05 | 普通闲聊只做必要模型调用；更正/遗忘在旧缓存和旧向量候选存在时仍生效 |
| A06 | 直接 GsCore/群指令由唯一处理者响应；核心不可用时按独立依赖继续执行 |
| A07 | 两个浏览器/多个角色看到同一房间状态；预览时间不改变真实状态；手动保持有效 |
| A08 | 开窗、关窗、两层帘与灯独立联动，关窗后风摆衰减；移动端与减少动态可用 |
| A09 | 日记、台词、穿搭与自拍读取一致状态；虚构经历不会记成用户真实行为；日记未授权时前端无全文 |
| A10 | HA 回执不冒充设备执行；未知容器健康不显示健康；部署部分失败能定位与恢复 |
| A11 | 近似图片、动画、原图/修订版不误删；资源整理可审阅，AssetLibrary 才发布受管目录 |
| A12 | 下载/归档/各索引阶段分开；事件重放不重复发布文件或推送通知；任务取消回到执行方 |
| A13 | 两编码体在独立工作目录接续同一项目；短恢复包可追溯当前版本；大文档增量索引 |
| A14 | 来源、推论与项目决策可区分；更换嵌入模型需迁移；外部模型字段不被静默改写 |
| A15 | 网页无实时通话/共同观影入口及权限请求；文字、小屋、QQ/TG 语音消息边界各自正确 |

本次只完成架构与契约设计的静态一致性检查，不把上述业务验收写成已通过。旧代码的复用结论参考固定提交的 [源码核对](../product/forgejo-source-review-2026-09-12.md)，正式实现前还需核实当前代码、运行环境和迁移数据。
