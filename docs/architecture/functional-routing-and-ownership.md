# 功能命令、陪伴对话与平台任务的分流

日期：2026-09-13。本文澄清现有目标架构中的执行路径，尚未完成插件移植或真实平台联调。用户已确认同会话陪伴对话最多两个处理轮次；这个上限不覆盖全部机器人功能任务。

## “中枢”的两种含义

天枢平台负责设备、资料、项目等业务以及统一配置界面。陪伴核心负责人格、对话、日程、情境和自然语言能力选择。群管理与 GsCore 的直接功能命令可以同时绕过这两个服务，由 NoneBot 的对应插件或桥接器完成。

自然语言请求仍可从陪伴核心调用这些能力，但实际执行者保持同一套。这样“使用指令”和“直接跟角色说话”是不同入口，不产生两份业务实现和绑定数据。

## 三类主要路径

| 路径 | 经过哪些组件 | 功能与结果由谁负责 |
| --- | --- | --- |
| 明确的群管理指令或已配置群规则 | 平台消息/事件 → NoneBot 分流 → 群管理插件 → 平台适配器 | 群管理插件校验发起者与机器人权限，执行支持的操作并返回真实结果 |
| 明确的 GsCore 命令 | 平台消息 → NoneBot 分流 → GsCore 连接插件 → GsCore | GsCore 保留游戏业务与账号绑定；连接插件负责协议与结果投递 |
| 自然语言陪伴及能力请求 | 平台消息 → 陪伴防抖/双轮次处理 → 陪伴核心 → 对应能力入口 | 核心理解意图，功能执行者处理动作；结果按本次回应负责方返回 |

自然语言能力请求还要按实际功能分流：群管理去群管理插件；游戏功能去 GsCore 桥接；NAS、下载归档和项目任务去天枢平台。不能因为某项能力可以通过聊天调用，就要求它的所有请求都经过天枢平台。

直接命令是否走快速路径，应以已经注册、完整匹配、参数明确的命令为准。建议这类命令不等待陪伴聊天的静默窗口，也不占用两个对话处理槽；自然语言和未完成的含糊请求仍走陪伴链。具体命令语法、支持平台和参数需按接入的插件验证，不把“包含某个关键词”当作命令匹配。

## 统一入口如何避免抢答

NoneBot 的消息接入先完成规范化、原消息定位和基础分流。一个明确的功能请求交给一个执行负责方；已经由原生插件受理的命令，不再作为新的闲聊请求送给模型，也不能被第二个桥重复执行。

原文归档、必要观察和已配置的群规则可按各自职责接收事件，但不因此各发一份答复。混合多个请求的自然语言保留原消息结构，由陪伴核心统一理解与分派；不做“插件先执行一次，模型再猜一次”的并行双重派发。

功能调用应复用插件中的执行函数或薄服务接口，携带可信的发起者、目标会话、请求编号和参数。不要通过伪造用户消息、重新投回消息总线来触发插件，这会混淆来源、计时器和执行次数。现有插件如果仅暴露命令回调，移植时先提取必要执行部分，不复制全部插件框架。

## 两种入口共用执行与权限

无论命令入口还是陪伴工具入口，群管理插件都要校验真实发起者是否有权操作、机器人是否拥有对应群权限、目标平台是否支持该动作。人格、好感度或模型输出“同意执行”都不能替代这些检查。

GsCore 的用户绑定按可信平台账号上下文查找；天枢的人物索引可以关联认识，但不取代 GsCore 的业务绑定库。是否支持某项查询或操作，以 GsCore 和桥接协议的实际能力为准。

天枢管理界面可以统一配置插件开关、角色可用能力并查看运行情况。常用直接命令应使用已经加载的必要配置和连接，不要求每次先访问平台控制台或长期记忆服务。配置更新、权限撤销及故障后的恢复仍需分别验证；独立路径不意味着取消必要检查。

## 回复由一个负责方组织

直接命令的结果由插件/桥接器投递，文本、图片和卡片可以按原业务格式返回。自然语言调用时，入口在提交请求时明确选择“把结构化结果交回核心组织回复”或“由桥接器投递原生结果并回报发送记录”。两种方式不能默认同时开启，避免插件发完一次，角色再重复宣布或重复发图。

人格化的一句说明可以按需要附加，但不要求对每张 GsCore 图片再调用一次模型。执行失败、已提交任务、最终完成和消息发送状态分别保留，不用自然语言修饰掩盖实际结果。

共享消息出口仍负责平台限速和回执。两个陪伴轮次的正常输出按轮次/段落排序；明确功能回执使用自己的请求关联和发送优先级，不以聊天模型完成作为排队前提。实际正在发送的消息不能被凭空撤销，各类回复也应在合适的消息边界调度。

## 两个处理轮次的范围

同一个逻辑会话/线程内，陪伴核心共享最多两个处理中轮次，多角色不能各自再乘以二；另允许正在收集中的防抖缓冲，超额已封存轮次有界排队。全局模型和设备资源不足时可以等待，但不自动扩大这个上限。

直接群管理、GsCore 命令和插件事件任务有各自的并发、目标顺序及限流规则，不占用陪伴对话槽。自然语言理解属于一轮陪伴处理；它提交的长功能任务可交给执行者后释放对话执行位，结果通过关联事件返回。

## 独立路径的实际边界

目标是：天枢平台或陪伴模型暂不可用时，已正确配置且不依赖它们的群管理/GsCore 直接命令仍可运行；自然语言理解、设备和资料等依赖相应服务的能力按实际情况降级。

独立执行路径不等于每个插件必须独立部署。群管理可运行在 NoneBot 进程内，GsCore 使用其业务后端。如果它们共享 NoneBot 进程、消息连接、CPU 或发送配额，仍有共同故障与资源影响；需要非阻塞执行、超时和必要的工作进程隔离，不能仅凭图上的分支就宣称完全互不影响。

## 后续验收

- 明确群管/游戏命令不会等待聊天防抖，不增加主对话模型调用。
- 两个聊天轮次都忙时，合法直接功能命令仍可按自身限额处理。
- 同一请求无论从命令还是自然语言进入，只执行一次，且只由指定负责方组织结果。
- 无权限的调用在两条入口都被拒绝，不能借角色工具入口绕过插件检查。
- 停止天枢平台或对话模型后，直接命令的实际可用范围与设计一致；NoneBot 或 GsCore 故障则真实报告对应能力不可用。
- 共享进程中的慢插件不会阻塞消息受理和轻量会话调度；多角色共同遵守两个轮次上限。

以上是架构与验收要求，不是本轮已经运行或通过的集成测试。
