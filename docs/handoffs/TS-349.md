## 实际兼容缺口与本卡实现

原 NativeModule 只启动 WebAccess 或 fallback TLS 之一。原 WebAccess 是 HTTP 8080→18446，此时 TLS frontend 被跳过，而 Ingress 按原规则拒绝非 TLS 服务 RPC/模型入口。现复用 host.frontend 为可与 WebAccess 并存的**额外 TLS API listener**：原 HTTP 网页保持，API 使用已经启动的 private app 的 ServerRunner，不重入业务生命周期；stop_accepting/close_public 同时处理两监听，原 ingress 继续跟踪并排空请求。原 HTTPS WebAccess/无 WebAccess 的单 TLS 路径保持；历史同端口 HTTPS fallback 不另开第二监听。HTTP 与 TLS 不能抢同一端口。

公开 API 仍走原 Ingress → 原服务路由和 token/schema 校验，未伪造 request.secure、Cookie、Origin 或服务身份。HTTP 上服务/模型路径仍拒绝，TLS 中原 bearer 可用。没有增加每模块 TCP。

`make_installation(..., native_origins=None, frontend=None)` 允许协调者明确提供完整实际 module origin 集合；默认保留原 fixture 值。origin 必须是 HTTP(S) authority，无凭据/fragment/path/query；不按 URL 猜本地，不 DNS fallback，不改源业务 settings/合同/签名 pin。实读 origins-r1 当前值如下（有 OneBot 时需完整六项，未装时只五项）：

```json
{"platform":"https://platform.internal:8443","gateway":"https://gateway.internal:8443","memory":"https://memory.internal:8130","knowledge":"https://knowledge.internal:8131","companion":"https://companion.internal:8765","onebot":"http://onebot:18765"}
```

Knowledge 当前 8131 与旧 plan 默认 18135 不同，这是真实兼容点。frontend 的原字段是 `host,port,tls_certfile,tls_keyfile`；生产可显式提供 `0.0.0.0,8443,/config/modules/platform/tls/server.pem,/config/modules/platform/tls/server.key`，沿实际既有证书。不要改实际证书 SAN 或签名 URL 来适配任意新名字。

`export(..., public_port=18446, api_port=None, onebot_port=18765)` / 原 compose API 增加独立 API/OneBot 映射；CLI 相应为 `--api-port`、`--onebot-port`。原默认不多发布端口。HTTP WebAccess+frontend 的生产映射为 **18446→8080、18443→8443、18765→18765**；隔离候选可用 **28446→8080、28443→8443、28765→18765**，端口可用性由协调者刚实读确认，执行时仍以当前快照为准。API 额外映射必须有相应 TLS frontend，发布端口和内部监听均不能冲突。
