## Implementation

- `OriginalOutcome` is passed from the current Models observation to the successor decision. Under Sources/Identity, partition, batch, frozen episode/read-set and Runtime locks, Memory checks generation, live lease, current step/attempt, request identity and digest, selected head, lineage/version and material provenance. One receipt projects `consolidation_attempts.status/error_code/recovery_policy_state` and Runtime attempt state in the same transaction. Unknown requires a finished, timezone-aware original receipt before it can authorize another computation.
- A successor uses that receipt's actual `unknown` or `failed` state, never a stale local `queued` projection. Before any Runtime lineage write in the same transaction, Memory locks `models.rbi_outcome_guard.lock_recovery_facts_on` and invokes Runtime's synchronous `validate_model_recovery_facts`, then verifies the frozen request's Models `submission_digest`, intent and attempt. The same fresh receipt is passed to reserve. Missing/changed facts remain observable; explicit cancellation cannot create a successor. A raw `cancelled` receipt is eligible as a pure-computation failure only for the exact `consumer_interrupted` status/error/cancellation tuple; Runtime classifies it as `INTERRUPTED`, counts it against the computation budget without provider cooldown, and never credits it as confirmed-not-sent. An exhausted unknown remains observable for a late original success. No blanket `recovery_original_not_failed` catch is added.
- `MemoryWorkers.recovery.resume_local_failure(batch_id, *, repair_ref)` applies only to a failed batch whose error is `recovery_original_not_failed`. It observes the existing Models attempt outside the transaction, then rechecks authority, generation, lease/claim, lineage budget, frozen digest/read set, episode revision/sequence/content/cursor and competing ownership. Proven identical applied coverage returns `already_covered`, including its recorded missing state; ineligible material remains unchanged with its reason. Eligible work is reopened on the original lineage and normal scheduler. The failed-only Runtime repair port is not used; original requests, attempt IDs, receipts and budgets are preserved.
- The ordinary episode `resume_on` command queues a targeted `memory.consolidate` wake for this exact failure. The worker observes the original outside the command transaction and calls the same recovery method. Other failures keep their existing paths.
- `MemoryWorkers.reconcile_due(*, limit=32)` returns `{scanned, woken, complete}` (plus `busy` when another scanner holds the cursor). It rotates over the partition primary-key index with an installation-scoped durable cursor and separate short partition transactions. The existing scheduler and queueing lock retain a matching earlier/equal todo without adding a job key; a doing job may have one todo successor. `complete` means the traversal reached its end, not a transactionally frozen whole-domain snapshot. Inserts behind the cursor are visited on the next traversal. The existing `recover` routine uses this scheduler.
- RBI-09 reuses the existing `MemoryService.observe_episode` API. In its single fallback transaction it must lock the complete event/Action/receipt Sources union before its Action fence and pass the same refs to Memory without recording any new Sources after the fence. Memory's source validation then re-enters the same Identity and Sources closure; `intake_scope` and `scene_authority_on` re-enter or read the same Identity context, and the episode observer only enqueues jobs. The two source-alias writer paths take write locks on already bound roots before expanding the closure. RBI-09 owns the cross-domain lock-order/concurrency stories.

## Models facts lock follow-up

The fresh-receipt reconciliation, local-failure resume and `rbh_transport._inspect_one` paths acquire the frozen original Models attempt lock before the first Runtime lineage write, including later claim/reservation in the same transaction. The startup `claim_due_recoveries` transaction only claims and schedules work; it does not record a model receipt or reserve a successor, and its later execution takes the Models facts lock separately. RBH keeps historic transport proof separate from present retry eligibility: if a later explicit cancellation is the only new fact and the frozen failed receipt still matches locked identity, submission digest, dispatch, error and finish, Runtime may record its independently proven old not-sent evidence, but the latest cancelled attempt is not scheduled. If a newly read receipt already includes explicit cancellation, Memory uses the unchanged previously stored `first_failure` receipt only when its identity, immutable route, timing and diagnostic evidence match the current original facts and receipt; it never removes cancellation from a receipt. An absent or mismatched old receipt earns no credit. Missing Models facts or a changed physical result never earns a credit. Historical unknowns and original receipts remain unchanged. The RBH fixtures now use a real isolated Models ledger and include cancellation-after-evidence, absent submission and Models-before-Runtime concurrency stories.
