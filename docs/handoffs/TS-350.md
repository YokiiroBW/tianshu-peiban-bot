## 新 profile 与装配

配置 `service_profile: "unified-one"`，固定 `compose: {"tianshu-unified": {workdir, file}}`，`images`/`binds`/可选 `external_data_binds` 只使用服务键 `tianshu`。例如真实安装目录 `/srv/tianshu/unified-20261027`；仅本 profile 允许 workdir 为固定部署根内部实目录，Compose 文件必须在该 workdir 内，沿用所有父级无 symlink/绝对正规路径校验。旧九/十服务 profile 的 workdir 规则不扩展。

原必填 `platform_first_compose` 与这唯一 compose entry 完全相同，保留旧 schema 字段而不虚构第二份文件。完整镜像 `.Config.Image`、workdir/file、全部 bind source/target/read-only 和 `unless-stopped` 规则照旧。统一服务承接 Platform 的精确外部 media allowlist 和逐服务 data allowlist；根、安装目录、显式 free_paths 与所有外部媒体/data 的磁盘空闲量都采样（仅上述两项既有易失 IPC 例外）。部署字节总量仍只统计部署树。

新 profile 必填 `retired_ids`：13 个不重复完整容器 ID。列表冻结在新 `armed.json` 的唯一签名内，顶层 marker 格式和旧 profile 签名不变。枚举到这些旧 ID 时，只有 `exited|dead|created` 且 restart `no` 才豁免旧 bind 冲突；running、paused、未知状态或未知 restart 均拒绝。所有旧 core/obs/OneBot/comic-files project 的额外未登记 ID 均冲突，即使不绑定部署根也不忽略。

旧 13 个 ID 每次 arm/sample/fail-close 都传入原 `fresh_ids`，OneBot/comics 不会被外部创建元数据缓存遮蔽；新 unified project 与原 core/obs 一样不缓存运行态。配置集合是精确冷回滚 allowlist，未枚举的 allowlist ID 不会被重建或管理；旧容器实际保留和完整冷态切换由协调者的部署生命周期核对。

新 generation 使用独立空 state/config/unit 和独立部署代码路径，旧 guard code、armed/latch/stop receipts 不覆盖。新 fail-close 只对新 marker 的唯一 owner 禁用重启和 TERM，绝不操作 `retired_ids`；即使旧容器复活，停止新 owner 后仍报告冲突 `unconfirmed`。拒绝将 retired ID 写成新 stop-target 的 marker。
