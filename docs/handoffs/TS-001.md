## 本轮协调意见的对应修正

1. 共享证据改为 `raw_message / shareable_projection` 判别结构。群只返回 memory 的投影引用/版本，私聊血缘留服务端；正例包含私聊原文仍 pending 的兴趣投影，负例拒绝附带 message_key 或伪造 archived。入站原消息 source 不变。
2. 模型分为宽松入站和必须有合法 model 的上游形状。缺失时可由显式默认或内部绑定补齐并记录 requested_model=null；preserve 无模型及显式 null 不补默认均拒绝且不发送上游。提供默认/内部绑定成功与拒绝被错误绕过的正反例。
3. 首次来源允许尚无 person_id/conversation_id，以 verified_account/channel 验证渠道，服务端幂等创建会话映射并解析/登记人物。陌生账号联合样例包含 resolve_missing、register 请求/结果、双方来源上下文及最终 ingest 回执，错误登记/映射被拒绝；无需用户先登记。
4. 精确 scope 目标一致，否则拒绝；收紧只作用于该目标下的记录/字段。请求账号与被查询 subject 分开；首切片限本人 subject，不宣称已覆盖其他人物或全群画像。
5. 封存允许实际时间晚于有效 deadline，仍核对 collection_revision；晚触发正例、旧版本负例与截止后消息另组既有负例共同通过。
6. turn_changed/reply=null 是失效通知，客户端只读取快照且不生成/发送；忽略刷新被拒绝。另补 semantic_state，statement 修订必须原子重建或失效完整条件/否定/时间/依赖组；旧条件混入重建结果或失效后继续召回均被拒绝。
