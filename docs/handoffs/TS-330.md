# TS-330 单容器统一运行时

基线 `ab93be4e91b824008d387d71c80e77dfac7341b3`，分支 `codex/single-container-runtime-20261027`。本卡只实现本地运行时及隔离测试；尚未集成统一镜像或在 Linux/生产运行，没有推送、部署、访问真实数据、调用模型或发送 QQ。

## 实现与复用

- `deploy/single_container/runtime.py` 为统一容器的入口，按清单管理原有 CLI/二进制，不重写业务。依赖真实探针成功后启动下游；模块退出或健康失败使整体 degraded，并保留健康的其他服务用于使用及诊断，不盲目重试业务。SIGTERM/SIGINT 反序停止，必要时结束该模块自己的进程组；Linux PID 1 回收收养的孤儿子进程。
- `process.py` 管理 Popen 生命周期、显式 argv/cwd/uid/gid、逐进程 env 文件及依赖。root 启动的业务进程通过 Popen user/group 降权并清空 supplementary groups。复查了 `ops/recovery/process_backend.py` 与 `process_identity.py`：前者明确是合成停写/回执适配器，后者只读进程身份，不适合直接当常驻 supervisor；这里使用持有的 Popen 对象及标准库进程组，不增加隐藏导入或另一份业务协议。
- `health.py` 支持真实 HTTP(S)、TCP 和 Unix connect，HTTP 保留 CA 验证、可选 mTLS 和令牌文件轮换，不跟随重定向。每个模块最多一个在途只读探针；探针过期立即取消 ready，卡住的解析/网络线程不阻塞 supervisor 收尾，也不无限追加线程。稳定 ready 默认每 5 秒探测，启动/失败按主循环重试。健康命令读原子状态与更新时间，拒绝过期/未来时间/部分状态及已退出 supervisor；状态不写 argv、env、URL、响应正文或凭据。
- `comics_control.py` 与 Platform 的原 comic-files 插件生命周期对接，不增加文件业务实现。两个 worker 的固定配置只来自私有清单；Unix HTTP 的所有动作以 SO_PEERCRED 核客户端 UID，并以插件实例 UUID 绑定 owner。start/stop 幂等，stop 只有确认两个 worker 停止后才释放 owner。

## 配置/API

入口 `python -m deploy.single_container.runtime --config /etc/tianshu/runtime.json`；容器健康命令 `python -m deploy.single_container.health --state /run/tianshu/runtime.json`（状态默认最多旧 10 秒）。

清单为 `{version:1,state_file:<绝对路径>,poll_interval_seconds?:1,processes:[...]}`。每进程必需 `name,argv,health`，可选 `env,env_file,cwd,uid,gid,depends_on,startup_timeout_seconds,stop_timeout_seconds,stop_signal`；uid/gid 必须成对。env_file 为一个绝对路径或路径列表，逐行 **KEY=VALUE 字面值**，不执行 shell、插值或 dotenv 引号解释；后面的文件覆盖前面的值，显式 env 最后覆盖。默认启动期限 60 秒，停止期限 30 秒，停止信号 SIGTERM。依赖不存在、循环、重复名称、缺真实探针均不启动。

health 必需 `type`，可选 `timeout_seconds`（默认 2 秒）、`interval_seconds`（默认 5 秒）。HTTP 使用 `url`，可选 `ca_file,client_certfile,client_keyfile,bearer_token_env,bearer_token_file,headers,expected_status`；client cert/key 成对，两个 bearer 来源互斥。TCP 使用 `host,port`；Unix 使用绝对 `path`。TCP/Unix 的成功只证明连接存在，不替代产品协议或真实文件回执验收。

可选 `comics:{socket:<绝对路径>,client_uid:10001,processes:[两份上述配置]}`，名称固定 `comic-inputs/comic-publisher` 且无外部 depends_on。POST `/v1/comics/{start,stop,status}`，JSON `{owner:<规范 UUID>}`，成功严格返回 `{state:ready|starting|stopped|failed,roles:{inputs:running|stopped|failed,publisher:running|stopped|failed}}`。start 立即返回后由插件轮询；异 owner 为 HTTP409 `{code:comic_file_owner_conflict}`。socket 保持 supervisor 所有、0660；发行配置应使用 supervisor `0:10001` 和必要 SETUID/SETGID/KILL，沿原文件 group10001 通信，不增加 CHOWN/DAC_OVERRIDE 或改媒体权限。漫画各 worker 的 stop timeout 建议不超过 2 秒，以匹配插件 5 秒 stop 调用；容器 grace period 必须覆盖全部反序停止预算。

## 实际验证

Windows bundled Python：`python -B -m unittest discover -s tests/deployment/single_container -p test_runtime.py -v`，**20 项中 14 通过、6 明确 POSIX/Linux 条件跳过**。通过项实际启动隔离 HTTP 子进程，覆盖依赖就绪、失败下游/保留诊断、env 覆盖、凭据不入状态、HTTP 鉴权/重定向/TCP、令牌文件轮换、退化恢复、启动超时、卡住探针不继续绿且不阻塞收尾、状态盘失败收尾、漫画 owner/停止/重启及 supervisor 状态新鲜性。

另外复用已有 `tests/deployment/observability/helpers.py` 临时合成 PKI，真实 loopback mTLS 的 **4 个断言通过**：正确客户端/链/令牌成功，缺客户端拒绝，不可信服务端链拒绝，令牌文件变更即时返回401。证书和令牌均位于临时目录，没有生产凭据。

开发中首版 Windows 的 `os.kill(pid,0)` 被平台当 CTRL_C 事件而中断测试，已改为 Windows 内核只读进程句柄并清理本批测试进程；一次新增测试插入错位造成两个 NameError，已修正，最终集中结果如上。未将这些失败写成已有故障或全程无失败。
