# A1-R1 resident first-install handoff

## Goal and scope

Build a real, one-attempt first-install entry for a new resident candidate.
Scope is `ops/resident_install/`, its isolated test, and this handoff.
Baseline: root `main` `a47b70c28e3d71dca80023a98e8b5360694b27e5`;
branch: `codex/nas-a1-r1`. Product repositories, old recovery code, shared
deployment adapters, root task board, NAS state, and production containers
were not changed.

## Changes

- `prepare` binds four fixed product commits and OBS resident commit
  `a194fa7b527ac2da0f13b8c3e95e76a1b836b4b3`, resident project/profile,
  explicit private LAN HTTP/IP, internal operator TLS, real admin username,
  independent private credentials, and a one-line private password. It calls
  the existing `bundle.initialize`; that builder produces the scrypt password
  verifier and a fresh integrity-indexed bundle.
- A3 consumes the unchanged bundle layout. Its Dockge export lock must bind
  manifest and bundle hashes, product source commits, OBS source, deployment
  root, and nine digest-pinned images. `activate` checks this lock, the
  prepared Compose, Linux UID/GID 10001 mount access, and all nine local
  Docker `RepoDigests` and empty fixed Compose project identities before
  Docker effects, with pulls disabled.
- Linux `activate` refuses nonempty product data or any previous attempt.
  It records an attempt first, invokes fixed Memory public migrations
  (schema 1→2→3, each with backup), starts Platform alone to health, runs its
  public preflight, optionally publishes an explicitly supplied private
  provider document, and uses its public `local issue` to obtain the Gateway
  `config-entry` source. The source ref is written only to
  mode-0600 `private/gateway.env` and reindexed. Reports contain no ref or
  credential. Failure leaves fixed-code diagnosis and forbids automatic retry.
- The first issue invalidates A3's pre-activation lock because Gateway's
  private env and bundle integrity hash change. A3 export must run again into
  a fresh output directory. The normal `activate` path invokes A3's public
  exporter immediately after issue, with its Git source and empty output
  checked before the first side effect. `finalize` reads back the new lock,
  requires both
  exported Compose files to be byte-identical to the first export, checks
  Platform is the only running service, and requires at least 120 seconds of
  source lifetime. Only that final export may be imported into Dockge. If
  the short-lived source expires during review, this module offers one
  explicit `reauthorize` operation while the same Platform container alone
  runs; it uses the fixed public CLI with an attempt marker, then immediately
  invokes A3 export into a prechecked fresh directory and performs a second
  `finalize`. No TTL extension or automatic reissue is introduced.
- Missing provider is recorded as `model_dialogue_unavailable`; no synthetic
  provider is created. Existing short-lived renewal and identity grants are
  untouched. Gateway, Memory service, and Companion are left for later live
  review. All outputs remain `release_ready=false`.

## Only permitted startup order

1. On Linux prepare the empty bundle, configure OBS from the fixed Git source,
   and make A3 export **one** against the declared empty deployment root.
   Copy the complete bundle/export there, establish UID/GID 10001 mount access,
   and load the nine digest-pinned images. Both Compose projects must be empty.
2. `activate` checks that first lock and local image `RepoDigests`, then
   migrates Memory while its service is stopped. It starts only Platform using
   export one's core Compose file, waits for health/preflight, then issues the
   short-lived `config-entry` for Gateway. Platform is the sole running
   service. Its settings and mounts are unchanged; Gateway has not been
   started, so it will read the updated private env only at its later start.
3. Issue changes `private/gateway.env` and `bundle-integrity.json`, making
   export one invalid for import. In the same `activate` run, invoke A3 export
   **two** into a previously checked new directory from the updated bundle.
   `finalize` then requires the new lock's hashes to match, both exported
   Compose files to equal export one byte-for-byte, only Platform to be
   running, and at least 120 seconds of the original 300-second source TTL
   remaining. A failure leaves all other services stopped and is not retried.
4. Import only export two, start Memory/Gateway/Companion and OBS through the
   reviewed live sequence, and authenticate readiness. This module does not
   claim that they started or that the candidate passed live acceptance. If
   the source expires before this point, stop at the pending state. An
   operator may use the one-shot `reauthorize` command only while the same
   Platform container alone runs; it creates another fresh export/readback in
   the same operation.
   No existing synthetic-only `linux_reauthorize.py` path is used.
   Pending expiry leaves Platform running alone and does not count as live
   readiness. If an operator chooses to stop it, A3's exact-container
   restart-disable/readback/SIGTERM/wait procedure applies; this module never
   silently stops or restarts it.
