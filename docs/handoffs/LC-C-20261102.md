## 设计映射和实现

- 总方案 7.5、CR14：沿原 `Content` 与 `Discovery`，补齐 research/explore/continue。问题研究保留问题；兴趣闲逛消费兴趣主题或公开热门；关注更新使用已配置 UP 主和论坛主题。B 站沿现 `Bilibili` connector/WBI 签名实际读取 search/popular/uploader 页面，不把订阅库当作站内搜索。各来源独立失败，游标绑定配置、问题和来源，候选去重保留稳定身份。
- 网页继续复用实际 HTTP/受控浏览器和角色会话。论坛单独保存作者、自己的正文、被引用作者/楼层/文字、时间、版本和分页。Discourse `/posts.json` 返回不含 topic/stream 时，通过原阅读游标保留剩余帖子，每页最多 20 帖；`follow_up` 用原主题地址及 `after_post_number` 查看新回复。无新回复明确返回 `experience_eligible=false`，不会把搜索摘要标成读过。
- CR15：保留现 PyAV 实际帧、音轨与内嵌字幕。`video.observe` 每次处理最多 30 秒；当配置的实际 Gemini 路线已经验证 video/audio 且原件适合现有 inline 预算时，优先提交真实 video 及明确时间窗口，内部采样仍为未知。其他情况使用真实帧及声音；配置路线缺少某模态时只提交实际支持的输入并记录缺口。未提交字幕/OCR时不制造对应覆盖。
- 疑点最多自动密读一次、最多 8 秒，保留仍未解决的问题；相同疑点标记已经回看，不在后续每段重复回看。每 8 段和窗口末尾进行一次跨段综合，依据原真实段落及先前综合；综合是派生材料。失败保留已完成段落和明确缺口。
- 观看续接只接受服务端已保存的 `consumption_id`，重新读取同一来源、版本、原件和真实下一位置；不信任调用者自带的摘要或覆盖声明。已取得原件的续段不再下载。URL 请求可省略 end，按实际分 P 时长观看；一 P 结束可沿真实下一 P 继续。原件证据单元沿 BVID/CID/原始文件 hash，角色经历不从标题推断。
- 总方案 13.1、CR17A/B：既有 SceneSnapshot → ImageIntent → 引擎编译/实际 graph → 产物保留。没有改用户 CFG/LoRA/工作流参数、增加第二引擎或自动重抽。产物后通过现有 `vision` function 做一次有时限的可见场景核验，使用原 ServiceClass/角色路由；未配置/失败/截断/缺项保持 unknown。结果存原 `image_work.completion`，重查直接复用。明确冲突的普通自主分享归档；用户明确请求仍保留并交付真实作品，附准确说明。

## LC-D 追加：真实发送边界和写作保存消费者

本次追加基于 C `691e80b6231cee612b1affabfd55014a27042ad7`，依赖 A 的 `contact_preflight`、候选代次/唤醒和写作进度消费者。已实读 B `f1058f93a5fac0cf55322d289646158b755cfad8` 的 product 装配差异；尝试将该 B 提交载入本树时遇到无关 generation 历史冲突，已立即 abort。本追加没有重写 B 的 episode observer、clock 或 diary；product 只有下述四行接口绑定。

实际调用路径：

```text
Life contact_due（A，candidate 的当前 delivery_generation）
 → ExpressionRenderer.send / speech 渲染 / turn 顺序等待
 → ExpressionRenderer.release
    → life_worker.contact_preflight(context, candidate_id, expression_id=当前代次)
 → ExpressionService.send → ChannelDelivery.deliver
 → canonical channels.deliver Action（后台排队）
 → DeliveryHandler.execute 再复查
    → web：prepare_call 后、web.publish 前再次复查
    → QQ/TG：prepare_call → owner 队列 → Channels.perform_call
              → transport.submitted 回调（媒体准备之后、真正网络发送之前）
              → contact_preflight → 原 actions.submitted / transport call
```

普通候选的内容当前性、联系窗口和显式提醒规则只有 A 拥有。C 传入 expression_id，拒绝旧代回调。A 的 defer 在同一候选上 CAS 持久化 waiting/due、增加代次并排原 `life.contact_due`；C 将从未进入发送的旧渲染表达取消，或把已排队但尚未提交的原 Action 收口为 `cancelled/none/not_requested`，结果保留 `contact_preflight={decision,reason,due_at?}`。旧 Expression 结果继续由原事件发布，不会长期停在 waiting。没有第二队列或自动重新提交旧 Action。

QQ/TG 的已知预检阻止用专用 `ContactPreflightStopped` 异常越过 transport 的 I/O 异常归一化，按实际 `submitted_at` 保存 rejected；它不会被误判为网络 unknown。已经 submitted、accepted、unknown 或 confirmed 的原调用不再调用候选策略，也不新发同一消息；继续读原渠道回执。部分原调用已经提交时同样不能把整份表达重新当成一份未来新消息。

写作完成路径：

```text
writing.request（只排队，不完成目标）
 → WritingService.generate / 原 GenerationRequests 真实模型回执
 → WritingService.save_generated（锁定当前 generation，拒绝过期/取消/来源失效）
    → 同 tx Sources.record_event 保存真实章节保存回执
    → 插入不可变 chapter revision / 更新 current_revision
    → on_completed(context, chapter, refs, connection)
       = life.writing_completed（A，校验当前版本和来源，更新里程碑并 signal）
 → LifeWorker.bind_writing(writing) 经既有公开 works/chapters API 读取跨日进度
```

保存回执包含 chapter_id/work_id/content_revision/generation_id/model_attempt_id/content_signature/character_count，原文仍只由 `life.chapter_revisions` 和 Writing 读者授权管理；不会在会话 Sources scope 复制未发布草稿。recipe 及 callback chapter 的 `completion_source_refs` 引用这个实际保存来源。来源、章节、回调同事务，重复 reconciliation 在已经保存为 draft 后不再写入或通知，不调用第二次模型。

product 的唯一追加绑定：`life_worker.bind_writing(writing)`、`writing.bind_completion(life.writing_completed)`、`renderer.bind_contact_preflight(life_worker.contact_preflight)`、`channels.bind_contact_preflight(life_worker.contact_preflight)`。

新增集中回归准备（均未运行）：`tests/conversation/test_render_contact_preflight.py` 覆盖等待顺序结束后才检查及旧表达取消；`tests/channels/test_delivery_contact_preflight.py` 覆盖后台排队、web 最后一跳、owner 媒体准备后变忙、已提交/未知不重发及普通表达不被套候选策略；`tests/life/test_writing_completion.py` 覆盖同事务保存来源/章节/通知、重复结果不重写及来源撤回不产生完成。
