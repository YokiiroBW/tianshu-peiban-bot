## 接口与装配

```python
make_installation(image, files, *, knowledge_client, mounts=(), comics=None,
                  observability_environment=None)
export(installation, output, *, public_port=18446, observability_ports=None)
compose(image, *, public_port=18446, frontend_port=8443, onebot=False,
        observability_ports=None, comics=False, stop_grace_seconds=420)
```

`make_installation` 返回且仅返回 `version,image,files,processes,mounts,comics`。`files` 为原配置生产者的输出映射：五个 `modules/<name>/settings.json`、`private/<name>.env`，原合同、TLS/secret，及原 `observability/{guard,vector,loki,prometheus,prometheus-web,vocabulary}.json` 和 provisioning/dashboard 文件。生成 `host.json`，`export` 生成 `runtime.json` 与一服务 Compose。`observability_environment` 直接携带原 Compose 各 `obs-*` 服务的 environment 字符串映射，不从密钥文件猜环境或外部 Origin。

业务只有 `business-host` 一个进程，uid/gid 10001，共用 `/opt/tianshu-venv/bin/python`；调用协调者增强的既有 `deploy/tianshu/runtime_guard.py --state-dir ... -- <python> -m deploy.single_container.host --config /config/host.json`。为各模块部署数据目录列锁参数，OneBot 可选；显式 bind 相同 source 的模块根只列一次，不读取/解析宿主已有目录。真正 inode/别名兼容归原 guard；没有声称保护任意外部存储 namespace，也没有改产品内部锁。

`host.json` 的五个模块各有明确 settings、逻辑 origin、独立 env_file/env；仅 Memory/Knowledge 的 spec 带绝对诊断合同目录及 log_directory，Knowledge 带已有注册 client。业务逻辑 URL/端口保持原意（包括 Gateway 8443）；没有业务 TCPSite、业务 DNS extra_hosts 或独立 Python 依赖树。原配置中的数据库名、PG/Redis后端/namespace、权限、模型、receipt/来源字段不改。

宿主状态为 `/run/tianshu/host/business-host.json`，进程用真实 `module_state` 探针，max_age 15s、间隔5s。此专属子目录必须由协调者的 root Runtime 启动准备为 root:10001/0770；父 `/run/tianshu` 保持0755，兼容漫画 IPC 的父目录检查。没有用预建可写文件冒充可原子替换的父目录。

五个观测进程沿原生 Vector/Loki/Prometheus/Grafana/guard 执行，不另实现日志业务。脚本路径为 `/opt/tianshu/application/deploy/observability`；guard 使用共享 venv Python、127.0.0.1:8445。Loki 健康探针保留真实 mTLS 客户端证书，guard /ready 保留 metrics_token 文件；五个都是 HTTP 探针。启动依赖保留日志链，业务不依赖观测就绪而被整体阻断；进程清单最后为 business-host，使原 ProcessGroup 反序停止时先收业务，再停观测。Compose 停止窗口按实际各进程退出预算及漫画 worker 预算求和加等待余量。

原 Vector 读取产品 JSONL 加自身 internal_metrics；原 Prometheus 只 scrape guard/vector/loki，guard 扫日志与持久账本并查询 Loki。没有删去原业务指标请求来伪装就绪，也不新增不存在的产品 metrics API。若传入自定义业务 TCP scrape，则明确报 `business_tcp_scrape_requires_host_adapter`，不输出失效目标。完整发行要求原 Vector 的独立 Knowledge 来源及 sink input，以及原 guard 的 Knowledge log_root 和正整数预算；旧四源输入分别报 `knowledge_vector_source_required` 或 `knowledge_log_root_and_budget_required`。协调者已确认由原 `configs.vector(include_knowledge=True)` 加明确预算提供，导出器不猜预算。

Grafana 启动环境保留原 Compose 值，尤其 GF_SERVER_DOMAIN / GF_SERVER_ROOT_URL / cookie 设置；仅重定位本地路径。健康探针 TLS 名优先原 domain 或原 root_url hostname，无元数据时只解码公开证书 SAN。默认不推断外部 Origin。复用正式 entrypoint，统一发行显式设置 QUERY_TOKEN_FILE=/config/observability/secrets/query_token；原独立部署不设置时仍读 /run/secrets/query_token。

## 文件、端口与持久性

JSON 的 dict/list 输入在原字段上重定位路径；str/bytes JSON 保留所有未变化 token、空白及 CRLF，仅替换路径字面量及 obs-guard 原8443→8445。路径状的 password/token/header、namespace 和模型标识仍按原值保留，不把它们当文件路径；原始 JSON 中键和值按原顺序分别处理，避免重写身份键。原生成器以 JSON 输出的 `.yaml` 同样处理，不解析手写 YAML。合同要求原 str/bytes 并逐字节写出；TLS/secret 原 bytes 不重编码或回显。env 保留单引号、字面 `$`、CRLF；仅已知部署路径变量重定位，不 shell 执行、展开变量或改任意 token。漫画显式开启且原 comic_files 存在时只补固定 runtime_socket；需要新增该字段的 JSON 对象会序列化，其余值保持。缺整个插件配置则报具体缺失，不猜启用/目录。

默认公开18446→内部8443；有 native web_access 时直接使用其 port（例如8080），不写 bootstrap frontend、不改原 Origin。外端口通过 export/compose 明确选择。原观测两个鉴权入口默认仅主机环回18490→3000、18491→8445，可显式传原端口。OneBot 只有原 storage.json 与原 token 文件同时存在才作为宿主模块及18765入口启用，没有独立进程。

Compose 仅一个 tianshu 服务，root0:10001 PID1、drop ALL、仅 SETUID/SETGID/KILL、read_only，运行态和临时目录为 tmpfs。继承镜像两个 VOLUME 由 `./data/legacy-state:/var/lib/tianshu` 与 `./data/legacy-logs:/var/log/tianshu` 显式持久 bind 接住，未用匿名卷或只 tmpfs 掩盖；/data 下保留模块、日志、观测各独立目录。原经审 bind（包括模块数据根/媒体）保留 source、target、read_only，并设 create_host_path=false。只在不存在的新安装目录写配置、创建目录；Linux root 分支只给这些新目录设应用权限，不遍历/chown既有 bind source、媒体或数据库。

## 实际验证与不利轮次

最终发行套件使用已存在的 TS307 q21 venv（含 cryptography），未安装依赖：

```text

```

15项包括新6进程清单/五模块配置、真实原生成器产物的日志源/ack/retention/账本/TLS路径、旧四来源缺项、原配置/合同/secret原字节、路径状身份/模型/密码不改、env单引号/字面$/CRLF、native WebAccess公开口与Origin、OneBot、漫画固定接点、原数据/媒体bind与共享根去重、新目录不覆盖、真实shell两种令牌路径，以及真实隔离公钥证书的多SAN/原hostname元数据优先。

已有 TS334 venv集中检查发行、原 `test_vector_sources.py` 及原 `ConfigurationTests.test_generated_stack_invariants`：16P/5 subtests，0.42s（当时发行11项，另5项原观测）；原5项后续代码未变化，结果复用。原 runtime+health 宿主探针25P/8skip/33 subtests的结果复用，不与多轮重复加总。8项跳过为当前 Windows 不适用的 Linux 权限/Unix/信号测试。原 exchange 52P没有因未改动重复执行。

保留不利记录：首9项8P/1F，新断言把6项 argv 尾错误切成7项，修测试后通过。扩展 shell 联合轮35P/1F/8skip，是 POSIX sh 不允许定义 exec 函数，改用别名拦截最终 exec 后真实 shell 两种路径通过；不是业务代码失败。最后审查发现新增的路径状 secret 字段保护会同时跳过 Vector.secret 配置对象，使其 directory 路径仍为 /run/secrets；已收窄为字符串身份值/headers，补原生成器 secret.files.path 断言并得到上述15P。TS334 venv没有 cryptography，初始 SAN 测试明确用解码替身；最终另用已有 q21 的真实临时公开证书证明解码，未安装库或读取生产证书/密钥。
