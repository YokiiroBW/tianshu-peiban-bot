## 公共接口与装配顺序

```python
from deploy.single_container.exchange import LocalExchange

exchange = LocalExchange(buffer_bytes=65536)
# 可先取得所有端口，解决产品构造时还没有 application 的依赖循环。
platform_session = exchange.session_factory("platform")
memory_async = exchange.async_transport("memory")
memory_sync = exchange.sync_transport("memory")

# 将 factory/transport 显式注入各产品，然后 register 完整应用。
exchange.register("platform", platform_app, "aiohttp", "https://platform:8443")
exchange.register("memory", memory_app, "asgi", "https://memory:8443")
await exchange.open()
# 最后停止新的 root 工作/后台生产者，再关闭 exchange。
await exchange.close(grace=30)  # None 为等待自然排空；到期取消并等待 finally。
```

- 工厂/transport 创建时仅绑定合法逻辑模块名，不要求已经 register。实际请求检查已注册、已启动、exchange 可接受请求及与目标固定 origin 一致；没有按 URL 猜产品或外部网络回退。
- `open` 按登记顺序运行 aiohttp `AppRunner.setup()`（不建 Site）及 ASGI lifespan startup。依赖方启动时调用的目标须先启动；失败逆序回收已启动资源。
- 接收方看到的真实 scheme 为 `http`，没有 socket、对端 IP、SSLContext 或证书。旧配置的 `https` origin 只用于固定目标身份与 Host，不能作为 transport 安全证明。
- 接收方 factory 在原安全边界显式核验 `exchange.owns(request)`。此判断登记实际 aiohttp Request/ASGI scope 的对象身份；任意 header、复制 scope 或 Request.clone 都不能获得该标记。它只证明内部 transport，原业务 token/授权照常执行。
- aiohttp session 支持现内部客户端使用的 request/get/post/put/delete、JSON/字节/异步字节上传、响应 read/text/json/content_type、content.read/iter_any/iter_chunked/iter_chunks、状态异常与 context manager。原 per-request `ssl` 参数可保留，但不会建立 TLS，接收方仍看到 plain HTTP。
- 不实现完整 aiohttp SDK：不跟随重定向、不建立连接池/socket、不支持代理、WebSocket 或网络 fallback；不支持的参数直接报错。内部调用继续采用原 identity 编码约定。外部真实 HTTP 客户端应保持原实现。
- 接入补充：显式支持现有网关调用的 `auto_decompress=False`，默认也保留应用原始字节；显式要求自动解压会拒绝。内部不会生成 Accept-Encoding 或压缩/解压副本，应用已有 Content-Encoding 与实体保持一致。connector/cookie_jar 等网络参数由注入端省略。
- HTTPX 为正式 AsyncBaseTransport/BaseTransport，实现真正逐块响应；没有使用会整段缓冲 SSE 的 ASGITransport。
- sync transport 及同步响应流仅供工作线程调用，通过 `run_coroutine_threadsafe` 回宿主 loop。loop 线程调用立即拒绝，避免自锁。同步上传在原工作线程的单 pull mailbox 中读取，不占第二个 executor，不预读整段。

## 生命周期与回压

每请求有独立输入/输出有界字节通道，默认各 64 KiB；aiohttp 额外保留自身有界 StreamReader。慢消费者阻塞生产者，而不是积累整段响应。响应头可先返回，handler 仍持续运行；HEAD 保留响应头而不等待实体。

没有包围跨模块 await 的全局 semaphore。A→B→A 回调可重入；关闭时停止新 root 请求，但已入调用仍能创建回调，直至其真实 finally 完成。宽限到期取消幂等，断连与停机不会二次打断业务 finally；流关闭立即唤醒有界通道。等待关闭的调用者被取消，也不会提前关闭应用资源。

请求及 multipart 临时文件收尾后才关闭应用。排空处直接回收已完成请求，避免完成回调尚未调度时对 done task 忙循环。aiohttp 私有入口 `_handle`、Request 构造及 `_finish` 集中在一个文件，明确要求 **aiohttp==3.14.1**；版本变化直接拒绝启动，需要重新核验。
