## 镜像与运行时修复

协调者以原只读后端确认持久漫画 `import_socket=/media/ComicInputs/service.sock`、`publisher_socket=/media/ComicPublisher/service.sock`，输入根 `/Cartoon`，两个 targets，全局 defaults 为空。只修改全局配置不会覆盖已保存的账本值。镜像构建时创建 `/media/ComicInputs` → `/run/tianshu/comics/inputs`、`/media/ComicPublisher` → `/run/tianshu/comics/publisher` 两个固定目录 symlink，账本原内容保留。

`image.install_comic_aliases` 在 COPY 冻结 deploy 源后由构建 Python 调用，仅处理这两个镜像内路径。先验证两者再创建；已有同目标链接可复用，其他文件/目录/链接冲突拒绝，不覆盖。不触碰真实媒体/NFS，也不为任意用户路径造别名。helper 配置 socket 使用对应 `/run/.../service.sock`，原 `/Cartoon` 和 `/output/*` 数据映射保留；新统一容器不挂旧 host IPC 目录。

原 `ManagedProcess.start` 清空附加组，且 IPC 子目录 `1770` 未设 setgid：保留原 UID1026/GID1654 的 worker 不能进入 GID10001 IPC；即使放行，socket GID1654/mode660 也阻止 Platform UID10001。复用现进程 spec 新增显式 `supplementary_gids`（仅有 uid/gid 时允许、非负整数且不重复），默认仍清空；漫画 worker 使用原 1026/1654 + 附加 `[10001]`。IPC 子目录改 root:10001/mode3770，只处理新固定 tmpfs 树；socket 继承组10001，原 SO_PEERCRED 仍严格核调用者 UID10001，无 CHOWN/DAC_OVERRIDE 新权限。

按协调者补充，将不影响依赖安装的 `COPY release.json` 与随 release 版本变化的 LABEL 一起移至应用 COPY 后；`runtime.lock/dependencies.json` 保持在 pip RUN 前。仅移动 COPY 仍会被早于 pip 的版本 LABEL 改变父层而失效，故两者同移。最终 provenance 路径和 label 不变，metadata 更新不再无谓破坏 wheels 安装层缓存。
