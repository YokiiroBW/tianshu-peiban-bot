# TS-367：same-ref 模型来源续期的只读诊断

基线 `ce5e686c89dcf43370018c389cf52cf4428ba741`，独立分支
`codex/unified-origin-diagnostic-20261027`。本卡只交 operational 诊断工具和定向测试，
没有 SSH、生产读取/写入、HTTP renew、clone expiry 修改、授权签发、ref 替换或产品改动。

## 真实拒绝规则

已安装 Platform `model_origin_renewal.py:49-74` 在写事务里认证
`config.snapshot` 的 Gateway service 后，明确要求原 origin 行存在、未撤销且尚未过期，
再核当前 entry/digest、entry 与 owner 撤销、entry 自身到期及唯一
`gateway → platform / config.snapshot` 路由；随后再次核 origin 未过期才更新同 ref 的 expiry。
已过期 ref 无法由原 renewal API 复活。`auth.py:280-313` 是相关 entry/route 规则。
Gateway `origin_renewal.py:_attempt` 将远端 401/403/410 都折为 forbidden 403，
因此单看 Gateway 403 不能确定过期。

不能为诊断实例化 `Platform`/`Store` 或调用 `Auth.activate`：它们有建表、迁移、
authority_policy 更新等写入。本工具复用 storage 0.1.3 的公开
`StorageRuntime.open_existing`，原生只读 PG session、现有 authority binding 校验，
不 start/finalize，不建立池或访问 Redis。

## 精确调用

将同提交的 `linux_origin_diagnostic.py` 与 `linux_clone.py` 放进新的私有工具目录。
root 使用既有私有 installed-wheel venv，不加产品源码 PYTHONPATH：

```text
<work>/venv/bin/python -I -B <new-tool-dir>/linux_origin_diagnostic.py
  --owners-inspect <work>/authority-source-owners-r1.private.json
  --source-root /srv/tianshu
  --clone-settings <work>/platform-migration-settings.json
  --clone-root <work>/clone/root
  --binding <work>/binding.private.json
  --state <work>/state.private.json
  --output <work>/authority-diagnostic-r1.json
```

上面各参数须合成同一条命令；源码无远端地址/目录默认值。工具显式加载同目录的
`linux_clone.py`，固定 SHA-256
`a6f5d366df67469851e4629b52d26b27af88a944aa3c86c2987535852440fdc5`，
因此 `-I` 不依赖脚本目录进入 sys.path；产品必须来自该 venv 的已安装 wheel，
不通过产品 checkout 覆盖来源。

`owners-inspect` 是协调者以 R3 inventory 精确原 13 ID 只读 inspect 后新建的
`service → full Docker inspect row` 文件，0600。工具从实际 Platform/Gateway `Config.Env`
取有效输入，并依最长匹配 bind mounts 找实际 settings 与 Platform state directory；
不读取 Compose/env_file 来替换已运行 owner 的环境。只访问明确 source root 内的物理路径。

clone 使用显式 physical settings，禁止继承进程 env；PG URL 必须等于原 pg2 binding，
Redis 必须为空。复用 `linux_clone.owned_binding` 核原 state/UUID/role/db/comment；
另在实际只读 PG session 核当前 db/user/session_user/owner、role flags、DB/role comment，
source 实际数据库必须与 scratch 数据库不同。

只新建输出 receipt（O_EXCL/0600），不覆盖已有文件。结果仅含 boolean、相对 expiry 秒数、
输入文件 hash 和已观察失败项，不输出 ref、entry 文档、凭据、URL或数据库行。
异常只输出固定拒绝码/类型，不把 psycopg 异常文本泄露到 stdout。

## 结论边界

`expired_same_ref_clone_candidate=true` 要求：source 全部已观察续期条件通过；
clone 只在 origin expiry 上失败；两边完整 origin 行除 expires_at 外全部一致，
完整注册 entry 相同，clone expiry 不晚于 source。不是授权，也不是 HTTP 或 readiness 通过。

该首版检查 **live Gateway Config.Env 所指 ref** 在 source/clone 的真实行；
clone credential 比较输入仍是明确标注的 original source 环境，不偷偷读取候选私有环境。
输出固定 `clone_gateway_environment_checked=false`、
`http_authentication_or_readiness_claimed=false`。若还需排除候选 env 装配差异，
应另提供实际 candidate 配置后显式核查。不得凭本 receipt 伪称候选 403 的全部原因已排除。

本卡没有 expiry-copy mode。协调者先执行首版只读诊断；只有真实结果确认 expired same-ref，
才决定是否需要单独显式 clone-only expiry 同步。此类同步仍必须保持完整非 expiry 行、entry、
digest/revocation/路由不变，只能读取有效 source 当前 expiry，不能签发授权或修改生产。

## 验证

4 项隔离定向测试通过：只读 SQLite 事实与过期 same-ref 比较、撤销/entry/ref/digest 差异拒绝、
实际 owner mounts/settings/secret reference 解析并用 mock 只读 PG identity 完成组合、
失败信息不输出凭据。使用真实 installed product digest/EnvSecrets，PG连接为替身；
不把此本地测试称为实际 PG 或 NAS 诊断通过。Ruff/diff 检查通过。

## 真实结果后的只读增量

协调者首轮实测：source 全部已观察条件通过，clone `origin_exists=false`，
不是过期行。不能把 row 缺失造成的后续 entry=false 当成 registration 已丢失。
本工具现用 source 真实 origin 的 entry_id/digest，在 clone 行不存在时独立读取其注册 entry，
比较完整对象、digest、entry/owner/caller 撤销与唯一 model route，仍不修改任何行。
新增 `missing_same_ref_clone_registry_matches` 只表示缺行但上述注册条件全等。

原 CLI 可直接沿用；另可加：

```text
--snapshot <explicit-cold-snapshot> --snapshot-gateway-env private/runtime-gateway.env
```

snapshot Gateway settings 相对路径由原实际 mount 映射至 source root 后推导。
只读验证 receipt 的 manifest hash，以及 snapshot/backup 中 settings/env 两文件的 inventory hash，
不重复整批 PG fingerprint 或 migration；输出 snapshot/live ref 是否相同、旧 ref 是否在 clone 存在等
boolean，不输出 ref。该增量用 6 项定向测试验证，新增缺 origin/registration 回退与冻结文件改动拒绝。

协调者随后找到已验收 `execution-preparation/origin_helpers.py` 的原 ORIGIN_READ /
ORIGIN_ISSUE / exact replace_origin_line 协议，明确改为复用原 operator scope 发 **fresh lease**，
因此本卡不再设计任何复制/复活 expiry 或 INSERT origin 的 SQL 路径。
clone 的显式 fixture 更新另单列原协议执行证据，原 25/39/3 克隆 proof 保留，
不能称全部当前数据已重新克隆。
