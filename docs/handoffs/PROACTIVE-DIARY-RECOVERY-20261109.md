## 修复内容

- **主动联系选人**：`Contacts.resolve_target` 从明确启用联系的人物关联私聊，再由现有 Identity 重新授权目标。角色日程无需包含目标私聊的阅读场景；待发送材料必须同时通过原日程场景与目标场景的来源检查，退出主动或禁止投递仍生效。
- **规划准备失败**：新请求尚未建立时，记录本次准备错误并安排 30 秒后重查。保留上一次成功规划头与回执，避免 `generation_consumed` 吞掉新配置错误；无需再由用户消息触发恢复，不新增物理模型尝试。
- **活动完成来源预算**：`record_event` 不再重复执行准备阶段的支持证明。保留锁发现、加锁后的闭包复查、实际写入场景中的支持证明，以及整个事件的保存点回滚。未改变来源闭包预算，也未删减活动依赖或历史图。
- **日记材料与旧失败恢复**：已有正文但材料新增或修订时，产生新的独立草稿版本；无材料变化时仍走原成功回执对账。仅收集阶段失败且没有冻结模型请求的旧日记可重新收集。已提交或未知请求继续原请求观察。
- **经历与整理状态读取**：复用 Memory 现有完整来源分批证明，合并同一次调用中的完全相同引用组，保留范围定位。修复 200 条经历或 128 份重试历史的重复引用耗尽输入限额；完整经历证明未知仍抛出原预算错误，整理状态证明未知则隐藏未授权详情并记录覆盖缺口。
- **记忆请求身份**：能力集合采用稳定排序；历史请求仅允许能力顺序不同的旧摘要匹配，其余身份字段仍须一致，原冻结请求与 Runtime 摘要不改写。旧 `memory_consolidation_attempt_changed` 接入现有原批次恢复入口，仍检查原模型事实、来源、版本、租约、取消、总尝试与预算。
- **事务取消**：复用 Runtime 清理机制，在 BEGIN/SAVEPOINT 进入和事务退出阶段处理取消时，先完成资源收尾，再传播取消，防止 Psycopg 保存点栈失序。已接到 Database 及相关 Sources/Memory 保存点。
