## 实现

- Memory 的经历时间页、按引用读取支持省略整理状态扩展；Life 的日记收集、通知消费与最终材料复检使用该模式，原身份、来源、范围、修订和缺失覆盖检查保持。
- 整理状态先为每条经历定位最新的对应批次，再读取、证明这些去重批次；不读取全部旧冻结请求。新增 `memory_episode_batch_lookup` 增量迁移，仅创建 episodes 成员 GIN 索引和隔离批次 lineage 索引。现场历史表约 3 GB；该次 DDL 使用事务内 120 秒预算，完成后恢复调用方原语句限时，不改变全局数据库配置。
- Runtime 仅将服务器明确报告的 statement timeout、且事务已确认回滚，纳入现有资源等待。用户取消、无阶段/回滚证明、提交未知仍不授权自动重试。
- Life 将收集页统一到现有原生队列；领域内有界轮转补偿检查仅恢复仍 collecting、未取消、未冻结/提交模型且没有待办/运行中收集任务的原代际、原 generation 和原 cursor。记录资源等待原因；已提交模型继续原请求观察。恢复不更换日记或模型尝试身份，旧失败任务历史保留。
- Memory 的业务待应用状态独立于 Runtime 物理请求终态。已成功的当前原尝试可由领域维护重新唤醒；租约忙时保留定向唤醒，另一活动批次的指针不被覆盖。应用前仍重新观察 Models、检查来源、读集、版本、代际及 CAS。暂停和已持久化的观察退避继续有效。
- Memory 的新材料到期、成功应用后后续材料唤醒与到期比较统一采用 PostgreSQL 时间。
- Life 规划加入核验收件人的联系机会、已有联系预算和当前可读的语义依据，允许有依据的日常问候、对话接续、约定与经历分享。全局日程不读取目标私聊正文；同场景对话读取复用 Memory 公共端口。目标变更后不把旧提案改投给新人。
- 联系提案由模型作语义选择，原显著性分数保留为解释信息；免打扰、退出主动、过期、配额、未回复限制、间隔和重复内容继续约束实际发送。规划应用记录明确的联系决定及原因；旧请求/回执缺少新字段时保持可读，并将缺失判断保留为未评估。
- 上游 524 继续复用原纯计算重试机制，先观察原请求，再按原总预算退避创建独立 attempt；旧 unknown 回执不改写，不切换供应商绑定，不重放渠道发送。
