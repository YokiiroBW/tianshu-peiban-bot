## 实现

- `DiaryService.day_closed(context, day, connection=...)`：生活时钟在实际睡眠/跨日边界登记当地日期；不是启动时补造历史。当地日期使用已配置 routine 时区。
- `DiaryService.changed(context, watermark, episode=..., connection=...)`：现有 Episode observer 同事务登记已经闭日的相关原始经历版本；按 Episode ID/revision 去重，并保留原作者 scope 上界。日记、reflection 和 internal 材料不会反复充当新证据。
- `life.diary_review`：复用现有持久调度器及 WRITING lane，把待处理材料交给原 `diary_collect` / `diary_generate`。无材料或原始版本集合没有变化时记录已复核，不调模型。短日记允许，自动产出始终是草稿。
- 日记材料身份只取当地日期、时区及原始 Episode 版本集合；其他日期/global sequence/派生日记增长不再触发无意义重写。保留原有有界材料选择与 coverage 缺项。
- 固定请求在当前授权的同一人物、会话、scope 和受众内观察原模型结果；unknown 不重新生成。保存前同事务复核原 Episode 版本、Sources、当前日记指针与取消状态；被修订/撤回的旧结果不能覆盖新材料。旧应用不可用时，模型账本原回执仍保留，合法的新材料可继续。
- 公开读者投影继续只含显式 disclosure 的已发布版本。自动状态、原始材料、上下文均不进入公开投影。日记日期统一输出 ISO 字符串，避免 PostgreSQL `date` 进入 JSON 失败。
- 人工 cancel/reconcile 的日记分支委派给同一固定请求处理；chapter 原路径不变。

## 通用生成端口

已独立提交：`300d4eb399d69a281d67e8e4169d26f16bab6627`。后续小调整随本卡补充：语义读者校验方法公开命名为 `observer_context`，prepare 重复调用返回原冻结身份，保留既有默认行为。

```python
frozen = await generations.prepare(material_key, request, connection=connection, guard=guard)
frozen = await generations.observe_request(attempt_id, observer=current_context)
result = await generations.read(attempt_id, frozen.context, observer=current_context)
```

`prepare` 只有数据库操作，可与 Life 原始指针在同一事务提交/回滚，不 claim、不调用模型。`run(..., observer=current_context)` 只观察，不提交，即使 Models 返回权威未登记 `None` 也不会准入。

原 principal/actor/person/conversation/kind/delivery 和 scope/audience 集合必须一致。当前 epoch 和权限交集只用于重新授权读取，原冻结请求及 fingerprint 不替换。Models 原 result 接口已把 epoch 与语义 fingerprint 分开，因此没有扩展 Models HTTP/API。

执行状态：succeeded 可在原材料及当前域 CAS 通过后应用；failed/cancelled 是已知执行终态；queued/running 继续观察；unknown 保留；None 仅表示原 attempt 未登记，只有默认原请求、合法原 context、原 deadline 内才允许同 ID 首次准入。不同业务场景只能终结/替代旧业务提案，不能嫁接旧正文。
