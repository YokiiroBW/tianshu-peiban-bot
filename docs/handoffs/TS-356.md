# TS-356 Owned PG17 客户端

本地实现交接，基线 TS-353 `f5c19401c0611625f62a5c2bb9fad05cc85ce165`，分支 `codex/owned-pg17-clients-20261027`。未 SSH、读真实 private binding/state、执行 Docker/PG、创建删除数据库、安装依赖或改生产数据。协调者实测230三项 native 均为 PG16.15，不能用于本批 PG17 archive；本卡不扩大旧 frozen wrapper 的 ts_restore 允许范围。

## 使用

新增 `tests/deployment/single_container/linux_clone_clients.py`，import 无操作。`prepare_clients(stage,state,*,snapshot,network,docker,python)` 所有位置、网络和执行器都显式传入。本批协调者选择 `network="host"`，无 network 默认；亦可由协调者明确选择已经存在的网络，生成时读取 Docker metadata 核其 ID，执行前再核同一个 ID。不创建网络或拉取镜像。

```text
python tests/deployment/single_container/linux_clone_clients.py prepare
  --stage /EXPLICIT/clone-stage --state /EXPLICIT/state.private.json
  --snapshot /EXPLICIT/cold-snapshot --network host
  --docker /usr/bin/docker --python /usr/bin/python3
```

CLI 只允许 Linux root 协调者执行；本地单测只生成合成文件、替换 Docker metadata/子进程，不执行该 CLI 的真实操作。固定 client image 为 `sha256:ca95f67ffb26270b70c5bc95dfaecc1a58bd08cab56ba6aeb051acb2163d2aab`，固定 scratch PG endpoint 为 `192.168.31.210:25008`，沿原 cold helper。**这不是 NAS230 业务/生产部署默认值**：这里只在230上运行既有 PG17 客户端，访问原 owned PG 资源所在地址；容器实际业务仍按隔离 Unix relay 和 `--network none` 验收。

输出新建 `stage/pg17-clients/`：三个 executable wrapper、hash冻结的两份源码、context、六份 archive 副本、`storage-backup.json`。协调者保存原 Tools 配置证据后，将输出配置用于 TS-353 的 `stage/config/storage-backup.json`；生成器不覆盖该原配置文件。其格式仍为原 `{"postgresql_tools":{"psql":ABS,"pg_dump":ABS,"pg_restore":ABS}}`，不修改 frozen Tools。

生成器调用 TS-353 原 `manifest`/`validate_stage`，要求明确的今日25域/6PG/39SQLite/3guard快照、archive原 hash/size 和独立 stage。沿现有 `owned_resource(state)` 复用原 PG2 状态规则：只读 `prepared_not_run`、单一 pg2 resource 的 UUID/role/database/comment/已创建/未清理 flags，不跟随 `binding_file` 或 `admin_binding_file`。context只保存角色/库/UUID和state hash，不保存token、comment、URL或password。包装器每次运行重新核原 state hash 与相同 ownership；原 TS-353 `owned_binding` 外部接口保持，13项原测试仍通过。

## 精确命令和数据边界

| 工具 | 允许范围 |
| --- | --- |
| 三工具 `--version` | 只运行固定 image 的对应二进制，不传 PG 凭据；TS-353 已检查其实际输出为 PG17。 |
| psql | 原 Tools.query/fingerprint 的固定 `-X --no-password --no-align --tuples-only --set=ON_ERROR_STOP=1 --command SQL`。SQL必须是原 identity/空库查询、manifest绑定 schema metadata、原 Memory/Knowledge/actor guard metadata、原关系枚举或 manifest既有表/sequence指纹读取的精确文本 hash。没有任意SELECT、DDL、函数执行或 psql meta-command入口。 |
| pg_restore | 原 TS-353 七个参数：`--no-password --dbname=OWNED --no-owner --no-privileges --single-transaction --exit-on-error ORIGINAL_ARCHIVE`。只允许该 state 的 `ts325_<32hex>`，archive只能是明确 manifest 的六份之一，转为新副本 `/archives/N.dump`；不接受 --clean/--create、其他库、其他参数或路径。 |
| pg_dump | 只有 --version；本卡不提供新的 export、输出路径或 PG 资源管理能力。 |

wrapper从原 Tools 的环境接收 PGPASSWORD，核 PGHOST/PORT/USER/DATABASE 与冻结endpoint和唯一resource一致。Docker argv只写 `-e PGPASSWORD` 等变量名，值留子进程环境，不读 passfile/PGSERVICE、secret文件或URL。对子进程构造新的最小环境，不继承调用者 Docker context/TLS、PGSERVICE/PGPASSFILE；psql 强制 `extra_float_digits=3` 和 `default_transaction_read_only=on`，不能经 ambient PGOPTIONS 改写。restore 用相同唯一低权限用户。

原 archive 不 chmod/chown。新副本由root复制并核hash，在新目录设置 root:10001、dir0750/file0440；仅该目录 readonly bind 到 /archives，使容器 UID10001:10001可读。psql/version不挂archive或其他宿主目录。容器 read-only rootfs、cap-drop ALL、no-new-privileges、512MiB/1CPU/128pids 和临时 /tmp；没有 Docker socket、私有绑定、配置或媒体挂入客户端。

stdout 是原字节流：不解码、不改换行、不打印诊断/JSON状态。Docker子CLI的stdout用独立PIPE，由wrapper分块原样转给Tools；stdin为DEVNULL，stderr与stdout分离。失败返回非零，wrapper只在stderr写固定无secret说明，不把异常内容或partial rows写入证据。原Tools继续以自身deadline和fingerprint规则消费。

## 收尾

普通客户端 `docker run --rm --pull=never` 自动退出。**Tools超时SIGKILL wrapper仍可能留下daemon容器**；wrapper子CLI不能直接继承Tools.stdout，否则孤儿CLI会继续持有父读端、拖住fingerprint消费线程。因此此处保留独立relay，同时协调者必须在本次操作的 `finally` 先清理client，再执行原 PG2 owner cleanup：

```text
python tests/deployment/single_container/linux_clone_clients.py cleanup
  --stage /EXPLICIT/clone-stage
```

`cleanup_clients(stage)` 只读取冻结context，按本run随机label列出client，先核**全部**容器完整ID、固定image、本run label和原network，再移除这些ID并确认列表为空。不执行SQL、CREATE/DROP或admin读取；不按名字模糊删除其他容器。即使原PG state后来被标记清理，仍可按该冻结run context回收残留client。真实成功还需协调者保存 `owned_pg17_clients_absent` 和原PG2 DB/role已不存在的独立证明。
