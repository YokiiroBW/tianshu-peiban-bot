## 稳定端口与 DTO

- POST `/api/v1/life/day-plan`：可选 day=`YYYY-MM-DD`，返回 plan/slots/unfinished/recent_results 与技术 planning 摘要；内部 context/frozen_action 不出 HTTP。
- POST `/api/v1/life/day-plan.move`：id、expected_revision、starts_at（带时区）、client_request_id。仅同日未来未启动 slot；活动与承诺占用均检查。CommandStore operation=`life.day-plan.move`。
- POST `/api/v1/life/day-plan.reconsider`：reason、可选 expected_revision、client_request_id。返回 queued 与 ISO 日期。operation=`life.day-plan.reconsider`；这是明确的新决策意图。
- Goal.save 接受 reason 与 criteria={kind,capability_id,target_count,work_id?}；target_count=1..50。chapter_saved 必须 writing.request+真实 work_id；已有 progress 后 criteria 锁定。origin 只读，模型无任意进度写口。
- Activity 核心状态仍 planned/running/paused/dormant/completed/cancelled；capability_running、outcome_unknown 不允许用 resume 重发。follow_up_available/plan_later_check 等待明确安排，手动 resume 报 activity_follow_up_requires_arrangement。
- routine.planning 与 day-plan.planning：revision/reason/next_due_at/last_planned_at/generation_consumed/pending。
- 运行装配：`clock.bind_lifecycle(day_plans=life.days,on_day_closed=diaries.day_closed)`；`contacts.on_received=life.received`；`LifeDependencies(life)`；`worker.bind_writing(writing)`、`writing.bind_completion(life.writing_completed)`；renderer/channels 绑定 `worker.contact_preflight`。B/C 已负责 runtime/product/execution 的实际绑定，A 未并写。
