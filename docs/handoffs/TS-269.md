## Behavior

`StorageRuntime._checkout` now confirms `search_path`, `lock_timeout` and `default_transaction_read_only` with one parameterized SELECT. Each checkout still sets all three values; there is no session-setting or authorization cache. The schema goes through `psycopg.sql.Identifier` quoting before becoming the bound search-path value. The functions are explicitly qualified as `pg_catalog.set_config`, so a previously selected schema cannot shadow them. Timeout rounding/minimum, read-only on/off, pool borrow timeout, sanitized failures and one-time release remain unchanged. Binding verification remains a separate statement after this SELECT has completed.

`PostgresConnection.read_batch(requests)` accepts trusted internal `(sql, parameters)` pairs for independent native SELECTs. It materializes and validates every request before sending anything. SQL must start with SELECT; this is a programming contract, not a general SQL parser or an authorization boundary for arbitrary SQL/functions. Do not pass DML, setup/advisory locks, multiple statements or dependent queries. The actual Memory SourceSnapshot requests were checked read-only: they are fixed SELECTs and are invoked after the caller's fresh CAS/lock confirmation, before its first mutation.

A nonempty batch requires a healthy existing `INTRANS` transaction. An empty batch returns `[]` without opening a pipeline or changing transaction state; closed wrapper/raw connections always fail, including for empty input. The method bypasses the product dialect and uses the unchanged native qmark binding and `prepare=False`. Its raw psycopg pipeline confirms all statements before returning the ordered Cursor list. Results are not consumed or converted ahead of the caller; existing cursor/Row/tuple-factory behavior remains available.

Immediate or delayed failures return no partial list and close every batch cursor already created. Psycopg errors retain existing sanitized StorageError/IntegrityError mapping, including delayed errors from pipeline exit. Request-iterator and Python adaptation errors propagate without replacement. The method does not begin, commit, roll back, retry, replay or release the connection; its owner retains the existing rollback/close path. Failed server transactions must be rolled back before another nonempty batch.

The setup-only `pipeline()` contract, `native(..., prepare=False)`, executemany, Row, savepoints, SQLite runtime branches, product CAS/guard/authority and durability rules are unchanged. No unused prepared-statement API was added.
