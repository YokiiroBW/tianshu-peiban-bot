## 既有图片的最小视觉验证调用

只观察旧尝试时，最小路径为已有 Models port 的授权结果读取：

```python
original = await models.result(original_image_attempt_id + ":consistency", context=current_context)
```

该调用只读原 `models.attempts`，不会提交供应商请求。旧 unknown 不改成功/失败、不更新截止、不换路由参数、不调用 `generate/stream`。读取失败也不构成原请求未执行的证明。

如根已获得明确的新视觉验证授权，可以直接检查既有 artifact；以下函数可以放入根现有受控验收进程。`models` 复用当前运行服务的 `ModelClient`（需要 `result/generation_profile/stream/generate`）；`artifacts` 复用现有 `Artifacts` port 的 `reference`。`current_context` 是 Identity 签发的当前授权且保持原 actor/会话/范围；`original_action` 是 `action_from` 解码后的原 Action；`prepared` 是只读取得的原 `capabilities.image_work.body`。`artifact_ids` 从已存在的 image completion 或原 Receipt.artifacts 取得，不能用重新执行生成来补齐。

```python
from dataclasses import replace
from datetime import UTC, datetime, timedelta
from types import SimpleNamespace

from tianshu.capabilities.images.consistency import ImageConsistency
from tianshu.types import Attempt, SourceRef


async def verify_saved_image(models, artifacts, current_context, original_action,
                             prepared, artifact_ids, verification_key):
    # Persist one explicit verification_key in the root's private evidence first.
    # Reuse it for observation after interruption; do not mint another on unknown.
    key = "image-verification:" + verification_key
    references = [await artifacts.reference(current_context, "artifact:" + identifier)
                  for identifier in artifact_ids]
    refs = (tuple(SourceRef(**item) for item in prepared["source_refs"])
            if "source_refs" in prepared else original_action.source_refs)
    check_action = replace(original_action, action_id=key, intent_key=key,
        context=current_context, source_refs=refs,
        deadline_at=datetime.now(UTC) + timedelta(seconds=180))
    checker = ImageConsistency(SimpleNamespace(broker=models))
    return await checker.check(check_action, Attempt(key, key), prepared, references)
```

这个新意图的最终 Models 身份为 `intent_id=attempt_id=image-verification:<verification_key>:consistency`，记录位于原 `models.attempts` 及其 result/receipt；profile 读取本身不登记尝试，也没有新增 `conversation.generation_requests`。后续只读观察可直接对这个精确 attempt 调用 `models.result`。

该入口只加载既有受控图片并进行视觉模型检查，不调用 `Images.prepare/execute/reconcile/complete_image_result`、图片引擎、分享策略或渠道发送，不改原 `image_work.completion` 与其 unknown 收据。返回结果由根保存到本轮私有证据即可。不创建或启动第二套 Models broker、worker、Life 调度器或后台服务；若根验收进程新建一个连接到现有服务的 `ModelClient`，正常 open/close 客户端即可，不能执行 `ModelBroker.open`。
