1. 实际五引擎启动并核对 PID 身份；原 TLS/Token 下通过 Grafana 实际数据源、看板、Viewer和匿名/写入权限检查；Prom query 返回 guard/vector/loki 三个 up=1。

3. 五源完整事件经 Vector→Loki→Guard 原 query 返回；三方 `compare` 检查无缺失、未知事件、内容或序号冲突。另要求返回每条日志与生成源的 canonical JSON 字节完全相同，保留查询原值和整体 SHA。这里断言的是生成夹具 canonical 原字节，不宣称 Vector 会保留任意原 JSON 空白/键序。
4. 停 Loki 后记录 Vector buffer 指标和实际磁盘文件，SIGKILL Vector（明确的崩溃用例），用同一数据目录重启并恢复 Loki；再停采、轮转、写新批次、重启，真实检索全部事件。
5. 从真实 guard/Prom 指标等到 pending=0/gap=0/landed=身份数；以只读 SQLite 核对 schema v2、每事件完整32字节 SHA、verified、摘要和位点。正常重启 guard 后重验；五源显式重复重放后 landed 不增，重复计数至少5。
6. 原 synthetic secret canary 被 Vector 拒绝，中央无匹配、源保留；原15告警仍在真实运行，实际 firing 投递到同 UID、本容器 loopback recorder。结束后所有本工具拥有的进程组先停止，再停 recorder，报告真实清理是否完成。

允许至少一次交付产生相同内容的中央重复行；会保留原 source/retrieval duplicates 计数，不把它称为 Loki exactly-once。身份/内容不一致或丢失仍失败，持久账本身份数必须保持。
