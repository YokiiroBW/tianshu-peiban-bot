# 私聊三态与主要用户管理员

用户授权默认不主动联系、现有私聊统一被动，群聊现有状态保留；修复后推送部署。后续澄清：禁用在入口过滤、不接收不回复不主动；被动接收并回复；主动按状态与节奏联系。用户页基本资料后增加主要用户／管理员，QQ 绑定后私聊和群聊按真实管理员权限处理。

## 实现

- 私聊模式组合既有 Identity 会话准入和 Life 联系设置，没有新增平行状态账本。一个命令在同一事务更新两者，保留各自 CAS/命令回执，并核对整组会话版本。禁用使用既有 ignore 入口，消息不进入后续来源、记忆和模型处理；被动/主动均为 reply，主动许可独立保存。
- 默认个人主动联系关闭；全角色节奏默认值不再给未单独许可的人物开启主动联系。新建 contact_preferences SQL 默认 false。主动联系判断缺省 enabled 也为 false。群主动参与继续使用原有逐群开关（未配置为 false），已启用群的共享节奏预算保持。
- 私聊模式在人物的会话权限和主动联系页共用；原接收/回复开关仅保留在群页面。联系节奏仍可独立调整，结构化修订和可重试命令复用现有公共能力。
- 主要用户／管理员位于基本资料后。新增明确的当前角色人物到既有后台管理员的渠道授权绑定，不合并人物、移动事实或改变原账号身份。权限从现有后台账号及当前角色授权实时求值；绑定、撤销均有 CAS，撤销使旧富权限上下文失效。
- 准入先取得真实连接/发送者的账户人物，再按当前角色绑定选择后台主体。仅已绑定人物可获得管理员权限；群内其他成员、转发与自称均不授予。角色权限、来源可见范围和会话禁用继续生效。来源作者仍为真实 QQ 人物。
- 两项增量迁移：private_contact_default 仅改未来行默认值；role_administrator 建立绑定表。既有数据不清理。后续实际管理员绑定由用户在新增入口选择。
