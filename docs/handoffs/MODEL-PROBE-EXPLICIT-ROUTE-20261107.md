# 显式目标能力测试与业务回退分离

用户已授权对当前聊天主路由和两个备用做真实工具检测并通过后登记。
真实调用发现两个备用在检测入口的 generation_profile 阶段即被
model_fallback_context_unverified 拦截，尚未调用供应商。
原因是 Catalog 把带管理权限的 capability_probe 显式目标误当作业务回退，
要求它先有业务上下文窗口证据，同时可能把主路由协议应用于检测目标。

修复限定在既有 Models.catalog.resolve：复用原有授权判断，显式授权能力测试
以目标自身作为主路由；原显式路由权限、revision CAS、普通业务回退容量判断、
模型调用账本和通过后登记保持。未填造窗口证据或手写能力，也不改变绑定。

新增六项定向PG边界：三个授权角色直接测试目标原生协议且不授予能力，普通业务
及无测试权限的标记仍检查回退容量，授权测试仍检查route revision。
交唯一生产写者执行该文件八项集中验证、串行发布并恢复两个未发出的原测试ID。
主路由180秒timeout_unknown保留，不换号重试；此前“无需新代码/发布”是任务派发时
的实现预期，真实测试发现检测入口缺口后由当前修复更新，并非用户限制。

无依赖、迁移或配置变更。真实检测结果与最终发布以协调者回执为准。

本地语法解析、diff检查和测试文件Ruff通过；未执行PG用例。
catalog.py的全文件Ruff仍有原导入I001/UP035，本次未改导入，不借此清理无关代码。
