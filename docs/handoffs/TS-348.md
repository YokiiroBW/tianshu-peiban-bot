## 已证实问题与修复

1. 原 `images=sha256:<config image ID>` 被直接写入 FROM。Docker 的命名引用解析会将其当成 `docker.io/library/sha256:<tag>`，不能冒充 registry manifest digest。Docker24.0.2 vendored [BuildKit convert.go](https://github.com/moby/moby/blob/v24.0.2/vendor/github.com/moby/buildkit/frontend/dockerfile/dockerfile2llb/convert.go#L379) 调用 ParseNormalizedNamed，配套 [normalize.go](https://github.com/moby/moby/blob/v24.0.2/vendor/github.com/docker/distribution/reference/normalize.go#L30) 对无 slash 的名字补默认 registry/library；另有原项目 [39769](https://github.com/moby/moby/issues/39769) 的同类复现。保留 release.images 的原精确 config ID，新增可选 base_references 显式命名引用；本地 ID 必须有有效 named tag/ref。原 registry repo@sha256 路径直接保留，不将 ID拼成 manifest digest、不改已有 registry pin。
2. 原 `# syntax=docker/dockerfile:1` 会解析额外、未固定的外部 frontend。已移除，当前只用 Docker 内建支持的基本 FROM/COPY/RUN/ENV/HEALTHCHECK 等语法。[官方 frontend 文档](https://docs.docker.com/build/buildkit/frontend/) 说明该 directive 选择外部镜像，内建 frontend 仍可使用；没有新增需高版本 BuildKit 的指令。
3. 真正原 Grafana `/run.sh` 的尾部是 `exec grafana server ...`。原镜像只复制 `/usr/share/grafana/bin/grafana`，PATH 没有该目录，绝对路径 --version 成功仍会漏掉启动时127。现将共享 ENV 的 PATH 加 `/usr/share/grafana/bin` 并移至原生引擎版本检查前，Grafana smoke 改为 `grafana --version`。完整复制原 `/run.sh`、home、config，继续由它处理原 Bash、__FILE、插件等启动行为，没有替代实现或丢掉媒体 OS 工具。

`base_references(release)` 返回实际写入 Dockerfile 的五个引用。`verify_local_bases(release, *, docker="docker")` 只调用 `docker image inspect --format` 读取 Id/Os/Architecture；逐项比较本地 tag 的 Id 与 expected config ID，检查 linux/amd64。返回也只含这三个字段和 ref，不读取 Env，不自动 pull/tag/run/build。registry manifest 分支由 Docker 对原 name@digest 做本地查找，输出实际 config ID，不将两者混淆。

```text
python -m deploy.single_container.image --verify-local-bases /explicit/release-or-context-receipt.json --docker /explicit/docker
```

`prepare` receipt 记录原 images 和实际 base_references，状态仍是 prepared_not_built_on_linux，不伪称执行过 Docker 身份验证。单一 venv、精确四产品/storage wheel、archive/约束/锁/依赖哈希和所有原媒体工具保持。
