## Change

`Cursor` now uses the identity of psycopg's current `pgresult` to reuse one column-name tuple and one immutable casefold-to-position mapping per result. Rows retain values and pure metadata only; they do not retain a cursor or PostgreSQL result. Result changes rebuild metadata, and closing the cursor clears its cached result reference even if close raises.

The public `description` property still delegates dynamically. `row_factory` is checked at each fetch: `None` returns a tuple without constructing description metadata; the existing non-`None` behavior still produces the shared `Row`. Duplicate/casefold-equivalent names retain the first column, keys retain original spelling/order/duplicates, and already materialized rows remain valid after another result, execute or close. Cursors without `pgresult` retain dynamic description-name comparison. Execute/executemany delegation, counts, failure behavior and MemoryCursor's no-op close are preserved. MemoryCursor also shares immutable metadata across its rows.

The native SQLite connection path, PostgreSQL SQL/transactions/pooling, Redis behavior and 0.1 API contract are unchanged. Package version is **0.1.1**; existing **0.1.0** artifacts and consumer pins are untouched.
