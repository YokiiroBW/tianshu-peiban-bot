# TS-340 统一业务宿主本地交接

## 实现与归属

本批隔离协调分支 `codex/single-container-20261027`。用户授权的一容器、模块化业务、漫画插件、异步联动及日志优化已形成可构建候选；没有推送、合入产品 main、操作生产配置/数据或部署。

业务进程只有一个：Platform / Gateway / Memory / Knowledge / Companion 各自保留原应用、Store、合同、token、来源、幂等和 receipt，在本模块 owner thread / loop 构造和关闭。可选 OneBot 复用原 SDK、持久 identity 和 ASGI lifespan，外部 WebSocket 单独监听；没有第二个 NoneBot driver 或服务进程。模块使用有界进程内 session / HTTPX transport，不开业务 TCP、不共享其他域数据库、不切换每请求进程环境，仍有原合同编解码成本。

复用原 Platform WebConsole/WebAccess 及 Gateway 外部模型连接池。统一 HTTPS 入口分发网页、Platform 服务 RPC、Gateway 普通/原生模型、receipt、模型管理及 retrieval；原鉴权、schema、Cookie/Origin、Content-Encoding、TLS 和私有模型身份继续生效。外部 SDK 不会因同 URL 被当成本地模块；仅原 persistent instance_id 明确匹配宿主 OneBot 的连接使用内部接口并重基 origin，不重写持久地址/授权。OneBot 先启动，Platform pump 之前绑定，避免冷启动先访问旧网络别名。

正常停止顺序：停止外部接收→已入网页/模型根请求完成→同时停各域 producer→真实 Core / Memory / Knowledge / Platform / SDK owned work 排空→关闭外部 listener→反序关闭原应用及依赖→join owner 线程→恢复进程环境。超时返回不等于线程或事务结束；宿主保持真实任务及 finally，PID1 承担最终进程退出预算。后续模块启动失败也先在仍可回调的 exchange 状态排空已启动模块，随后关闭，避免丢失 receipt 或提前恢复全局环境。

宿主健康按原只读 readiness 取安全结论；每模块最多一个在途 probe。被同步 SQL 阻塞的 owner 不会冻结协调线程的健康报告，也不会因取消 Future 就伪称 DB 工作停止。PID1 用状态文件的新鲜度、真实 PID 与所有模块 verdict 作聚合，缺配置/尚未验证仍降级。OneBot 尚未连 QQ 时原 live 可用，不以真实账号连接作为网页启动门槛。

原 Linux `runtime_guard.py` 扩展多目录锁并兼容旧 CLI；失败回滚所有已取 FD，同一实际 inode 只持有一次，exec 后继续持锁。PID1 只给固定 `/run/tianshu/host` 子目录 root:10001/0770，父目录保持0755；不会放宽漫画 controller 父目录。漫画插件关闭仍可用 controller，业务退出后才关闭 controller/助手。Linux 权限、flock/bind inode 与信号实机尚未在本机执行。

Gateway 新增独立 CA 接线用真实 HTTPS 模型替身验证（4P / 0.69s）；Platform 持久 SDK origin 重基及原取消/SQLite 清理验证（7项 / 2.314s）。新增代码 Ruff 以 Python3.12、format 和 diff 检查；没有重复声称未变化全量绿。

## 发行与性能限制

复用既有配置生产者，单一 Compose 服务、一个共享 venv、原五个观测引擎；保留 PG/Redis namespace、原件、媒体 bind、原日志检索/补传/30天及15条告警。发行构建从四产品 wheel 的实际 METADATA 和 NoneBot extra 求解 Linux cp312 二进制依赖，采用本批已验证公共依赖约束与 SHA256 lock。已修 prepare 内部 backend constraints 局部变量遮蔽 runtime constraints 的错误，新增贯穿 prepare 的透传回归；真实最终 prepare 及其 receipt 另见交付记录。

日志账本样本从349147136降至293482496字节（-15.94%）；metrics、confirmed、idle 样本查询显著缩短。完整日志保留；不是全站日志目录、生产盘或 RSS 已下降15.94%。百万行批量写入17.06→33.64s较慢，迁移约3.78s；没有自动 VACUUM 或删除未经确认源段。原证据与具体查询见日志卡交接。

本机无 Docker/WSL，故没有 Linux 镜像构建/运行、原生观测 ELF/真实 Grafana启动、UID/capability/flock/Unix 宿主完整实测、真实 PG/Redis、NAS端到端吞吐/CPU/RSS/镜像层大小或更新停机验收。Python CPU 密集工作仍受单进程 GIL 和各域原预算影响；不能由取消 TCP 直接推断整机提速。生产数据、媒体、权限、模型、QQ、设备、外部 AssetLibrary/Chat 等独立产品未操作。
