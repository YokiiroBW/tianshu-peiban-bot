## 正式公共边界

- `tianshu.types`：TrustedContext、RequestBudget、ServiceClass、OriginKind、Action、Attempt、Receipt、MediaRef、ArtifactRef、SourceRef、Coverage。
- `tianshu.models.types`：ModelRequest、ModelMessage、ModelPart、ToolSpec、ModelResult、ModelReceipt、ModelUsage、ModelEvent；`models.ports.ModelPort` 提供 async generate/status/cancel 和 async iterator stream。
- `tianshu.runtime.database.Database.transaction(budget=None, control=False, read_only=False)` 是 async context manager，返回原生 psycopg AsyncConnection，dict_row、原生 `%s` 参数。`await conn.execute(...)` 返回游标，随后 `await cursor.fetchone()/fetchall()`。业务领域通过自己的 repository 写 SQL。
- `runtime.jobs.JobQueue.register(name, async_handler, retryable=False)`；`await jobs.enqueue(conn, JobSpec(...))` 使用同一事务连接真实派工，key 唯一；取消用同连接 `await jobs.cancel(conn,key)`。
- `runtime.composition.DomainModule(name, register_routes, start, stop, register_tasks, migrations)` 注册真实领域路由；`RuntimeServices(database,jobs,models,files,settings)` 只传基础资源。
- 各域 SQL 使用 `Migration(name,sql)` 加入总注册，迁移仅走根 CLI，不在每个请求中运行。

## Web JSON

公开域路由统一 `/api/v1/`。不保留旧 API 自动回退。

```json
{"error":{"code":"revision_conflict","message":"revision_conflict","details":null,"request_id":"..."}}
```

CommandResult 为 `{client_request_id,data,revision,action_id,attempt_id,receipt}`，未知值保留 null。
分页为 `{items,next_cursor,coverage:{complete,total,missing,ranges,representation}}`。
写入 body 包含 `client_request_id`，修改已有对象带 `expected_revision`；未知写入不能自动重发。

正式会话路由：GET `/api/v1/session`，POST `/api/v1/setup`、`/api/v1/auth/login`、`/api/v1/auth/logout`。
同源 HttpOnly Cookie，修改请求使用 `X-CSRF-Token`。身份领域负责实际鉴权/初装；本基础不会注册假登录。
SessionView JSON 为 `{authenticated,initialized,principal,csrf_token,setup_token_required}`；principal 为 null 或
`{principal_id,display_name,permissions:[...]}`。初装与登录 body 的业务字段由 identity 所有者正式定义。

## CR01–03 当前实际实现

- 单根后端 manifest/锁与 `tianshu migrate|interactive|model-broker|worker`；一个 asyncio/aiohttp 生态，无旧产品 import/sys.path 转发。
- 原生 PG async/control/sync 分池、绝对 deadline、真正 SQL 取消、有界同步线程；`enqueue`/`enqueue_sync` 在外部原生连接上实际调用 Procrastinate 3.10.0，取消同事务，due/elastic 独立消费份额。
- 一个 Broker 通过 PG session advisory lock 保持唯一所有者；控制 API/连接池独立；路由固定后一次调用结束即释放执行位，工具等待不持有它。
- 原生 quota_group 并发、前台预留、后台最大在途、RPM/TPM 与通用 utf8_bytes/audio_seconds 单位预算、前台速率预留、后台速率上限、有界等待、角色/会话轮转与等待老化。
- attempt 在发送前持久化；取消墓碑覆盖“取消先于请求落库”，取消移除实际队列等待；未知供应商效果保留原 attempt 和明确 hold_until，重启不重放、不立即归还未知占用。
- ExternalRequest 与 ModelClient.resource 用于 Fish/MCP/图像等领域真实协议；submitted/finish/unknown 与控制监视贯穿跨进程，多个 Key 不成为独立容量池。费用单位分列，未知 usage 不当零。
- Chat/Responses/Claude/Gemini 原生编译，Gemini 图片/音频/视频实际字节、工具结果及 thoughtSignature 保留；对外同协议 SSE 字节透传。Responses 旧状态引用必须属于原 principal 且实际路线兼容。
- Embedding 强制 1024 维、实际结果检查、固定 profile/模型版本/指令/归一化/路线指纹；route 改变后明确要求重建，不偷偷接纳不同向量空间。
- 模型设置真实 PG/CAS/统一命令幂等、只写 AES-GCM 凭据、明确文本/流式 provider probe。没有后台偷偷借前台默认，也没有按模型名字宣称模态。
- CommandStore 只保存响应身份/修订，不缓存私密 data/receipt；on_replay 由领域重新取当前可访问投影。来源遗忘通过 models.ledger.purge_source_results(connection, SourceRef) 删除有依赖的模型结果缓存，实际历史效果状态保持。
- FileStore 支持 put_stream/put_async/open_reader/iter_bytes/iter_async，固定工作缓冲、摘要/大小校验、范围读、取消等待底层 I/O 后再清理；小文件 bytes/text API 继续可用。
- 完整注册运行事件持久 JSONL、批次 fsync、有界队列；HTTP 安全路由模板/方法/状态、job/attempt、关联及耗时，不采样、不存正文，不建 PG 日志账本。RuntimeDiagnostics 读真实队列/Broker/Loki，饱和查询明确不完整。

## 正式补充端口

- `CommandStore.execute(...,on_replay=async_callback(conn,original_identity))`；sync 版本对应同步 callback。on_replay 不重做 CAS，必须保留原 client/action/attempt 身份。不给钩子只返回身份、data/receipt=null。`replay` 可在长外部步骤前查既有结果身份。
- `Database.sync_transaction(budget=None,read_only=False)` 与 `await database.run_sync(operation(conn),budget=None)`；同步连接仍是原生 psycopg/%s/dict_row。
- `ExternalRequest(...,source_refs=())`；permit 必须在实际提交前 `await submitted(handle)`，完成后 `await finish(usage,result)`，无法核实用 unknown。来源非空且 Authority 尚未绑定时明确拒绝，不跳过保护。
- `ModelClient.embedding_profile()` 返回真实固定 profile 和提供者/模型/路线修订；领域不直接读 models 表。
- `ContextContribution/ContextPack/TokenUsage` 在 tianshu.types；由后续 A 的唯一 ContextAssembler 实际消费。used_tokens 未实报保持 null，字节和估计分列。
- TrustedContext 增加 `conversation_kind`，由 identity 查真实场景填入，不从 audience 字符串猜 private/group。
- RuntimeServices 提供 `commands/credentials/events/diagnostics` 资源。配置能力子树固定 `settings.document['capabilities']`，第三方插件依赖环境仍由唯一 PluginHost 管。
