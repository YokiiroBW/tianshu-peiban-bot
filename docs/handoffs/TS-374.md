# TS-374：最终冷停后的精确运行日志 reset

基线 `2086fa6a1a3480b1613a4b7448b137e814ecc615`，独立分支
`codex/unified-log-reset-20261027`。仅离线工具与合成测试；未 SSH、停服务、读 private、
调用真实 Docker、清生产文件或改产品/日志策略。实际 230 写者仍为根协调者。

原 `reset_candidate_logs_r1.remote.py` 是 `/srv/tianshu-tooling` 隔离克隆工具，且自身 stop，
不直接移作生产 reset。新工具沿其“仅清已确认根的后代”结构，复用 TS360 冷备返回协议，
不另建部署编排、备份/恢复框架或权限机制。

## 唯一函数与调用

```python
import importlib.util
from pathlib import Path

spec = importlib.util.spec_from_file_location("log_reset", EXPLICIT_REVIEWED_TOOL)
module = importlib.util.module_from_spec(spec)
spec.loader.exec_module(module)  # 无操作
receipt = module.reset(
    Path(FINAL_COLD_STAGE),
    ALL13_STOPPED_FULL_INSPECT_JSON_OR_DICT,
    TS360_COLD_BACKUP_RECEIPT_JSON_OR_DICT,
    EXPLICIT_LOG_RESET_PLAN_JSON_OR_DICT,
    aux_backup_receipt=EXPLICIT_AUXILIARY_RECEIPT_JSON_OR_DICT,
)
```

输入均显式。`stage` 是本轮全十三正常冷停后调用 TS360 `cold_backup(stage, ...)` 的
同一个新 stage，须已有 `stage/cold-snapshot`，不是旧 group-modes snapshot。
工具只默认执行 `/usr/bin/docker --host unix:///var/run/docker.sock inspect --format ...`
读元数据，无 stop/start/update/网络请求；不读取 `.Config.Env` 或打印文件内容。
可选 `inspect` 参数仅用于测试注入同形元数据读取函数，正式调用省略。

`owners13` 必须是正常停后完整 inspect map：五业务、五 `obs-*`、`onebot`、`inputs`、
`publisher`。full ID、Image、compose project/service、所有 mount 字段及重复项与实读一致；
baseline 和当前均 exited/exit0/restart=no，非 running/paused/restarting/dead/OOM/error。
当前 `FinishedAt` 也须与 baseline 相同，防冷备后又启动再停而误用旧备份。

冷备要求 `status=cold_backup_verified`，内层及磁盘 receipt 均
`offline_restore_verified/restored_disabled/authority_unchanged`；实读 manifest SHA 与 receipt
相同、十核心 ID/Image/project/mounts 匹配，并且 manifest mtime 不早于全部十三
`FinishedAt`。不加任意时长 TTL，不调用 PG、备份或 restore。

辅助备份由根沿原 OneBot backup 协议在**同 cold epoch**另行生成：

```json
{
  "status": "auxiliary_backup_verified",
  "coverage": ["onebot", "comic-inputs", "comic-publisher"],
  "cold_manifest_sha256": "<TS360 receipt.manifest_sha256>",
  "manifest_path": "<显式独立辅助备份manifest绝对路径>",
  "manifest_sha256": "<上述manifest实际SHA256>"
}
```

媒体本体外部挂载不复制。辅助 manifest 必须是根外的普通文件，其 SHA 实读核验。
这个 receipt 的原备份内容与恢复验收仍由根原协议负责，工具不凭空制造备份证明。

## 清理边界与结果

硬白名单恰好九项：`/srv/tianshu/logs/{platform,gateway,memory,knowledge,companion}`、
`/srv/tianshu/observability/data/{guard,vector,loki}`、`/mnt/tianshu-nas/loki-chunks`。
`roots_plan.roots` 必须恰好该集合、service 对应且与原 guard/vector/Loki bind source 一致。
安全摘要或原 private plan 均可使用；`source_owners_file` 等 display 字段不参与解析。

先全九目录预检，才有任何 unlink：根与祖先不得为软链/junction，逐项 lstat、不跟子软链；
检查可读/写/遍历、目录设备和 `/proc/self/mountinfo`，只拒根**内部**嵌套 mount，
允许这九个根本身就是挂载点（包括 NFS）。权限不够直接失败，不尝试 UID 切换、
chown/chmod、NAS ACL 改动。NFS 是否须既有 UID10001 由根保留原失败后另处理。

Linux 删除用根 `O_NOFOLLOW` directory FD，核原 inode/device/UID/GID/mode，再调用标准库
fd-safe `shutil.rmtree(..., dir_fd=...)`/unlink，仅清根后代，fsync 目录。
软链接只 unlink 本体，硬链接只减少本 root 内链接；不触及目标外部文件。
根本身、其 UID/GID/mode 保留；根 mtime 随清目录改变，不冒称保持它。

成功返回/保存 `stage/log-reset.json`，status `runtime_logs_reset`，逐根及 `deleted_totals`
列 files/directories/symlinks/bytes（bytes 为普通文件逻辑大小，不是物理分配量）。
开始回执 `log-reset-started.json` 先 fsync；部分失败保存
`log-reset-failed.json`，status `log_reset_incomplete_no_automatic_retry`，只把已完全清空的
root 标为 deleted。当前失败 root 可能已部分删除，不能把失败回执解释为零删除或完整成功。
同 stage 不自动重跑；根须保留证据并显式判断。回执不含文件名/内容/配置/凭据。

不处理 Docker 自有 stdout 缓存，不访问聊天/记忆/日程/config/业务 DB 或改保留策略。
清 guard/Vector/Loki 指其运行日志账本、队列和日志数据；不能启动旧生产者后再声称不会回放。
正式调度顺序与后续单容器启用仍由根持有。

## 实际验证及限制

共享 Python 3.12.14 stdlib unittest：9 项中 **8 passed / 1 skipped**（0.254s）。
通过普通递归、九根元数据保持、业务文件不动、硬链接、越界/owner/mount/冷停拒绝、
fresh cold SHA/epoch+aux coverage、挂载/权限先全预检、根自身挂载允许、部分失败不重试。
Windows 创建软链无权限，该真实软链用例明确跳过；Linux FD/mountinfo/fsync 分支
尚未在本机执行。根执行前可在 Linux 私有临时目录单独运行同一测试，无开发依赖：

```text
<python> -I -B -m unittest discover -s <工具测试目录> -p test_linux_log_reset.py -v
```

Ruff format/check、diff 检查通过。测试仅 TempDirectory，所有固定 ROOTS 在测试内替换为
该临时目录后代；正式 API 没有范围覆写参数。上述测试通过不等于真实清理已完成。
