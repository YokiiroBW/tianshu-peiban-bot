沿用现有角色工作区、视觉、来源详情、命令 hook、CAS、回执和角色切换取消读取。未改 Python、用户 Memory 页面、通用鉴权或模型/语音配置；没有新依赖或确认门禁。

- 工作区增加“今日安排”“长期目标”“日记”，保留总览、经历、阅读、衣柜、相册和作息入口。
- 长期目标显示来源、随经历形成/作者记下、动机与调整理由、实际进度、完成条件。复用 `goals.save` 编辑、暂放、继续、放弃；不提交伪造的 origin 或 progress。有实际进度后的完成条件沿用服务端原约定。
- 今日安排读取真实 `life/day-plan`，展示少量活动、自由时间、下一步、等待结果与未完成进度。只给当日未开始项调整时间入口，按 plan.timezone 转为带时区 ISO，CAS 使用 slot.revision。重新考虑使用 plan.revision，保留正在进行的工作。
- 初次日期由服务器按角色作息决定；用户可切换日期查看过去安排。当前日自然切换时继续服从服务器日期，不按浏览器时区误选一天。过去/已结束安排没有当前日写入口。
- 活动展示检查点、实际覆盖、唤醒条件、后续探索意图和原任务。展开后读取真实 ActionReceipt/原件/产物；unknown、效果未知和投递未知继续明确展示。实际续读沿 `activities.resume` 和原 revision；原动作仍运行/未知时不显示重发入口。
- 内容发现仍标明是候选元数据，优先执行服务端 next_actions。论坛正文展示作者/楼层/引用归属及真实后续回复入口；视频与正文续接只使用原回执 continuation.arguments，不再以 last URL 或 next_position 百分比重建请求。视频分析完成与逐帧完整理解分开展示，模态/采样缺口保留。
- 自动日记展示实际 automatic DTO、材料版本/已复核版本、等待/失败/无新增材料和上次复核。复用原 request/read/revise/cancel/reconcile/publish 以及明确读者发布，不把未知显示成正文成功。公开阅读投影未增加内部状态。旧 read 回来时按 diary.revision 选择较新控制元数据。
- 图像只扩展现有结果展示块：保留实际产物，显示 consistency 的 matched/conflict/unknown、可见场景检查和 sharing.notice。生成、核验与投递分别显示；archive/recheck/send 意向不冒充已送达，未增加自动重抽。
- 阅读上传和图像原结果控制增加组件退出时的 AbortController 清理，角色切换后迟到结果不会继续发起旧角色写入。
- 增加移动布局：当日时间轴改单列、控件换行、正文/引用有界滚动，沿原工作区按钮及焦点样式。

## API 与依赖

A 冻结的 API：

- `life/day-plan` 只读 POST（可省 day，由服务器决定当地今日）。
- `life/day-plan.move`：`{id,starts_at,expected_revision:slot.revision,client_request_id}`。
- `life/day-plan.reconsider`：`{reason,expected_revision:plan.revision,client_request_id}`。
- Goal 新字段 `criteria/origin/reason/progress`；origin/progress 只读。Activity 新 `wake_condition` 和当前等待原因。
- 原 `life/activities.resume` 负责实际续读与跨 capability 检查点。

原操作清单增加上述 3 项。A 确认 CommandStore operation 本身就是 `life.day-plan.move/reconsider`，与现 commandRecovery 默认映射一致，因此没有添加重复映射。

B 自动日记 DTO 使用现已冻结的 `automatic`，无新日记 API。C 结果消费使用 `next_actions/discovery_continuation/continuation/follow_up`；图像读取 `images/view.jobs[].result.consistency/sharing` 或原 `capabilities/get` 回执；相册像素仍走已鉴权的原 ArtifactList/MediaPreview。
