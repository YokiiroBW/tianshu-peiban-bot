## 改动与复用

`control_bundle.py` 复用旧 `bundle.git_files` 的 Git 对象导出，并将原确定性 ZIP 写入／读取校验提取成共享函数；旧源码包的文件列表和资产没有改变。新控制包包含 TS-205 全部既有节点代码、control Python、两个 Node JS、匹配新旧合同、合成样例与原依赖锁。`run_control.py` 提供隔离 Python 入口／版本输出；`run_remote.py` 让原有 sudo Python 入口进入独立版本 venv，不新增 sudo 规则或改变原工具环境。

现有 `image.py`／controller 新增显式 `--control-package`，保留当前完整 Platform Git 源、Dockerfile、音乐工具和所有旧验证。控制代码只装进镜像固定目录，复用只读节点的单独 venv；安装后验证哈希／权限／两个绝对入口及真实空 catalog，不新增 Platform Docker socket。

现有 resident 新增 `--control-install`，仍使用 `--preserve-infrastructure`、完整 fresh baseline、原 stage／launch／poll、guard、离线恢复校验、唯一冷备保留和 rollback。冷备验证前只有只读检查；之后安装独立不可变代码目录／venv、离线哈希 wheel、新私有登记和两条持久 journal。仅修改 `infrastructure.control`，其他 settings、已装只读包、采样 tmpfs、完整挂载和媒体配置沿原值保留。回退只恢复此前 control 引用，初装没有旧 control 时删除该 key；保留后续其他设置、代码、配置和 journal，不恢复数据库。

`control_node_check.{py,js}` 在显式 Dockge full64 ID 内以既有 Node 执行两个合成进程组证明，不要求 NAS host Node 或 Dockge Python。`control_acceptance.py` 是独立标准库实机验收驱动：必须显式输入新测试项目、两条不同镜像 ID、新 marker 目录和固定命令；创建／容器与栈启停重启／不同真实镜像配置部署／镜像更新／版本恢复，每步同 operation_id 重放、精确运行态和 marker 读回，并保存全量非目标身份／挂载／配置摘要。更新记录实际 before／after ID；同 ID 拉取不冒称版本升级。失败不重发未知变更、不自动清理栈／卷／数据。

完整参数和真实执行边界见 [CONTROL.md](../../deploy/infrastructure/CONTROL.md)，私有登记骨架见 [control-install.example.json](../../deploy/infrastructure/templates/control-install.example.json)。没有生产连接／路径默认值。
