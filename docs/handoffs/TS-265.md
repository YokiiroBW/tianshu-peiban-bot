## 复用与计时

`memory_write_fixture.py`仅组合现有Harness/SyncHarness、Store、Contracts、LocalWorkflow/TrustedWorkflow及SourceAuthority；不另建存储/事务或复制产品业务规则。source owner仅复用公开SyntheticOwners响应，保留完整来源与权限协议，未连接真实服务或模型。

原两suite保持三轮四组合24次/4,560采样。`memory_source_write.py`独立新增完整SourceAuthority纯commit/full-flow两case，每case30次；三轮四组合另12次/720正式采样。种子300组/30源，full-flow另5次真实预热，写后365组，关闭重开核对ledger和原生field内容签名；不改变原source读suite的300组语料。两研究分母分别保存，候选/版本变化后不混旧样本。

`sqlite_write_control.py`为单入口四mode，四case：`local_commit`、`local_full_flow`、`source_commit`、`source_full_flow`。默认300组模板（smoke20），每case原生准备/封存一次，再为每对复制相同物理DB/guard/合成状态。pending commit与尚无目标source/event/job的full-flow分别封存。克隆使用普通文件复制、文件与目录fsync及hash核对，不hardlink、不共享可变库，不使用rollback或幂等重放取得样本。

每侧原生Store构造器在计时外，必须保持初态DB/guard字节；实际native commit或全flow计wall/cpu纳秒。提交后要求完整组/records/ledger增长、job committed、source revision增长、DB/guard变化；关闭并重开核验native guard、ledger、完整组内容、quick_check及FK。原生UUID可能令两侧提交后bytes不同，比较语义签名和业务增量。SourceAuthority核验本身可能在计时外持久同步，单列记录，不能抑制。FULL/WAL及pool4保持。

## CLI与驱动协议

所有命令附通用参数`--config /bench/private.json --backend sqlite --variant original|optimized --trial N`及`PYTHONHASHSEED=0`，继续执行原common安装proof。控制内显式空PG/Redis，同writecontrol namespace；工作挂载固定`/bench/write-active`，两侧内部绝对路径一致。

1. `--mode seed --case CASE`：绑定新空模板目录，原生种子/prepare并重开验证后封存，输出seeded及seed_groups、seed_source_count/source_count、初态hash。模板不覆盖；必要FileStore或storage状态若不在封存清单则拒绝。
2. `--mode prepare --case CASE --source /bench/write-control/templates/CASE --destination /bench/write-control/pairs/b1/CASE/p0001`：目的地全新，产生original/optimized独立复制；输出prepared、每侧复制bytes和全部file hash。
3. `--mode run --case CASE`：绑定一侧新克隆，真实执行一次、完整校验后输出sample，并保存合成`result.json`/`fixture-after.json`。已用副本初态hash不符时拒绝，不会把旧ledger命中当新写。
4. `--mode verify --case CASE`：只重开核对已提交结果，不重放写命令，输出verified。

`--mode run --stream`先输出ready；stdin每行`{"case":"local_commit"}`（四case之一）执行一次并关闭所有Store后输出sample；`{"case":"stop"}`输出closed。父级driver负责每条换入新的独立克隆，两个worker无打开连接时才更换专属文件，保留绑定目录inode、模板及历史结果。Contracts可保持热状态，每次业务Store原生新开/关闭。预热也必须使用独立克隆，不复用已提交job。

计划写控制3block×每case20对，四case共240对/480真实提交，预热独立。每case每block old/new先后各半，一次一活跃调用；每个reader CPU0–7/shares128/512MiB。准备/复制/hash/断言/重开均在计时外，全部异常值保留；不把固定小smoke或普通完整组模板泛化成全部自动事实/并发/远端工作负载。私有NAS驱动不入库，具体调用见[基准README](../../scripts/benchmarks/pg-read-performance/README.md)。
