# TS-347 日志账本批量写入退步修复

状态：`local_verified_not_integrated`，只做本地合成数据验证。协调基线为 `8341ed07e7cdeffca5183427ac8ffc0754b1b070`，分支 `codex/log-write-performance-20261027`；实现与本交接一起提交，最终精确 SHA 由本提交记录确定。未推送、构建 Linux 镜像、连接 NAS、访问生产日志或数据库。

## 原因与改动

TS-331 的 `event_insert` 逐事件执行一次 `totals` UPDATE 和一次 `streams` UPSERT。百万条冷灌因此重复约两百万次摘要写入，原记录为 17.061→33.640 秒；该记录没有被新的实测覆盖或撤回。

本次保留 SHA-256 的 32 字节无损 BLOB、总量/逐流摘要和三类部分索引。`ledger_schema.insert_summary()` 只收集成功 INSERT，在原扫描事务提交前更新一次总量、每条受影响流一次摘要。作用域位于数据库事务内层，预算/容量提前返回也会刷新摘要；扫描、摘要或文件位点任一步骤失败则一起回滚。原 verified/delete 触发器保留，reconcile 的查询水位、128 批次、公平复查和中央丢失退回 pending 均未改变。

只替换摘要维护后，真实扫描仍较旧版慢约 7%。因此继续消除成功写入路径中先 SELECT ID、再 INSERT 的重复索引查找：使用定向 `ON CONFLICT(id) DO NOTHING`；只有未插入时再读取原 ID/hash，仍按原 ID 优先规则区分重复内容、身份冲突和序号冲突。没有使用泛化 INSERT IGNORE，也没有删索引或改变日志采集、720h 保留、100 万容量上限、确认水位、重放、去重、15 条告警、鉴权或去敏。

检索了协调仓库的 Ledger 构造、导入和 `.db` 使用点，以及观测目录全部事件写入 SQL。实际运行只有 `guard.State.run_monitor` 串行调用 `scan→reconcile→metrics`；其它事件 INSERT 是旧库测试夹具及合成基准。原 `benchmark_ledger.py` 已复用同一摘要作用域，计时包含摘要维护。不能把跳过摘要的裸 SQL 灌入当成修复后的性能。

## 升级与回退

schema 版本升至 2：v0 仍在同一事务内转换所有旧 TEXT hash、回填摘要并建索引；无效 hash 保持整批回滚。v1 只在事务内撤销旧 insert trigger、更新版本，不重写事件或每次启动全表回填。已有 files/counters、BLOB、时间、确认状态及摘要原值保持。新库较小不意味着旧库文件自动缩小；没有 VACUUM、删除源段或删除历史证据。

回退仍由协调发布恢复升级前账本备份；不能用 v0/v1 程序直接打开 v2 写入。用户已授权的 NAS230 隔离实测、镜像和切换由根协调后续执行，本卡未实施。

## 验证

首批相关 52 个节点：40 通过、6 因未设置权威合同路径失败、6 跳过。显式设置原根 diagnostics/v1 原字节路径后，仅补原 6 失败和 5 合同跳过，11 项通过；余 1 项为既有 POSIX SIGTERM 平台跳过。修改成功 INSERT 路径后，再集中验证相关 20 项全部通过，包含新增复合 ID/序号冲突。按精确节点覆盖的适用范围为 **52 通过、1 既有平台跳过、0 未解决失败**，不是各轮相加或整个观测套件全量。

新增回归覆盖 v1 重开及证据逐表保持、预算/容量提前返回与重放、摘要失败的事件/文件位点/计数回滚、Memory 实际 service/instance 分组、复合唯一冲突分类。原有 v0 坏 hash 回滚、重复/冲突、乱序补洞、二进制核对、中央丢失、公平队列、真实本地 TLS 监测生命周期和 ready 路径通过。原合同/TLS角色协议和配置规则没有新增改动。

原始 XML 保留在 `.runtime/ts347-*.xml`，小规模旧基准兼容检查在 `.runtime/ts347/legacy-benchmark-smoke/`；按节点核算见[验证收据](../../tests/deployment/observability/evidence/ts347-validation-2026-10-27.json)。受影响文件 Ruff、`git diff --check` 和 Python 编译检查通过；首次 Ruff 的导入顺序及等价 with 排版问题已修正。

## 同负载性能对照

精确旧版 `ab93be4e91b824008d387d71c80e77dfac7341b3`、有退步候选 `67dfa3c80ee02ee7402100ef4babae4c5bfdffab`、本次修复。候选的 monitor/schema/vocabulary 与协调基线 8341ed0 无差异。新 `benchmark_ledger_writes.py` 直接导入指定版本原源码，不复制账本算法；源码原字节 hash、Python/SQLite/OS、全部轮次原值及索引/尺寸记录随证据保存。
