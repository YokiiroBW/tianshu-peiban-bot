## 判断和范围

原 `Policy.verify_contract()` 检查合同字节，`Policy.validate()` 检查注册事件/错误码，不比较 installed commit/source hash。因此旧 vocabulary 的源码字段不会单独导致运行失败；但 R6 已换产品源码，继续宣称旧 commit 不符合溯源事实。沿原 snapshot.extract/git-show 生成新公开 snapshot 后，允许显式替换该来源记录即可，无需修改运行规则。

新 capture r6 仅新增可选 `--vocabulary PATH`：除四个固定产品的 `commit` / `source_sha256` 外，新旧文档所有字段必须相等，包括整个 contract、repo、source_path、events、error_codes；四产品集合固定，并检查新旧 40 位 commit / 64 位 source SHA。未传参数时继续原 vocabulary。

替换保留新文件原 bytes，旧文件原 bytes 另归档为 `config/private/original/obs-guard/vocabulary.json`，不覆盖旧工具/输出。capture receipt 新增 `vocabulary_provenance`，记录原/新 SHA、归档位置和实际改变的字段；stdout 仍仅原有状态/数量/receipt hash。

另一项必要投影复用当前 context 的 `configs.ALERTS['LedgerCapacity'][0]`：只改已捕获 `observability/provisioning/alerting/tianshu.yaml` 中 UID `obs-ledgercapacity`、refId `A` 的 `model.expr`。没有 UID 时原样，不新建规则。复用现 json_set 的窄数组索引能力，保留其余全部字节，包括另外 14 项、所有 UID、持续时间和用户配置。旧完整 raw 归档为 `config/private/original/obs-grafana/provisioning/alerting/tianshu.yaml`，receipt 的 `observer_projections` 记该一项表达式、前后 SHA；不重新生成 15 项规则。
