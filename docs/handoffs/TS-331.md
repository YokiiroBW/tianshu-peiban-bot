# TS-331 日志账本占用与读取优化

状态：`local_verified_not_integrated`。基线 `ab93be4e91b824008d387d71c80e77dfac7341b3`；分支 `codex/single-container-logs-20261027`；本交接与实现同一提交，最终精确 SHA 由协调者接收时的 Git 提交记录确定。没有推送、部署、生产写入、QQ 或真实模型调用。

## 目标与范围

沿用既有 Vector/Loki/Prometheus/Grafana/guard 全功能日志链路，在保留事件、核对证据、完整检索与告警的前提下优化本地账本。只改 `deploy/observability/`、对应测试及本交接；单容器 Dockerfile、统一进程管理和漫画插件由其他写者负责。

原每轮 `scan()`先全事件计数；guard 前后两次`metrics()`各自聚合全部事件并按服务/实例重新分组。已确认复查复用`(verified,last_checked,first_seen)`索引，`verified>0`后仍需对大量事件临时排序。SHA-256用64字符hex存储，每事件重复占据64字节。

## 最终变更与复用

- 新增 `ledger_schema.py`，由原 `Ledger` 打开路径调用。以一个SQLite事务无损升级旧账本：32字节BLOB摘要、小型总量/逐实例汇总、待确认年龄及两类公平队列部分索引。事件、原始hash信息、时间、源位点、异常计数均保留。
- 汇总与事件写入/核对状态变化同事务提交，失败插入和回滚不改变汇总。重复身份、内容冲突、序号冲突及缺口仍按原规则判定。
- `scan()`直接读取持久总量；`metrics()`读取小型汇总及最老待确认索引。guard每轮只发布一次最终指标，Loki查询失败/关闭取消后仍反映本地新增积压。
- 原字符串 `policy.digest()`接口保留，新增 `digest_bytes()`供账本使用；已有对账CLI等调用方语义不变。
- 原配置导出和运行源码校验清单均加入 `ledger_schema.py`。协调统一镜像时必须把该文件与`monitor.py`共同打包。

没有改 Vector采集、持久位点/缓冲/补传、Loki720h保留、角色鉴权、15条告警或原100万事件容量界限，没有采样、删除源段、删除事件、自动回收或生产迁移。Loki/Grafana缺少实际参数对照证据，本卡没有任意降低其缓存、并发或限额。

## 百万事件合成对照

执行 `benchmark_ledger.py`，旧实现为基线Git导出的原`monitor.py`，两侧为相同16实例、100万条事件、5%pending。普通指标/复查/空扫描各9次，追加为1000条真实格式事件单次，合成容量显式设为100万+1000；生产默认没有调整。数据、源日志和数据库均为隔离合成文件，没有访问网络。

| 项目 | 原实现 | 本实现 |
|---|---:|---:|
| 100万事件新库文件尺寸 | 349,147,136 B | 293,482,496 B（减少15.94%） |
| 指标读取中位耗时 | 200.021 ms | 0.0128 ms |
| 指标读取SQLite执行步数（1000步分辨率） | 24,050,000 | 少于1000 |
| 64条已确认公平队列读取中位耗时 | 96.103 ms | 0.0349 ms |
| 该队列SQLite执行步数 | 13,300,000 | 约1000 |
| 无源空扫描中位耗时 | 23.887 ms | 0.0036 ms |
| 1000条追加单次 | 74.897 ms | 51.939 ms |
| 直接SQL冷灌100万条耗时 | 17.061 s | 33.640 s |

如实保留写入代价：逐事件事务汇总增加了直接SQL冷灌时间，不能把该项声称为提速；追加只有单样本，也不代表稳定吞吐。读取SQL执行计划从临时排序切为`event_confirmed(last_checked)`索引，持续公平复查语义保持。若账本积累大量已超出检索窗口的历史事件，已确认队列仍可能跳过较长的过期索引前缀，本卡未通过删除历史证据消除该边界。

旧库带1000条追加原地升级耗时3.778秒，保留1,001,000条全部事件，total/pending/gap与旧版一致；旧文件没有执行VACUUM、仍是原尺寸，产生4885个可供后续复用的空闲页。新库尺寸收益不能直接宣称既有生产文件已下降。完整样本、尺寸分项、查询计划、基线源码hash见 [性能收据](../../tests/deployment/observability/evidence/ts331-ledger-performance-2026-10-27.json)；大数据库保留在`.runtime/ts331/million-comparison/`，不入库。
