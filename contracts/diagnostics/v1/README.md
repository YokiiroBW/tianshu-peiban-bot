# 运行诊断合同 1.0.0

本批 TS100–103 开发冻结输入，中央采集联合验收尚未完成，不宣称生产全链路冻结。产品独立实现日志适配器，不跨仓导入源码或复制共享schema；部署保留该合同包。event.schema.json定义封闭记录；每行UTF8 JSON加LF，最大4096字节，格式/枚举必须严格校验，NaN/Infinity拒绝。

event与error_code只能来自产品源码登记的静态枚举，用户字符串即使匹配正则也不可作为事件名/错误码。禁止message、extras、堆栈原文、URL/query、header、token/cookie、账号/路径、请求响应正文、聊天/日记/模型内容。未知异常只记固定internal_error，详细堆栈不得流入另一条不安全日志。关联ID是随机32位小写hex，不从用户身份推导；HTTP只接受合法X-Tianshu-Correlation-Id，非法生成新值，不回显非法原串；向既有内部对端请求传播同一合法ID，不改业务body/授权。instance_id每次进程唯一，sequence线程安全单调分配，event_id独立UUID；重传保持原值。

全量=所有注册运行事件及级别不采样、不按成功过滤；每产品提交事件覆盖表：启动/关闭、请求开始/鉴权结果/结束、后台周期实际工作开始结束、排队/取消/重试、外部调用开始结束及失败、日志故障。空闲循环不制造业务事件；错误循环须有可取消退避，禁止20次/秒无休止重试。业务状态仍由原领域账本决定，日志不能成为第二业务数据库。

文件输出由TIANSHU_LOG_DIR显式指定，部署为/var/log/tianshu，非root可写专属目录。按实例/进程不同文件防双写，单个日志文件64MiB封段，总目录默认1GiB可显式配置32MiB至64GiB。本批不删除未获采集确认的文件；容量到达时可读既存日志，拒绝新增业务503并ready=false，不能静默丢日志继续宣称全量。中央确认和保留清理在下一批单独实现。在新业务发生副作用前将受理日志flush+fsync，完成事件也持久写入；IO失败不抛出导致业务自动重试、不改原unknown语义，在途已完成副作用须保留既有回执。健康状态内存保留固定log_unavailable，stderr仅一次固定安全告警，恢复需真实成功写探测事件（仅显式维护动作/正常写，探针不能写文件）。进程崩溃/断电不能承诺绝对零丢失，测试和文档明确边界。开发未配置目录可stderr且标non_durable，生产就绪不允许。不要劫持第三方任意正文logger，禁默认HTTP access/raw协议日志，使用自有白名单事件。

GET /health/live：公开最小JSON {status:alive}，存活200；不代表业务可用。
GET /health/ready：独立TIANSHU_DIAGNOSTICS_TOKEN bearer，不复用业务/管理员token；缺凭据401，服务端未配置503。返回封闭安全状态：status ready|not_ready，service，checks（静态键到ok|failed|not_configured|not_verified|non_durable），不返回环境值/路径。就绪按本地必要配置已通过验证、持久日志正常、实际运行时已装配且未关闭/所有者未失效判断；只读，不mkdir/写探测文件/迁移/tick/发消息/调付费模型，不在线写DB。依赖未实测必须not_verified，不能仅配置存在报可达。可选图像/资产不阻断基本聊天，必须文档列出最低必要项；核心未配置不报ready。两个端点不能落SPA回退。TLS/认证沿用原服务，不信任任意转发头来绕过HTTPS。

验收：schema正反例、秘密canary覆盖异常和headers、并发日志唯一序号、N条实际事件数量、真实HTTP权限与只读事实、容量满/写故障/恢复、不重复副作用、重启不同实例、轮转不删未收集。生产Linux容器build/run尚未执行必须写未验证。镜像先沿现有Python依赖精确版本，部署基础镜像digest在后续打包验收固定，不声称浮动标签可复现。

探针请求本身不落日志，不通过请求中间件写探测事件；其查询结果由后续外部监控者记录。因此只读保证包括日志目录不变。业务请求仍全量记录。
